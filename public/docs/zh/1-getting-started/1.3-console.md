# 控制台导览

Web 控制台的默认访问地址为 `http://127.0.0.1:50721`（可通过 `CAMPUS_AUTH_PORT` 环境变量或 `--port` 参数覆盖，端口被占用时自动递增，重试 5 次）。首次启动进入初始化向导，后续所有配置均通过此控制台完成。

> 控制台与 API 服务共用同一端口，可通过 `GET /api/health` 快速验证服务是否正常运行。

## 主要入口（按控制台实际布局）

| 入口 | 路径 | 说明 |
| --- | --- | --- |
| 仪表盘 | `/` | 展示当前活跃方案、网络状态、实时日志流及“登录”按钮（`POST /api/login` 执行活跃任务）；Python 环境未就绪时提示前往系统设置进行修复 |
| 配置方案 | `/profiles` | 管理全部 Profile，`default` 为系统兜底项，支持多方案列表展示；顶部提供“自动切换”开关，每条方案支持编辑、设为活跃及删除操作 |
| 任务管理 | `/tasks` | 集中管理浏览器、脚本及定时任务，支持新建、编辑、复制、删除、排序、导入导出及“执行指定任务” |
| AI 生成任务 | `/ai-task` | 上传登录页截图，由 AI 辅助生成可用的浏览器任务 |
| 自定义脚本 | `/scripts` | 管理脚本与 Shell 任务 |
| 定时任务 | `/scheduled` | cron 调度视图，关联既有浏览器任务进行定时执行 |
| 设置 | `/settings` | 包含 5 个子页面，详见下表 |
| 外观 | `/appearance` | 主题与界面偏好设置 |
| 关于 | `/about` | 版本信息、更新通道及“检查更新”/“立即更新”操作 |

在 `/settings` 页面存在未保存的修改时离开，系统将弹出二次确认对话框，以防止配置丢失。

## 设置的五个子页面

| 子页面 | 路径 | 职责 |
| --- | --- | --- |
| 账号 | `/settings/account` | 账号、密码、认证地址 `auth_url`、重定向触发地址 `trigger_url`、运营商 `isp`（支持自定义关键字） |
| 网络监测 | `/settings/monitor` | 三种探针的开关与目标、检测间隔与超时、重试与暂停时段、登录前检测 |
| 系统 | `/settings/system` | Python 环境、启动与运行、自动更新、网络/端口/代理、维护操作 |
| 浏览器 | `/settings/browser` | 浏览器选择、后台运行、会话保持、安全与反检测、高级设置（需关闭纯净模式后可见） |
| 任务 | `/settings/tasks` | 任务概览、从文件/仓库导入、录制器、OCR 依赖与验证码识别 |

> 各子页面的字段含义、默认值及取值范围，详见 [配置参考 · 浏览器](../6-reference/6.1-browser.md)、[监测与重试](../6-reference/6.2-monitor.md)、[应用与日志](../6-reference/6.3-system.md)。

## 仪表盘

- 顶部展示当前活跃 Profile 的名称与网络状态（在线 / 劫持 / 离线）。
- 中央日志流通过 `/ws/logs` WebSocket 实时推送，网络状态通过 `/ws/status` 推送。
- “登录”按钮触发 `POST /api/login`，执行当前 Profile 绑定的活跃任务；执行失败时可在日志中查看截图与错误摘要。

## 配置方案页面（`/profiles`）

- 列表展示全部 Profile，`default` 为系统兜底项，不可删除。
- 每行提供 **编辑**（进入三段式编辑器：基本信息 / 网络匹配 / 认证设置）、**设为活跃**（`POST /api/profiles/switch`）及 **删除** 操作。
- 顶部 **自动切换** 开关对应 `auto_switch` 配置，启用后 Engine 将按 `profile_check_interval`（默认 180 秒）周期性检测当前网关与 Wi-Fi，并自动切换至匹配的方案。
- 底部提供分步指引卡片，引导新用户完成首次配置。

## 任务管理页面（`/tasks`）

- 以统一列表形式展示三类任务，支持按类型筛选。
- 单条任务支持 **执行**（`POST /api/tasks/{id}/execute`）、**编辑**、**复制**及 **删除** 操作。
- 顶部操作区提供新建空任务、从本地文件导入、刷新列表、批量排序（`POST /api/tasks/order`）及导出（`GET /api/tasks/export/{id}`）功能。
- 活跃任务通过 `POST /api/tasks/active/{id}` 设定（仅浏览器任务可设为活跃）。

## 调试面板

- 前端全局挂载的调试面板，通过 `POST /api/debug/start` 进入单步调试模式，支持 `step`（单步执行）/ `run_all`（连续执行）/ `stop`（停止）操作。
- 面板中可查看每一步骤的执行结果与失败截图。
- `POST /api/debug/capture` 可一键打包当前浏览器截图、MHTML 快照与日志至 `debug/` 目录，用于问题反馈时附带现场信息。

## 系统托盘

| 平台 | 说明 |
| --- | --- |
| Windows | 已运行实例被再次双击时，直接打开控制台页面；`--status` / `--stop` 在终端中可见（附着于父控制台） |
| macOS | 因 `tray-icon` 与 Tokio 主线程存在冲突，托盘自动禁用，轻量模式回落为完整模式 |
| Linux | 依赖 `GTK3` / `libayatana-appindicator`，无桌面环境时托盘不启动 |
| 通用 | 可在 设置 → 系统 中关闭“显示系统托盘”选项，或在启动时附加 `--no-tray` 参数 |

开机自启可通过 `campus-auth --autostart enable/disable` 配置（Windows 写入注册表 Run 键 / macOS 创建 LaunchAgent / Linux 创建 XDG autostart），或在 设置 → 系统 中启用“开机自启动”选项。详见 [常用命令与文件说明](../5-system/5.1-cli.md)。
