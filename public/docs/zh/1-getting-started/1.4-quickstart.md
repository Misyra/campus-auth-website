# 五分钟跑通（从填地址到自动跑起来）

> 目标：让一台新机器从零到“断网自动登录 + 开机自启”可用。按顺序做完即可，不用先把所有文档看完。

## 0. 准备

- 准备好校园网账号、密码、运营商（移动/联通/电信/校园网，有的学校没有就留空）
- 知道认证页地址怎么找：连上校园网后，浏览器会自动弹出的那个登录页地址就是 `auth_url`；如果是“访问任意 http 才跳到登录页”的劫持型，记下一个能触发跳转的 `http` 地址作 `trigger_url`（见下文）

## 1. 启动

```bash
campus-auth                 # 完整模式：Web 控制台 + 托盘 + Engine
# 端口占用会自动 +1，重试 5 次；想固定可用：
campus-auth --port 50721 --host 127.0.0.1
# 先看状态/停止旧实例：
campus-auth --status
campus-auth --stop
```

Windows 双击 `campus-auth.exe` 不弹控制台，已有实例会自动在浏览器打开 `http://127.0.0.1:50721`。首次打开走初始化向导，其后都在「设置」里改。

## 2. 配置方案：默认已有一条，直接改它

安装后 **默认已有 `default` 方案**（兜底，不可删除），不用新建。

打开 Web 控制台 `http://127.0.0.1:50721` → 侧边栏 **设置** → 点 `default` 的 **编辑**，把地址与账号填对即可。需要多校区/多运营商再点 **新建方案** 另起一条。

| 字段 | 填什么 | 典型错法 |
| --- | --- | --- |
| 名称 | 随便起，如“宿舍 / 教学楼” | — |
| 认证地址 `auth_url` | 浏览器里看到的登录页完整 URL | 填了 js 跳转后的中间态、或带 token 的一次性链接 |
| 触发地址 `trigger_url` | 仅劫持型必填：`http://www.msftconnecttest.com/connecttest.txt` 这类明文 `http`（控制台里叫“重定向触发地址”开关） | 填了 `https`（劫持下 TLS 直接失败，拿不到 Captive） |
| 账号/密码 | 真实账号，落盘自动 `ENC:` 密文 | 用了测试账号 |
| 运营商 `isp` | 有运营商下拉的学校必填（下拉含“自定义”可手填） | 留空导致 `select` 匹配不到 |
| 网关 IP / WiFi 名称 | “检测当前网络”一键填入，或手填；按网关或 WiFi 自动切方案 | 校区 A/B 共用同一方案，漫游不切 |

重定向模式：`trigger_url` 非空即启用，任务里写 `{{LOGIN_URL}}` 的存量任务会自动变成触发地址并跟 302 到真门户，不用改任务。

## 3. 浏览器设置：先关后台运行，调稳再开

第一次跑务必 **先关闭后台运行**，亲眼看一次流程是否真的填进去了。

**设置 → 浏览器**：

- **后台运行**（即 `headless`）：先关，调通后再开；提示文案为“不显示浏览器窗口。首次配置任务或排查问题时可关闭”
- 浏览器选择：默认 `msedge`，可选 `chromium` / `chrome` / `firefox` / `webkit`（卡片式），支持 `browser_custom_path` 指定本机已装浏览器
- 高级设置：需先关“纯净模式”才可见 `viewport 1280×720` / `UA` / `browser_args`（每行一个，`#` 注释，`--proxy-server` 等敏感参数会被过滤）
- 常用：`locale zh-CN` / `timezone Asia/Shanghai`，超时 `timeout 30` / `navigation_timeout 15` / `login_timeout 120` 秒
- 会话：`登录完成后保持浏览器进程`（`keep_alive`，关后 `idle_timeout 300s` 空闲回收）、`记住登录状态`（`persistent_context`，数据在 `config/browser-data/{channel}/`，Firefox 不可用）

> 控制台里没有叫 `headless` 的输入框，只有 **后台运行** 这个开关；文档里不再写裸字段名。改完点保存，再去任务里验证。

## 4. 任务：录制器优先，手写为辅

### 用录制器（不手写 JSON）

1. 装 Tampermonkey
2. 设置 → 任务 → 安装录制器脚本
3. 打开认证页，点浮动按钮开始，依次点账号框、密码框、验证码、登录按钮
4. 结束保存 → 设为活跃任务（`POST /api/tasks/active/{id}`）→ 仪表盘点“登录”试一次

### 手写/改任务

浏览器任务存 `tasks/browser/*.json`（`type=browser`），关键字段：

```json
{
  "name": "校园网登录",
  "url": "{{LOGIN_URL}}",
  "timeout": 30000,
  "navigation_wait": 1.0,
  "step_delay": 0.5,
  "variables": {},
  "success_condition": "login_success",
  "steps": [
    { "id": "fill_username", "type": "input", "selector": "#username", "value": "{{USERNAME}}" },
    { "id": "fill_password", "type": "input", "selector": "#password", "value": "{{PASSWORD}}" },
    { "id": "select_isp", "type": "select", "selector": "select[name='isp']", "value": "{{ISP}}", "required": false },
    { "id": "submit", "type": "click", "selector": "button[type='submit']" },
    { "id": "check_success", "type": "eval", "script": "() => document.body.innerText.includes('登录成功')", "store_as": "login_success" }
  ]
}
```

> 劫持型记得 `url` 用 `{{LOGIN_URL}}`，不要写死真门户；多页 SSO 用 `goto`/`navigate` 继续跳。

变量优先级：任务 `variables` < 系统 `USERNAME/PASSWORD/ISP/LOGIN_URL` < 前序 `store_as`。脚本/命令里同样可用 `{{USERNAME}}` 等（见自定义脚本一节）。

## 5. 调试：失败就地看

- **先关后台运行复现**：把 **后台运行** 关掉，点“执行指定任务”（`POST /api/tasks/{id}/execute`），看是否真的点到了按钮、是否在 iframe 里（需要 `frame` 字段）
- **单步调试**：`POST /api/debug/start` → `step` / `run_all` / `stop`，面板里看 `steps` 输出与失败截图
- **验证码**：含 `ocr` 的任务先在设置 → 任务里装 OCR（`ddddocr`，约 120MB），装好后用“验证码识别”上传截图试一次
- **一键取证**：`POST /api/debug/capture` 打包截图/MHTML/日志到 `debug/`

常见坑：选择器随门户改版失效（优先用稳定 `id`/`name`/`data-*`，别用自动生成的长 class）；动态页把 `navigation_wait` 调大到 `1.5~2.0`，固定等待用 `sleep` 别用无 selector 的 `wait`。

## 6. 让它自动跑

### 断网自愈

设置 → 检测：默认 `204 门户检测` 开启（`generate_204`），其余按需开

- 网络状态检测：`TCP 检测` / `204 门户检测` / `URL 标题检测`（`Success` 等关键字）
- 登录前检测：`网卡连接检查` / `认证地址可达检查` / `检测不走代理`（默认直连）
- 常用：`check_interval 300s`、`post_login_delay 5s`、`retry.max_retries 3` / `retry_interval 5s`（指数退避），暂停时段支持跨天

### 定时任务

定时任务页用 cron 关联一个浏览器任务（如每日 8 点签到）：`0 0 8 * * *`（秒 分 时 日 月 周），先用手动执行验证稳，再挂定时。

### 开机与长期运行

- 开机自启：`campus-auth --autostart enable`（Windows 计划任务 / macOS LaunchAgent / Linux systemd），或控制台系统设置里开
- 启动动作：`app.startup_action`（`monitor` 启动即检测 / `login_once` 启动即登一次 / `none` 不动作），也可用 `campus-auth --startup-action monitor` 覆盖
- 长期运行：`app.auto_restart_hours` 默认 `24` 小时周期自重启，回收浏览器/Worker 内存；`worker.keep_alive=false` 默认即用即还，`idle_timeout_seconds 300s` 空闲回收

## 7. 验证清单

```bash
curl http://127.0.0.1:50721/api/health
curl -H "X-Auth-Token: $(cat config/.auth_token)" http://127.0.0.1:50721/api/profiles
# 控制台：仪表盘日志是否出现登录成功、失败截图是否可打开、/ws/logs WebSocket 是否已连
```

都通过后，把 **后台运行** 再打开，收工。后续调优再看检测、更新与常见问题各节。
