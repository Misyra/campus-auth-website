# 配置方案概览

控制台的 **配置方案**（`/profiles`）即 Profile，是“某个网络下的认证配置”。

## 默认已有一条

安装后 **默认已有 `default` 方案**（兜底，不可删除）。新装直接编辑它即可，不用先新建；需要多校区/多运营商再新建第二条。

每条含：`auth_url`、可选 `trigger_url`、账号密码、`isp`、网关/SSID 匹配与 `active_task`（`GET /api/profiles`、`POST /api/profiles`、`GET /api/profiles/active`）。

- 认证地址 `auth_url`：登录页地址，重定向模式下可留空
- 触发地址 `trigger_url`：劫持型触发地址，非空即进入重定向模式，控制台为开关“重定向模式（劫持型门户）”（`http://www.msftconnecttest.com/connecttest.txt`）
- 账号 `username` / 密码 `password`：落盘 `ENC:` 密文，运行时注入 `{{USERNAME}}` / `{{PASSWORD}}`，密码框显示“已保存，清空可更新”
- 运营商 `isp`：注入 `{{ISP}}`，参与 `select` / `click_select`，控制台下拉含“自定义”可手填关键字
- 匹配规则 `gateway_ip` / `wifi_ssid`：编辑器内“检测当前网络”一键填入，或手填
- 活跃任务 `active_task`：该方案绑定的活跃任务，多环境各自绑定，不用各写一套 JSON 副本
- 方案标识 `id` / 名称 `name`：`id` 仅新建时可改

## 在控制台怎么操作

- **编辑**：列表点“编辑”进编辑器（分基本信息/网络匹配/认证设置三段）
- **设为活跃**：列表点“设为活跃”（`POST /api/profiles/switch`），顶栏会显示当前方案名
- **新建/删除**：新建走 `POST /api/profiles/{id}`，删除 `default` 会被拒绝
- 顶部可开关 **自动切换**（`auto_switch`），下方有分步指引卡片
