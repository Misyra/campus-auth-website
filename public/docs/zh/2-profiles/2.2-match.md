# 自动匹配

控制台顶部 **自动切换** 开关即 `auto_switch`，开启后 Engine 每 `profile_check_interval` 检测当前 `gateway_ip` / `wifi_ssid` 并自动切换方案。

## 优先级与回落

- 约束越多优先级越高（同时匹配网关与 SSID 的优于单条件）
- `gateway_ip` 优先于 `wifi_ssid`
- 均无匹配时回落 `default`
- 删除活跃方案时 `active_profile_id` 会回落 `default`

## 行为

- 切换后重置登录失败的去重状态，避免“刚切环境仍被抑制”
- 手动切换与定时任务的执行不依赖自动匹配，仅自动登录与 Engine 检测走该逻辑
- 编辑器内“检测当前网络”可一键把当前网关/SSID 填入对应字段

## 建议

- **双校区**：各建一条方案，分别填 `gateway_ip` 前缀或 `wifi_ssid`，`auto_switch` 保持开启
- **双运营商**：同一网络下用不同 `isp` 区分，任务中 `select` / `click_select` 消费 `{{ISP}}`
- 两项留空仅手动切换，适合固定单网络

接口：`POST /api/profiles/auto-switch` 开关，`POST /api/profiles/detect` 探测当前网络。
