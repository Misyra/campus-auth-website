# 自动匹配

控制台顶部的 **自动切换** 开关对应 `auto_switch` 配置，启用后 Engine 将按 `profile_check_interval`（默认 180 秒）周期性检测当前网关 IP 与 Wi-Fi 名称，并自动切换至最为匹配的 Profile。

## 开关与接口

- 开关位置：`/profiles` 页面顶部的 **自动切换**。
- 相关接口：`POST /api/profiles/auto-switch`（切换开关），`POST /api/profiles/detect`（探测当前网络）。
- 关闭后，仅支持手动切换，自动登录与 Engine 的周期性检测不再执行匹配逻辑。

## 优先级与回落规则

系统按以下优先级决定选中哪条 Profile：

1. **约束条件越多，优先级越高**——同时匹配网关与 SSID 的方案，优先于仅匹配单一条件的方案。
2. **`gateway_ip` 优先于 `wifi_ssid`**——当多条方案匹配度相同时，网关匹配的方案优先。
3. **均未匹配时回落至 `default`**——`default` 作为系统兜底项，确保始终存在一条可用方案。
4. **删除活跃方案时自动回落**——`active_profile_id` 将被重置为 `default`。

> 匹配失败时系统不返回错误，仅静默回落至 `default`。若 `default` 本身未配置活跃任务，则自动登录将跳过执行。

## 行为说明

- **切换后重置去重状态**：切换 Profile 后，Engine 将重置此前“登录失败去重”的抑制状态，以避免“环境已切换但仍被抑制”导致无法触发登录。
- **手动与定时执行不受影响**：手动点击“登录”（`POST /api/login`）、“执行指定任务”（`POST /api/tasks/{id}/execute`）及定时任务的执行，不依赖自动匹配机制，仅自动登录与 Engine 的周期性检测遵循该逻辑。
- **一键填入**：编辑器内的 **检测当前网络** 按钮将调用 `POST /api/profiles/detect`，自动将当前网关与 SSID 填入对应字段。

## 配置建议

| 场景 | 建议 |
| --- | --- |
| 双校区（如本部 / 新校区） | 分别创建一条 Profile，各自填写 `gateway_ip` 前缀或 `wifi_ssid`，保持 `auto_switch` 启用 |
| 双运营商（同一网络下） | 在同一网络环境中使用不同的 `isp` 字段加以区分，任务中的 `select` / `click_select` 步骤通过 `{{ISP}}` 消费该值 |
| 单一固定网络 | 两项均留空，仅通过手动切换即可 |
| 首次配置 | 先连接至目标 Wi-Fi，再点击 **检测当前网络**，确认填入的值正确后保存 |
