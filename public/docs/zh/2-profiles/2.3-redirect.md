# 重定向模式（劫持型门户）

当 Profile 的 `trigger_url` 非空时，该方案进入**重定向模式**。此模式适用于“先访问任意 `http` 地址，由网关返回 `302` 跳转至真实登录页”的劫持型网络。控制台入口：**设置 → 账号 → 重定向模式（劫持型门户）** 开关。

## 适用场景

| 网络类型 | 特征 | 配置方式 |
| --- | --- | --- |
| 直连型 | 认证地址可直接访问，无需预先触发跳转 | 仅填写 `auth_url`，`trigger_url` 留空 |
| 劫持型 | 需访问任意 `http` 地址后才被 `302` 重定向至登录页；直接访问 `auth_url` 可能无法打开 | 填写 `trigger_url`（明文 `http`），`auth_url` 可留空 |

> 无法确定网络类型时，可先连接校园网，尝试直接访问登录页——可正常打开即为直连型，否则为劫持型。

## 配置说明

- 启用开关后，系统自动填入 `http://www.msftconnecttest.com/connecttest.txt`（Windows NCSI 同源的明文探测页，`DEFAULT_TRIGGER_URL`），可根据实际网络环境改写。
- `auth_url` 可留空；直连模式下留空将回落至默认值。
- **必须使用明文 `http`**——`https` 在劫持场景下 TLS 握手直接失败，Engine 无法获取 `Captive` 判定结果，仅返回网络错误。

## 运行时差异

| 行为 | 直连模式 | 重定向模式 |
| --- | --- | --- |
| `{{LOGIN_URL}}` 指向 | `auth_url` | `trigger_url`（`{{LOGIN_URL}} == {{TRIGGER_URL}}`） |
| Worker 首导航 | 直接打开 `auth_url` | 打开 `trigger_url`，跟随 `302` 重定向至真实门户 |
| 既有任务 | 需指向 `auth_url` | 使用 `{{LOGIN_URL}}` 的任务无需修改，自动适配 |
| 网络检测 | 包含 `auth_url` 可达性检查 | 跳过认证地址探测 |
| 登录预检 | 执行 `auth_url` 可达性预检 | 跳过预检 |
| 监测判定 | 正常的三探针检测流程 | `Captive`（劫持）判定优先于离线状态 |

## 常见问题

- 首导航在触发页空转、任务步骤无法定位元素——通常由于 `trigger_url` 填写为 `https` 或不可达地址所致。
- 可临时切换回直连模式，或更换触发地址后重试；调试时建议关闭后台运行，以观察首导航的实际跳转过程。
