# 重定向模式（劫持型门户）

当 `trigger_url` 非空时，方案进入重定向模式。常见于“先访问任意 `http` 再 `302` 到真门户”的劫持型网络。控制台入口：设置 → 账号 → **重定向模式（劫持型门户）** 开关。

## 配置

- 打开开关后自动填 `http://www.msftconnecttest.com/connecttest.txt`（Windows NCSI 同源的明文探测页，`DEFAULT_TRIGGER_URL`），可手改
- `auth_url` 可留空（直连留空会回落默认值）
- 必须是明文 `http`，`https` 在劫持下 TLS 直接失败，拿不到 `Captive`

## 运行时差异

- `{{LOGIN_URL}}` 同步为触发地址（`{{LOGIN_URL}} == {{TRIGGER_URL}}`），Worker 首导航跟随 `302` 到真门户，存量任务不用改
- 检测跳过 `auth` 探测，登录跳过预检
- URL 探测的 `Captive` 判定优先于离线
- 设置页认证地址字段提示会变为“重定向模式下可留空，仅填触发地址”

错误配置会在调试面板看到首导航一直在触发页空转；可切回直连或换触发地址重试。
