# 变量与成功判定

## 模板位置

`{{VARIABLE_NAME}}` 可出现在 `selector` / `value` / `frame` / `option_selector` / `target_selector` / `path` / `pattern` / 脚本内容与扩展字段的嵌套字符串中。

## 系统变量

- `{{USERNAME}}` / `{{PASSWORD}}` / `{{ISP}}` / `{{LOGIN_URL}}`
- 重定向模式下 `{{LOGIN_URL}}` 即 `trigger_url`，Worker 跟随 `302` 到真门户

自定义变量在任务 `variables` 中定义，例如：

```json
{ "variables": { "campus": "south" }, "steps": [{ "type": "goto", "url": "https://auth.example.edu.cn/{{campus}}/login" }] }
```

## 优先级（从低到高）

1. 任务 `variables`
2. 系统保留变量
3. 前序 `store_as` 的运行时结果

因此自定义变量不会覆盖真实凭据；`store_as` 的结果在后序步骤中可覆盖同名模板。`store_as` 保留原生类型，插入字符串时 `null -> ""`、布尔 `true/false`、对象/数组 `JSON.stringify`。

## success_condition

```json
{ "success_condition": "login_success" }
```

执行器读取同名 `store_as` 的结果判成功，`false` / `null` / `0` / `""` / `"false"` / `"0"` / `"no"` / `"off"` 均判失败。

## 调试技巧

- 拿不到 `store_as`：确认前一步确有该字段且拼写一致
- 想把 OCR 结果拼进后续 URL：`{ "type": "goto", "url": "https://...?captcha={{captcha_text}}" }`
- 数学验证码：`ocr -> store_as=captcha_expr` → `eval` 计算 `{{captcha_expr}}` → `store_as=captcha_answer` → `input {{captcha_answer}}`
