# 变量与成功判定

## 模板变量的使用位置

`{{VARIABLE_NAME}}` 可在以下字段的嵌套字符串中使用：

`selector` / `value` / `frame` / `option_selector` / `target_selector` / `path` / `pattern` / 脚本内容与扩展字段。

> 控制台编辑器中，包含 `{{…}}` 的字段在保存时将高亮显示，便于核对变量名是否正确。

## 系统变量

| 变量 | 来源 | 说明 |
| --- | --- | --- |
| `{{USERNAME}}` | Profile `username` | 登录账号 |
| `{{PASSWORD}}` | Profile `password` | 登录密码（运行时解密注入） |
| `{{ISP}}` | Profile `isp` | 运营商关键字，参与 `select` / `click_select` 匹配 |
| `{{LOGIN_URL}}` | Profile `auth_url` 或 `trigger_url` | 直连模式下为 `auth_url`；重定向模式下为 `trigger_url`，Worker 将跟随 `302` 重定向至真实门户 |

## 自定义变量

在任务的 `variables` 字段中定义，供后续步骤引用：

```json
{
  "variables": { "campus": "south" },
  "steps": [
    { "type": "goto", "url": "https://auth.example.edu.cn/{{campus}}/login" }
  ]
}
```

## 优先级（从低到高）

1. 任务 `variables`（自定义变量）
2. 系统保留变量（`USERNAME/PASSWORD/ISP/LOGIN_URL`）
3. 前序步骤 `store_as` 的运行时结果

因此，自定义变量不会覆盖真实凭据；`store_as` 产生的值可在后续步骤中覆盖同名模板变量。`store_as` 保留原生类型，插入字符串时的序列化规则为：`null → ""`、布尔值 `true/false`、对象 / 数组经 `JSON.stringify` 处理。

## success_condition — 成功判定

```json
{ "success_condition": "login_success" }
```

- 执行器读取同名 `store_as` 变量的结果进行成功判定。
- 下列值将被判定为失败：`false` / `null` / `0` / `""` / `"false"` / `"0"` / `"no"` / `"off"`（大小写不敏感）。
- 为空时不执行额外判定，仅依据各步骤是否全部 `required` 通过来判断。

**典型写法**：

```json
{ "id": "check", "type": "eval", "script": "() => document.body.innerText.includes('登录成功')", "store_as": "login_success" }
```

## 调试技巧

| 问题 | 排查方式 |
| --- | --- |
| 无法获取 `store_as` | 确认前序步骤中确有该字段且拼写一致；检查 `required` 是否为 `true`（失败步骤被跳过时不会产生 `store_as`） |
| 将 OCR 结果拼入后续 URL | `{ "type": "goto", "url": "https://...?captcha={{captcha_text}}" }` |
| 数学验证码（如 `3+5=?`） | `ocr → store_as=captcha_expr` → `eval` 计算 `{{captcha_expr}}` → `store_as=captcha_answer` → `input {{captcha_answer}}` |
