# 录制与调试

> 本页原位于“自动化与检测”分组，现归入“任务系统”——录制器产出即为浏览器任务，调试亦针对任务步骤，置于此处更贴合任务编写的工作流程。若通过旧链接 `?section=automation&item=debug` 访问，系统已自动兼容跳转。

## 录制器：无需手写 JSON

**设置 → 任务**（`/settings/tasks`）提供可视化录制功能，无需手写任务 JSON：

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展。
2. 点击 **安装录制器脚本**（接口 `GET /api/tools/task-recorder.user.js`，实现位于 `resources/tools/task-recorder.user.js`）。
3. 打开认证页，点击页面上的浮动按钮开始录制，按提示依次点击账号输入框、密码输入框、验证码及登录按钮。
4. 结束录制并保存为任务，设为活跃任务后返回仪表盘点击 **登录** 进行验证。

> 卡片内含“导出编写指南”与任务手册链接（`GET /api/docs/...`），可直接下载参阅。

## 验证码 OCR

| 项目 | 说明 |
| --- | --- |
| 适用范围 | 仅含 `ocr` 步骤的任务需要 |
| 依赖 | `ddddocr`（约 120 MB），通过 `uv add ddddocr` 安装 |
| 安装位置 | **设置 → 任务** 的 **OCR 依赖** 区域，支持一键安装 / 卸载，状态实时检测（含大小与重试） |
| 未安装时 | 非 `ocr` 任务不受影响，`ocr` 步骤执行失败但不阻塞其他任务 |
| 验证方式 | 同页 **验证码识别** 功能可上传本地图片并转为 base64 调用 `ocrApi.recognize` 进行测试，以验证环境是否就绪 |

## 调试

### 调试面板

- 前端全局挂载的调试面板，通过 `POST /api/debug/start` 进入单步调试模式（执行前进行环境就绪检查，缺失时自动引导）。
- 支持 `step`（单步执行）/ `run_all`（连续执行）/ `stop`（停止）操作。
- 面板中可查看每一步骤的 `steps` 输出与失败截图；失败截图的访问经鉴权 WebSocket 内联，不暴露 Worker 绝对路径。
- 建议先查看仪表盘日志与失败截图（受 `retention_days` 控制），再进入调试面板逐步骤定位问题。

### 调试接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/debug/start` | 启动调试会话 |
| `POST /api/debug/step` | 单步执行 |
| `POST /api/debug/run_all` | 连续执行剩余步骤 |
| `POST /api/debug/stop` | 停止调试 |
| `POST /api/debug/capture` | 一键打包截图、MHTML 快照与日志至 `debug/` 目录，用于反馈时附带现场信息 |

### 调试建议

| 场景 | 建议 |
| --- | --- |
| 任务未按预期执行 | **关闭后台运行后复现**：关闭后台运行后点击“执行指定任务”（`POST /api/tasks/{id}/execute`），观察是否正确触发按钮点击、是否存在 iframe 嵌套（需配置 `frame` 字段） |
| 选择器失效 | 优先使用稳定的 `id` / `name` / `data-*` 属性，避免使用自动生成的长 class；必要时可使用 `text="登录"` 文本选择器 |
| 动态页面等待不足 | 将 `navigation_wait` 调整至 `1.5–2.0` 秒，固定等待建议使用 `sleep` |
| 验证码识别失败 | 确认 OCR 依赖已安装且 `ocr` 步骤的 `selector` 指向正确的图片元素；识别失败时自动重试 |

### 一键取证

`POST /api/debug/capture` 将截图、MHTML 及日志打包至 `debug/` 目录，反馈时附带最为有效。仪表盘与设置中的日志通过 `/ws/logs`、网络状态通过 `/ws/status` 实时推送。
