# 命令行与目录

可执行文件 `campus-auth`（Windows `campus-auth.exe`，另有 `campus-auth-helper` 辅助自替换，无需手调）。

## 启动模式

| 模式 | 命令 | 用途 |
| --- | --- | --- |
| 完整 | `campus-auth`（默认） | Web + 托盘 + Engine，全功能 |
| 轻量 | `campus-auth --mode lightweight` | 仅 Engine + 托盘，Web 按需唤起（macOS 自动回落完整） |
| 单次 | `campus-auth --mode login-once`（亦兼容 `once`） | 跑一次活跃任务后退出，适合脚本/计划任务 |

运行中双击 `campus-auth.exe` 不会起第二进程，会直接在浏览器打开已有实例的控制台。

## 常用参数

```bash
# 端口/地址/数据目录（亦可用 CAMPUS_AUTH_PORT / CAMPUS_AUTH_HOST / CAMPUS_AUTH_BASE_PATH）
campus-auth --port 50721 --host 127.0.0.1 --base-path D:\campus-auth-data

# 实例控制
campus-auth --status          # 查询 PID/端口/存活
campus-auth --stop            # 停止
campus-auth --force           # 终止旧实例后抢占（含 PID 复用防护）

# 开机自启（亦可在设置 → 系统中开关“开机自启动”）
campus-auth --autostart enable
campus-auth --autostart disable
campus-auth --autostart       # 查询

# 启动后不自动打开浏览器 / 不显示托盘
campus-auth --no-browser
campus-auth --no-tray

# 启动动作覆盖（覆盖设置 → 系统的“启动后执行”）
campus-auth --startup-action monitor
campus-auth --startup-action login_once
campus-auth --startup-action none
```

完整参数 `campus-auth --help`（`src/launcher.rs::CliArgs`），Windows 终端可见输出会附着父控制台。

## 运行时目录

默认 `base_path` 为可执行文件所在目录。

```
<base_path>/
├── config/                  # settings.json + profiles/*.json + .auth_token（0600）
├── tasks/
│   ├── browser/             # 浏览器任务
│   ├── scripts/             # 脚本 / Shell 任务
│   └── scheduled/           # 调度状态
├── logs/                    # 按日归档（受 retention_days 控制）
├── environment/             # uv / .venv / Playwright 浏览器（按需）
└── update/                  # last_check.json + staging/
```

`settings.json` 为 v6 schema，`config_version` 驱动迁移；密码 `ENC:` 的 AES-256-GCM 密文。`--base-path` 与环境变量可覆盖根目录。

## 鉴权与端口

- Token 在 `config/.auth_token`（`0600`），前端经 `/api/auth/token` 懒取，在 `X-Auth-Token` / `Bearer` / `?token=` 携带；`GET /api/health` 等少数端点豁免
- 默认 `127.0.0.1:50721`，占用自动 +1，重试 5 次；Docker 默认 `0.0.0.0:50721`
- 轻量模式下 `.instance` 记哨兵端口 `0`，首个 Web 按需启动后回写

## 系统设置里的相关开关

- **启动与运行**：启动后执行 `monitor`/`login_once`/`none`、运行模式 `full`/`lightweight`
- **网络、端口与代理**：控制台端口与“使用代理下载更新”及 `proxy_url`
- **维护操作**：`定时自重启`（`auto_restart_hours` 默认 24 小时）与“配置热重载”

## 日志与清理

- 日志保留 `logging.retention_days`（默认 7 天），`file_enabled` 与 `level`（`TRACE/DEBUG/INFO/WARN/ERROR`）在设置 → 系统中即时热更新；`/ws/logs`、`/ws/status` 实时推送
- 占用大、删了可重建：`python_worker/.venv`（约 100MB+，运行时按需重建）、`logs/` 旧归档
