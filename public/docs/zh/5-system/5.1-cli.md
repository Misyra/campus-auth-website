# 常用命令与文件说明

可执行文件为 `campus-auth`（Windows 系统下为 `campus-auth.exe`，另含 `campus-auth-helper` 辅助完成自替换，无需手动调用）。

## 启动模式

| 模式 | 命令 | 说明 |
| --- | --- | --- |
| 完整（默认） | `campus-auth` | Web 控制台 + 系统托盘 + Engine，全功能运行 |
| 轻量 | `campus-auth --mode lightweight` | 仅运行 Engine 与系统托盘，Web 控制台按需唤起（macOS 因 `tray-icon` 冲突自动回落至完整模式） |
| 单次 | `campus-auth --mode login-once` | 执行一次活跃任务后即退出，适用于脚本或计划任务调用 |

> 运行期间再次双击 `campus-auth.exe` 不会启动新的进程实例，而是直接在浏览器中打开已有实例的控制台页面。

## 常用参数

```bash
# 端口 / 地址 / 数据目录（亦可通过环境变量 CAMPUS_AUTH_PORT / CAMPUS_AUTH_HOST / CAMPUS_AUTH_BASE_PATH 指定）
campus-auth --port 50721 --host 127.0.0.1 --base-path D:\campus-auth-data

# 实例控制
campus-auth --status          # 查询 PID / 端口 / 存活状态
campus-auth --stop            # 停止运行中的实例
campus-auth --force           # 终止旧实例后抢占（含 PID 复用防护）

# 开机自启（亦可在 设置 → 系统 中启用“开机自启动”）
campus-auth --autostart enable
campus-auth --autostart disable

# 启动后不自动打开浏览器 / 不显示系统托盘
campus-auth --no-browser
campus-auth --no-tray

# 启动行为覆盖（覆盖 设置 → 系统 中的“启动后执行”）
campus-auth --startup-action monitor      # 启动后进入网络监测
campus-auth --startup-action login_once  # 启动后执行一次登录
campus-auth --startup-action none        # 不自动执行任何动作
```

完整参数可通过 `campus-auth --help` 查看（定义于 `src/launcher.rs::CliArgs`）；Windows 系统下从终端启动时，输出将附着于父控制台。

## 运行时目录

默认 `base_path` 为可执行文件所在目录，可通过 `--base-path` 参数或环境变量 `CAMPUS_AUTH_BASE_PATH` 覆盖。

```text
<base_path>/
├── config/                  # settings.json + profiles/*.json + .auth_token（0600）
├── tasks/                   # 浏览器 / 脚本 / 定时任务
├── logs/                    # 按日归档的日志（受 retention_days 控制）
├── environment/             # uv / .venv / Playwright 浏览器（按需下载）
├── update/                  # last_check.json + staging/（更新产物）
└── debug/                   # 调试打包产物（POST /api/debug/capture）
```

> 完整目录结构、`settings.json` 结构及可清理项，详见 [配置文件与目录](../6-reference/6.4-files.md)。

- `settings.json` 为 v6 schema，`config_version` 驱动自动迁移；损坏时备份为 `settings.corrupt.*`，原子写入经 `.tmp_*.json` 中转。
- 账号密码以 `ENC:` 前缀的 AES-256-GCM 密文落盘，内存中经 `zeroize` 清理。
- `config/profiles/{id}.json` 每条 Profile 独立存储，删除时移入 `.trash` 安全目录。
- 详尽的目录与文件说明，见 [配置文件与目录](../6-reference/6.4-files.md)。

## 鉴权与端口

| 项目 | 说明 |
| --- | --- |
| Token | `config/.auth_token`（权限 `0600`），前端通过 `GET /api/auth/token` 获取，在 `X-Auth-Token` / `Authorization: Bearer` / `?token=` 中携带 |
| 豁免端点 | `GET /api/health` 等少数端点无需鉴权 |
| 默认端口 | `127.0.0.1:50721`，端口被占用时自动递增，重试 5 次；Docker 默认 `0.0.0.0:50721` |
| 轻量模式 | `.instance` 文件初始记录哨兵端口 `0`，Web 服务首次按需启动后回写实际端口 |

## 日志与清理

| 项目 | 说明 |
| --- | --- |
| 日志保留 | `logging.retention_days` 默认 `7` 天，`file_enabled` 与 `level`（`TRACE/DEBUG/INFO/WARN/ERROR`）在 设置 → 系统 中即时热更新 |
| 实时推送 | `/ws/logs`（日志）、`/ws/status`（网络状态）WebSocket |
| 可安全删除（删除后可重建） | `python_worker/.venv`（约 100 MB+，运行时按需重建）、`logs/` 旧归档 |
| 调试产物 | `debug/` 目录下的截图、MHTML 与日志打包文件 |

详尽的日志与应用参数，见 [配置参考 · 应用与日志](../6-reference/6.3-system.md)。
