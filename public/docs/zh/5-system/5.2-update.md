# 自动更新

入口不在设置，而在 **关于**（`/about`）的更新卡片：**检查更新**（`GET /api/check-update` 按通道拉清单，`GET /api/update-state` 回放上次 `update/last_check.json`）与 **立即更新**（`POST /api/system/update`）；设置 → 系统里可见“上次检查时间”与“立即检查”。

## 通道

`config.global.updater.channel`（`src/config/schema.rs::UpdateChannel`）：

- `stable` 正式版：仅跟随稳定发布（`releases/latest` 单包语义）
- `prerelease` 测试版：仅跟随预发布
- `all` 全通道最新版：按 semver 取最高；列表为空回退单包口径（`src/updater/check.rs::fetch_manifest_for_channel`）

控制台为分段按钮：正式版/测试版/全通道最新版。

## 频率与开关

- `auto_check_enabled`：总开关，关闭后仅手动检查
- `check_interval_hours`：设置 → 系统为“每次启动 / 每天一次 / 每周一次”（`0 / 24 / 168`），存量非标准值展示时归一
- 每次检查无论成败均刷新 `update/last_check.json`（`last_check_at`/`has_update`/`latest_version`/`error`，UTC RFC3339）

## 代理

- 显式 `proxy_url` 优先，回退旧 `proxy_port` 兼容（`resolved_proxy_url()`），仅影响更新与任务仓库；检测流量走设置 → 网络检测的 `检测不走代理`
- 产物在 `update/staging/`，自替换由 `campus-auth-helper` 完成；下载前校验 `.sha256`

## 出问题怎么办

- 代理环境：设置 → 系统 → 网络、端口与代理填 `http://127.0.0.1:7890`（支持非本机），留空跟随系统
- 看结果：关于页与设置 → 系统的“上次检查时间”与错误提示即来自 `last_check.json` 的 `error`/`latest_version`
