# 应用与日志

> 对应 `src/config/schema.rs::AppSettings` / `WorkerSettings` / `LoggingSettings` / `UpdaterSettings`，控制台路径 **设置 → 系统**（`/settings/system`）及 **设置 → 浏览器** 的会话保持区域。

## 应用设置（`global.app`）

| 配置项 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 自动打开控制台 | `auto_start_browser` | `true` | 启动后是否自动在浏览器中打开控制台 |
| 运行模式 | `runtime_mode` | `full` | `full`（完整模式）/ `lightweight`（轻量模式，仅运行 Engine 与系统托盘，Web 控制台按需唤起；macOS 自动回落至 `full`） |
| 启动后执行 | `startup_action` | `monitor` | `monitor`（启动后进入网络监测）/ `login_once`（启动后执行一次登录）/ `none`（不执行任何动作）；可通过 `campus-auth --startup-action` 命令行参数覆盖 |
| 控制台端口 | `port` | `50721` | Web 控制台监听端口，端口被占用时自动递增，重试 5 次；可通过 `--port` / `CAMPUS_AUTH_PORT` 覆盖 |
| 开机自启 | `autostart_enabled` | `false` | 是否注册系统自启（Windows 写入注册表 Run 键 / macOS 创建 LaunchAgent / Linux 创建 XDG autostart）；可通过 `campus-auth --autostart enable/disable` 切换 |
| 任务通知 | `task_notification` | `true` | 任务完成后是否发送系统通知 |
| 开发者模式 | `developer_mode` | `false` | 是否启用开发者辅助功能 |
| 显示托盘 | `show_tray` | `true` | 是否显示系统托盘图标；关闭后仅 Web 控制台可用，不显示桌面图标 |
| 定时自重启 | `auto_restart_hours` | `24` 小时 | 长期运行场景下，浏览器 / Worker 常驻内存缓慢增长，按周期优雅自重启以回收内存；`0` 表示不启用；运行时修改无需重启即可生效（重启计时任务每分钟读取一次该值） |

## Worker 设置（`global.worker`）

| 配置项 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 保持浏览器进程 | `keep_alive` | `false` | 登录完成后保持浏览器进程常驻，以加快下次登录；开关位于 **设置 → 浏览器** 的会话保持区域 |
| 空闲回收超时 | `idle_timeout_seconds` | `300` 秒 | `keep_alive=false` 时，Worker 空闲达到该时长后自动回收 |

> `keep_alive=false` 为默认的“即用即还”模式，适用于内存敏感环境；启用后需关注 [定时自重启](#应用设置) 的配合使用。

## 日志设置（`global.logging`）

| 配置项 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 日志级别 | `level` | `INFO` | `OFF` / `ERROR` / `WARN` / `INFO` / `DEBUG` / `TRACE`；在 设置 → 系统 中即时热更新，无需重启 |
| 写入文件 | `file_enabled` | `true` | 是否写入 `logs/` 目录 |
| 保留天数 | `retention_days` | `7` 天 | 日志按日归档，超期自动清理 |

- 实时日志通过 `/ws/logs` WebSocket 推送，网络状态通过 `/ws/status` 推送。
- `file_enabled` 与 `level` 的修改即时生效（`ConfigService` 热更新）。

## 自动更新（`global.updater`）

| 配置项 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启动检查 | `check_on_startup` | `true` | 启动时是否检查更新；仅 `check_interval_hours == 0` 时独立生效 |
| 自动检查总开关 | `auto_check_enabled` | `true` | 关闭后，后台检查与启动检查均静默处理，仅保留手动“立即检查” |
| 更新通道 | `channel` | `stable` | `stable`（正式版）/ `prerelease`（测试版）/ `all`（全通道最新版，按 semver 取最高版本） |
| 发布源 | `release_source_url` | GitHub Releases API | 发布清单地址 |
| 检查间隔 | `check_interval_hours` | `24` 小时 | `0`=仅启动检查，不进行周期性检查；控制台显示为“每次启动 / 每天一次 / 每周一次”（`0/24/168`） |
| 使用代理 | `use_proxy` | `false` | 是否使用显式代理下载更新 |
| 代理地址 | `proxy_url` | 空 | 如 `http://127.0.0.1:7890`，支持非本机代理 |
| 兼容字段 | `proxy_port` | `7890` | 旧版“本地代理端口”，仅用于兼容读取；新配置统一写入 `proxy_url` |

**代理地址解析**（`resolved_proxy_url()`）：`proxy_url` 非空时优先使用；为空时回退至 `proxy_port` 派生的 `http://127.0.0.1:{port}`，两者皆为空则跟随系统代理。`proxy_url` 的默认值保持空字符串，以避免旧配置的自定义端口被覆盖。

> 代理配置仅影响更新与任务仓库的下载；网络检测流量由 **监测不走代理**（`monitor.disable_proxy`）控制，两者相互独立。

- 每次检查无论成功与否均刷新 `update/last_check.json`（`last_check_at` / `has_update` / `latest_version` / `error`，UTC RFC3339 格式）。
- 产物下载至 `update/staging/` 目录，自替换由 `campus-auth-helper` 完成；下载前执行 `.sha256` 校验。

## 完整配置示例

```json
{
  "global": {
    "app": {
      "auto_start_browser": true,
      "runtime_mode": "full",
      "startup_action": "monitor",
      "port": 50721,
      "autostart_enabled": false,
      "task_notification": true,
      "developer_mode": false,
      "show_tray": true,
      "auto_restart_hours": 24
    },
    "worker": {
      "idle_timeout_seconds": 300,
      "keep_alive": false
    },
    "logging": {
      "level": "INFO",
      "file_enabled": true,
      "retention_days": 7
    },
    "updater": {
      "check_on_startup": true,
      "auto_check_enabled": true,
      "channel": "stable",
      "check_interval_hours": 24,
      "use_proxy": false,
      "proxy_url": ""
    }
  }
}
```
