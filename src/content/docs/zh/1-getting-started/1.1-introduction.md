# Campus-Auth 简介

Campus-Auth 是一款面向校园网门户（Captive Portal）的本地自动化认证工具。该工具将“断网后手动打开登录页、填写账号、输入验证码”等重复性操作交由程序自动完成——涵盖断线重连、多网络自动切换、验证码自动识别及日常打卡定时执行，全部流程在本地执行，数据不出本机。

## 功能概览

- **断线自动重连**：在宿舍、教学楼等网络波动较为频繁的环境中，自动检测网络异常并完成静默重连，无需人工干预。
- **多网络自动切换**：依据当前网关 IP 或 Wi-Fi 名称自动匹配对应的配置方案与活跃任务，跨校区、跨运营商场景下亦可自动选择正确的账号与认证流程。
- **复杂门户适配**：针对二次跳转、iframe 嵌套、运营商下拉选择、图片验证码等常见门户形态，通过真实浏览器步骤序列实现稳定覆盖。
- **定时任务执行**：签到、保活等周期性操作可通过 cron 表达式挂载至浏览器任务，无需额外编写脚本，到达设定时间自动执行。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 断网重连 | 提供三种探针：TCP 连通性检测、HTTP 204 门户检测（默认启用）、URL 标题校验；劫持状态优先于离线状态判定；网络异常时探测间隔自动收敛至 30 秒，重连无需等待完整检测周期 |
| 多网络配置 | 每条配置方案独立管理账号、认证地址、匹配规则与活跃任务；`default` 为系统内置兜底项，不可删除；支持按网关 IP 与 SSID 自动切换 |
| 浏览器自动化 | 基于 Playwright 驱动真实浏览器，支持 `input` / `click` / `select` / `ocr` / `eval` 等 18 种步骤类型，并通过 `success_condition` 实现精确的成功判定 |
| 验证码处理 | 通过 `ocr` 步骤按需启用，依赖 `ddddocr`（含推理依赖，体积约百 MB 级），可在 设置 → 任务 中一键安装；单次识别失败后由上层登录重试机制兜底 |
| 定时任务 | 通过一行 cron 表达式关联任意浏览器任务，到达设定时间自动执行 |
| 控制台与系统托盘 | 提供本地 Web 控制台（默认 `http://127.0.0.1:50721`，端口占用时自动递增，重试 5 次）与系统托盘常驻入口 |
| 安全与隐私 | 账号以 `ENC:` 前缀的 AES-256-GCM 密文落盘，内存中经 `zeroize` 清理；鉴权 token 存放于 `config/.auth_token`（权限 `0600`），控制台默认仅允许本机访问；采用进程隔离架构，Playwright 与 OCR 按需懒加载，空闲 300 秒后自动回收 |

## 架构

```text
┌─────────────────────────────────────────────┐
│  Rust 控制面（Tokio + Axum）                 │
│  配置管理 / 状态维护 / 调度 / 监测 Engine     │
└──────────────┬──────────────────────────────┘
               │ NDJSON IPC（子进程通信）
               ▼
┌─────────────────────────────────────────────┐
│  Python Worker                              │
│  Playwright 真实浏览器 + ddddocr 按需懒加载  │
│  空闲 300s 自动回收                          │
└─────────────────────────────────────────────┘
               │
               ▼
        校园网门户登录页
```

- 前端控制台嵌入至二进制文件中，开发期间可跳过前端构建。
- 本地回环服务与系统托盘协同工作，无需依赖云端服务，离线状态下认证逻辑仍可在本地触发。
