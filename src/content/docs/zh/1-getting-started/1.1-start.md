# 新手上路

Campus-Auth 是一款**运行在本机的校园网自动认证工具**。校园网（强制门户 / Captive Portal）在断线、重启或切换 Wi-Fi 后，通常要求手动打开门户登录页、填写账号、选择运营商、识别验证码。Campus-Auth 将上述重复操作交由程序完成：持续监测网络状态，一旦发现离线或被门户劫持，即使用真实浏览器自动完成登录。

全部逻辑在本机执行，账号以密文形式保存在本地，**不经过任何云端服务器**；离线状态下本地调度依然有效。

本页面向新设备上的首次配置，完成全部步骤后可实现两个目标：**掉线后自动重新登录**与**开机后自动运行**。预计耗时 10–20 分钟（含首次运行环境初始化）。

## 工具定位

### 核心能力

- **断网自动重连**：在宿舍、教学楼等网络波动频繁的环境中自动发现异常并静默重连，掉线后约 30 秒内恢复，无需人工干预。
- **多网络自动切换**：依据当前网关 IP 或 Wi-Fi 名称自动选用匹配的账号与登录流程，跨校区、跨运营商无需手动切换。
- **覆盖复杂门户形态**：基于真实浏览器执行操作，可处理二次跳转、iframe 嵌套、运营商下拉、图片验证码等场景。
- **定时签到与保活**：通过 cron 表达式将任意登录任务挂载到定时器，到点自动执行。
- **本地控制台与系统托盘**：提供浏览器可视化控制台，也可最小化至托盘常驻。

### 适用与不适用场景

| 场景 | 是否适用 |
| --- | --- |
| 拥有合法校园网账号，希望省去重复登录操作 | 适用 |
| 需要在多校区 / 多运营商网络之间自动切换 | 适用 |
| 希望签到、保活等操作定时自动执行 | 适用 |
| 无校园网账号，意图绕过认证 | **不适用**。本工具仅自动填写本人的合法凭据，不提供任何绕过认证的能力 |

## 工作原理

Campus-Auth 采用「控制面与执行面分离」的进程架构：Rust 主程序负责配置管理、网络监测、任务调度与本地控制台；与门户登录页交互的浏览器由独立的 Python Worker 按需拉起，空闲后自动回收，两者通过本机进程通信协作。控制台界面在编译时嵌入主程序，浏览器与 OCR 组件按需懒加载。

```text
┌─────────────────────────────────────────────┐
│  Rust 主程序（Tokio + Axum）                 │
│  配置管理 · 网络监测 · 调度 · 本地 Web 控制台 │
└──────────────┬──────────────────────────────┘
               │ 本机进程通信（NDJSON IPC，不出本机）
               ▼
┌─────────────────────────────────────────────┐
│  Python Worker（按需启动）                   │
│  Playwright 真实浏览器 + ddddocr 验证码识别   │
│  空闲 300 秒后自动回收                        │
└──────────────┬──────────────────────────────┘
               ▼
        校园网门户登录页
```

## 前置条件

开始配置前，请准备以下两项信息：

1. **校园网凭据**：账号、密码，以及运营商信息（移动 / 联通 / 电信 / 校园网）。若所在学校门户无运营商选项，可忽略该项。
2. **门户登录页地址**：连接校园网后浏览器自动弹出的页面地址。若所在网络属于劫持型（需先访问任意 `http` 站点才被跳转至登录页），还需准备一个可触发跳转的明文 `http` 地址，详见 [劫持门户（重定向模式）](../2-profiles/2.3-redirect.md)。

## 首次配置

整体流程分为七个步骤：

```text
启动程序 → 填写网络与账号 → 准备浏览器环境 → 获取登录任务
        → 手动验证一次 → 开启自动化 → 收尾验证
```

### 第 1 步：启动程序

尚未安装时，请先按 [下载与安装](1.2-install.md) 完成部署，随后按平台启动：

- **Windows**：双击解压目录中的 `campus-auth.exe`，稍候将自动打开浏览器控制台。
- **macOS / Linux**：在终端进入解压目录执行 `./campus-auth`；无桌面环境时追加 `--no-tray`。
- **Docker**：在 `docker-compose.yml` 所在目录执行 `docker compose up -d --build`，访问 `http://localhost:50721`。

控制台默认地址为 `http://127.0.0.1:50721`。首次访问将进入初始化向导，确认协议后进入仪表盘。

### 第 2 步：填写网络与账号

首次启动会自动生成名为 `default` 的内置配置方案（兜底方案，不可删除）。**直接编辑该方案即可，无需新建**；需要区分多校区或多运营商时，再新建配置方案。

进入 **配置方案** 页（或 设置 → 账号）→ 点击 `default` 的 **编辑**，按下表填写：

| 字段 | 填写说明 | 常见错误 |
| --- | --- | --- |
| 名称 | 便于辨认即可，如「宿舍」「教学楼」 | — |
| 认证地址 `auth_url` | 门户登录页的**完整** URL | 填写 JS 跳转后的中间页，或携带一次性 token 的临时链接 |
| 触发地址 `trigger_url` | **仅劫持型网络需要**，填写明文 `http` 地址，如 `http://www.msftconnecttest.com/connecttest.txt` | 填写 `https`。劫持场景下 TLS 握手会直接失败，无法取得劫持状态 |
| 账号 / 密码 | 本人的校园网凭据，保存时自动加密为 `ENC:` 密文落盘 | 使用会过期的临时账号 |
| 运营商 `isp` | 门户登录页存在运营商下拉时填写（下拉框支持输入自定义关键字） | 留空，导致任务中的下拉选择步骤匹配不到选项 |
| 网关 IP / Wi-Fi 名称 | 点击编辑器中的 **检测当前网络** 一键填入，也可手工填写，用于自动匹配配置方案 | 多校区共用同一条方案，导致漫游后无法自动切换 |

> [!TIP]
> 如何判断网络类型？连接校园网后直接访问门户登录页地址：可正常打开即为直连型，仅填写 `auth_url`；无法打开、必须先访问任意 `http` 站点才发生跳转，即为劫持型，需填写 `trigger_url`，`auth_url` 可留空。详见 [劫持门户（重定向模式）](../2-profiles/2.3-redirect.md)。

### 第 3 步：准备浏览器环境

进入 **设置 → 浏览器**，首次调试仅需关注以下两项，其余保持默认值：

1. **后台运行（无头模式）**：首次调试建议**关闭**。关闭后登录过程会显示真实浏览器窗口，便于确认账号是否填写正确、按钮是否点击命中。待第 7 步全部验证通过后，再重新开启以静默执行。
2. **浏览器选择**：默认使用系统 Edge（`msedge`）。本机已安装 Edge / Chrome 时将直接复用；也可选择 `chromium` / `chrome` / `firefox` / `webkit`，或指定自定义浏览器路径。

视口、语言、时区等参数通常无需调整，完整说明见 [settings.json 配置参考](../6-reference/6.1-settings.md)。

### 第 4 步：获取登录任务

「任务」即自动操作门户登录页的步骤序列。以下三种方式按推荐顺序排列。

#### 方式一：从共享仓库下载（推荐）

若仓库中已有所在学校或同型号认证系统的任务，可直接下载使用，无需自行录制：

进入 **设置 → 任务** → **从仓库导入**，选择索引源并加载，检索本校任务后导入。完整流程见 [从仓库下载共享任务](../3-tasks/3.7-repo.md)。

#### 方式二：使用录制器生成

在真实登录页上按操作顺序点选元素，即可生成浏览器任务：

1. 为浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 在 **设置 → 任务** 中点击 **安装录制器脚本**。
3. 打开校园网门户登录页，点击页面上的录制浮动按钮，依次点选：账号输入框 → 密码输入框 → 验证码（如有）→ 登录按钮。
4. 结束录制并保存，然后在任务管理中将其 **设为活跃任务**。

详见 [任务录制器](../3-tasks/3.2-recorder.md)。

#### 方式三：手工编写或修改任务

当门户较为特殊、录制结果需要微调时采用。浏览器任务保存在 `tasks/browser/*.json`，最简示例如下：

```json
{
  "name": "校园网登录",
  "url": "{{LOGIN_URL}}",
  "timeout": 30000,
  "navigation_wait": 1.0,
  "step_delay": 0.5,
  "success_condition": "login_success",
  "steps": [
    { "id": "fill_username", "type": "input", "selector": "#username", "value": "{{USERNAME}}" },
    { "id": "fill_password", "type": "input", "selector": "#password", "value": "{{PASSWORD}}" },
    { "id": "select_isp", "type": "select", "selector": "select[name='isp']", "value": "{{ISP}}", "required": false },
    { "id": "submit", "type": "click", "selector": "button[type='submit']" },
    { "id": "check_success", "type": "eval", "script": "() => document.body.innerText.includes('登录成功')", "store_as": "login_success" }
  ]
}
```

其中 `{{USERNAME}}`、`{{PASSWORD}}`、`{{ISP}}`、`{{LOGIN_URL}}` 会在运行时替换为第 2 步填写的内容，**请勿将真实密码写入任务文件**。全部步骤类型见 [浏览器任务](../3-tasks/3.3-browser.md)，变量规则见 [变量与成功判定](../3-tasks/3.4-variables.md)。

### 第 5 步：手动验证一次

返回 **仪表盘** 点击 **登录**。由于第 3 步已关闭后台运行，此时可看到浏览器窗口完整执行一遍登录动作。

- 若页面被正确填写、网络恢复正常且仪表盘日志显示成功，说明主流程已打通，可继续第 6 步。
- 若未达预期，请按下表就地排查：

| 现象 | 处理方式 |
| --- | --- |
| 按钮未点中 / 输入框未填写 | 保持窗口可见再执行一次，观察元素是否位于 iframe 内（需为步骤补充 `frame` 字段）、选择器是否因门户改版而失效 |
| 页面跳转后元素尚未加载 | 将任务的 `navigation_wait` 调整至 `1.5–2.0` 秒；需要固定等待时使用 `sleep` 步骤 |
| 验证码识别失败 | 含 `ocr` 步骤的任务需先在 设置 → 任务 安装 OCR 依赖（`ddddocr`，约百 MB）。OCR 单次不重试，由整体登录重试兜底 |
| 需要逐步定位 | 使用调试面板单步执行，查看每步输出与失败截图；必要时使用一键取证打包现场 |

选择器应优先使用稳定的 `id` / `name` / `data-*` 属性，避免使用构建工具自动生成的一长串 class。完整调试方法见 [调试与取证](../3-tasks/3.6-debug.md)。

### 第 6 步：开启自动化

手动验证通过后，再开启各项自动能力。

#### 断网自动重连

进入 **设置 → 网络监测**。默认已开启 **HTTP 204 门户检测**，通常无需调整——请保持至少一种网络探针处于开启状态，否则掉线或被劫持时不会自动触发登录。

判定异常后，探测间隔会自动收敛至 30 秒，即掉线后约半分钟内开始重连。三种探针的取舍见 [断网自动重连](../4-automation/4.1-monitor.md)。

#### 定时签到与保活

在 **定时任务** 页使用 cron 表达式关联任意已有任务。cron 采用 **5 段** 格式 `分 时 日 月 周`：

| 表达式 | 含义 |
| --- | --- |
| `0 8 * * *` | 每天 08:00 执行 |
| `30 7 * * 1-5` | 工作日 07:30 执行 |
| `0 */2 * * *` | 每 2 小时执行一次 |

错过的时间点不会补跑，建议先手动验证任务稳定后再挂载定时。详见 [定时任务](../4-automation/4.2-scheduled.md)。

#### 开机自启

以下两种方式任选其一：在 **设置 → 系统** 中开启「开机自启动」，或执行 `campus-auth --autostart enable`。

开机后的动作由「启动后执行」（`startup_action`）控制，可选直接进入监测、先登录一次或不执行动作，详见 [开机自启与托盘](../4-automation/4.3-autostart.md)。

### 第 7 步：收尾验证

1. 确认手动登录稳定后，回到 **设置 → 浏览器**，重新开启 **后台运行**，使后续登录静默执行。
2. 通过健康检查与接口确认服务状态：

```bash
curl http://127.0.0.1:50721/api/health

# 带鉴权查看当前配置方案（令牌位于 config/.auth_token）
curl -H "X-Auth-Token: $(cat config/.auth_token)" http://127.0.0.1:50721/api/profiles
```

3. 在控制台确认：仪表盘日志正常输出登录结果、`/ws/logs` 实时日志已连接、失败截图可正常查看。

至此配置完成，程序将按预期实现开机自动运行、掉线自动重连、到点自动签到。
