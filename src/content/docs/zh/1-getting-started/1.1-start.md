# 新手上路

认证喵（Campus-Auth）是一款**运行在本机的校园网自动认证工具**。校园网（强制门户 / Captive Portal）在断线、重启或切换 Wi-Fi 后，通常要求手动打开门户登录页、填写账号、选择运营商、识别验证码。认证喵将上述重复操作交由程序完成：持续监测网络状态，一旦发现离线或被门户劫持，即按方案选择浏览器自动化或直连请求完成登录。

全部逻辑在本机执行，账号以密文形式保存在本地，**不经过任何云端服务器**；离线状态下本地调度依然有效。

本页面向新设备上的首次配置，完成全部步骤后可实现**掉线自动重连**与**开机自动运行**，预计耗时 10–20 分钟。文中截图来自 v5.0.0 的全新安装实例，界面如与截图存在细节差异，以程序内提示为准。

## 工具定位

- **断网自动重连**：持续监测网络，掉线或被门户劫持后约 30 秒内静默重连。
- **多网络自动切换**：按网关 IP / Wi-Fi 名称自动选用匹配的账号与登录流程。
- **开箱即用**：内置「通用登录」任务可语义识别常见登录表单，多数校园网无需自行编写；也可从共享仓库下载、用 AI 生成或录制器辅助制作。
- **覆盖复杂门户**：浏览器渠道可处理二次跳转、iframe、运营商下拉、图片验证码；简单门户可用免浏览器的直连请求。
- **定时签到与保活**：定时任务支持「每日固定时间」与「每次启动后」两种触发方式。
- **本地控制台与系统托盘**：浏览器可视化控制台，可最小化至托盘常驻。

### 适用与不适用场景

| 场景 | 是否适用 |
| --- | --- |
| 拥有合法校园网账号，希望省去重复登录操作 | 适用 |
| 需要在多校区 / 多运营商网络之间自动切换 | 适用 |
| 希望签到、保活等操作定时自动执行 | 适用 |
| 无校园网账号，意图绕过认证 | **不适用**。本工具仅自动填写本人的合法凭据，不提供任何绕过认证的能力 |
| 必须安装专用认证客户端（如 iNode、Dr.COM 客户端、锐捷认证客户端）才能联网 | **不适用**。本工具只处理网页门户登录，无法代替客户端完成认证 |
| 门户要求短信验证码 | **不适用**。验证码由运营商下发至手机，程序无法自动获取 |
| 门户使用滑块、点选等交互式验证码 | **不适用**。OCR 仅支持图形字符验证码，无法完成拖动与点选 |

## 工作原理

Campus-Auth 采用「控制面与执行面分离」的进程架构：Rust 主程序负责配置管理、网络监测、任务调度与本地控制台；与门户登录页交互的浏览器由独立的 Python Worker 按需拉起，空闲后自动回收，两者通过本机进程通信协作。控制台界面在编译时嵌入主程序，浏览器与 OCR 组件按需懒加载。

```text
┌─────────────────────────────────────────────┐
│  Rust 主程序（Tokio + Axum）                 │
│  配置管理 · 网络监测 · 调度 · 本地 Web 控制台 │
└──────────────┬──────────────────────────────┘
               │ 本机进程通信（NDJSON IPC，不出本机）
               ▼
┌─────────────────────────────────────────────┐
│  Python Worker（按需启动）                   │
│  Playwright 真实浏览器 + ddddocr 验证码识别   │
│  空闲 300 秒后自动回收                        │
└──────────────┬──────────────────────────────┘
               ▼
        校园网门户登录页
```

## 前置条件

开始配置前，请准备以下两项信息：

1. **校园网凭据**：账号、密码，以及运营商信息（移动 / 联通 / 电信 / 校园网）。若所在学校门户无运营商选项，可忽略该项。
2. **门户登录页地址**（可选）：连接校园网后浏览器自动弹出的页面地址。v5.0.0 起方案编辑器内置**重定向检测**，多数校园网无需手工填写认证地址，见第 2 步。

## 首次配置

整体流程分为七个步骤：

```text
启动程序 → 填写方案 → 选择登录方式 → 确认登录任务
        → 手动验证一次 → 开启自动化 → 收尾验证
```

### 第 1 步：启动程序

尚未安装时，请先按 [下载与安装](1.2-install.md) 完成部署，随后按平台启动：

- **Windows**：双击解压目录中的 `campus-auth.exe`，稍候将自动打开浏览器控制台。
- **macOS / Linux**：在终端进入解压目录执行 `./campus-auth`；无桌面环境时追加 `--no-tray`。
- **Docker**：在 `docker-compose.yml` 所在目录执行 `docker compose up -d --build`，访问 `http://localhost:50721`。

控制台默认地址为 `http://127.0.0.1:50721`。首次访问将进入初始化向导。

> [!IMPORTANT]
> 协议内容较长，**勾选框与「同意并开始使用」按钮位于弹窗底部，一屏内看不到**——请在弹窗内**向下滚动到底**，先勾选「我已阅读并同意《使用协议》和《免责声明》」，按钮才会解除置灰并可点击：

![初始化向导：需向下滚动到底部才能看到同意勾选框与按钮](/screenshots/docs/01-wizard.avif)

随后进入**仪表盘**：左侧是主导航（仪表盘 / 方案 / 任务 / 设置 / 关于）与运行状态，中部为检测统计、快捷操作与登录历史，右侧为实时日志：

![仪表盘：检测统计、快捷操作、登录历史与实时日志](/screenshots/docs/02-dashboard.avif)

> [!NOTE]
> 首次启动时仪表盘可能出现「Python 环境未就绪」横幅，属正常现象：浏览器登录所需的 Python 环境会在首次登录时自动初始化，也可前往 **设置 → 任务与环境** 手动初始化。直连请求登录不需要该环境。

### 第 2 步：填写网络与账号

首次启动会自动生成名为 `default`（默认显示名「默认网络」）的内置方案，它是兜底方案、不可删除。**直接编辑该方案即可，无需新建**；需要区分多校区或多运营商时，再新建方案。

进入 **方案** 页，编辑器自上而下分为基本信息、网络匹配（折叠）、账号凭证、认证设置与登录方式几个区块：

![方案编辑器：基本信息与账号凭证](/screenshots/docs/03-profile-editor.avif)

按下表填写：

| 区块 | 字段 | 填写说明 |
| --- | --- | --- |
| 基本信息 | 方案名称 | 便于辨认即可，如「宿舍」「教学楼」 |
| 网络匹配 | 网关 IP / Wi-Fi 名称 | 点击区块内 **检测当前网络** 一键填入，用于多方案自动切换；单方案可留空 |
| 账号凭证 | 账号 / 密码 | 本人的校园网凭据，保存时自动加密为 `ENC:` 密文落盘 |
| 账号凭证 | 运营商 | 门户登录页存在运营商下拉时选择或输入自定义关键字，留空则跳过下拉步骤 |
| 认证设置 | 认证地址 | **多数校园网无需填写**，见下方「重定向检测」 |
| 登录方式 | 浏览器自动化 / 直连请求 | 复杂门户选浏览器自动化；可复现 HTTP 登录请求的简单门户选直连请求 |

#### 认证地址与重定向检测

认证地址（`auth_url`）为**可选项**：程序默认打开内置触发地址并跟随门户跳转，多数校园网无需手工填写。拿不准时先退出校园网登录态，点击 **重定向检测**，程序会打开可见浏览器窗口实测跳转并给出结论：

![认证设置：重定向检测按钮与可选的认证地址](/screenshots/docs/04-profile-auth.avif)

劫持型网络需自定义触发地址时，展开 **重定向高级设置** 填写（必须为明文 `http`）。详见 [认证地址与重定向](../2-profiles/2.3-redirect.md)。

#### 网络匹配（可选）

多网络环境时展开「网络匹配」，点击 **检测当前网络** 一键填入当前网关 IP 与 Wi-Fi 名称：

![网络匹配：检测当前网络一键填入网关 IP 与 SSID](/screenshots/docs/05-profile-match.avif)

「登录方式」为二选一：**浏览器自动化**（默认，兼容验证码与动态表单，需要 Python 与浏览器）或**直连请求**（直接发登录请求，免 Python 与浏览器，可点 **直连配置向导** 按引导填写，详见 [直连请求登录](../2-profiles/2.4-http-login.md)）。「浏览器任务」默认绑定内置 **通用登录**，按方案绑定、切换方案即切换任务。填写完成后点击 **保存方案**。

### 第 3 步：准备浏览器环境

如果方案使用浏览器自动化（直连请求不需要准备浏览器环境），无需逐项手动调整，直接使用运行模式预设：进入 **设置 → 系统 → 运行模式**，点击 **调试模式**，程序会一键切换到排查配置——显示浏览器窗口、保留浏览器进程、记录调试日志、启动后不自动登录，方便完整观察登录过程：

![系统设置：运行模式预设与启动行为](/screenshots/docs/09-settings-system.avif)

浏览器参数保持默认值即可：

- **浏览器选择**：以卡片形式列出本机可用的浏览器，默认使用系统 **Edge**（本机已安装 Edge / Chrome 时直接复用，无需下载）；也可切换 Chromium / Chrome / Firefox 或填写自定义浏览器路径，入口在 **设置 → 浏览器**。
- 视口、语言、时区、会话保持等参数通常无需调整，完整说明见 [settings.json 配置参考](../6-reference/6.1-settings.md)。

> [!TIP]
> 首次调试只需记住一个入口：**调试模式**看过程，**默认模式**管日常。切换预设前会列出每一项「旧值 → 新值」，确认后才写入；夜间暂停时段的起止时间不受预设影响。

### 第 4 步：确认登录任务

「任务」即自动操作门户登录页的步骤序列。当前方案默认绑定的 **通用登录（内置默认）** 任务可语义识别表单、智能判断结果，**多数校园网无需额外准备工作，可直接跳到第 5 步验证**；内置任务不可删除，可在 **任务** 页查看或复制后修改。

若内置任务不适合本校门户，按推荐顺序尝试以下方式：

#### 方式一：从共享仓库下载（推荐）

若仓库中已有所在学校或同型号认证系统的任务，可直接下载使用：

进入 **任务 → 浏览器任务** 标签页，点击 **仓库导入**，选择索引源并加载，检索本校任务后导入。页面右侧同时提供录制器、编写指南与 AI 生成的入口：

![任务页：浏览器任务列表与导入入口](/screenshots/docs/11-tasks.avif)

完整流程与安全核对见 [从仓库下载共享任务](../3-tasks/3.7-repo.md)。

#### 方式二：AI 生成浏览器任务

进入 **任务 → AI 生成浏览器任务** 标签页，按三步操作：配置 LLM 服务 → 捕获登录页面 → 生成并保存任务。支持 OpenCode Zen（内置体验 Key，开箱可用）、智谱 GLM、DeepSeek 及其他 OpenAI 兼容服务：

![AI 生成浏览器任务：三步流程与服务商选择](/screenshots/docs/12-tasks-ai.avif)

该功能仍在开发中，生成结果建议按第 5 步实测验证；无法生成正确任务时改用方式三或方式四。

#### 方式三：使用录制器生成 AI 提示词

录制器不再直接生成任务，而是把你在登录页上点选的元素整理成一段 **AI 提示词**，交给任意大模型生成任务 JSON：

1. 为浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 在 **设置 → 任务与环境** 中点击 **安装录制器脚本**，同一页面还提供任务编写指南与手册下载：
3. 打开校园网门户登录页，点击页面上的录制浮动按钮，依次点选：账号输入框 → 密码输入框 → 验证码（如有）→ 登录按钮。
4. 点击 **复制 AI 提示词**，把提示词发给任意大模型（ChatGPT、GLM、DeepSeek 等），得到任务 JSON 后在 **任务** 页导入或粘贴。

![任务与环境：录制器入口、任务概览与 OCR 安装](/screenshots/docs/08-settings-tasks.avif)

详见 [任务录制器](../3-tasks/3.2-recorder.md)。

#### 方式四：手工编写或修改任务

当门户较为特殊、生成结果需要微调时采用。浏览器任务保存在 `tasks/browser/*.json`，最简示例如下：

```json
{
  "name": "校园网登录",
  "url": "{{LOGIN_URL}}",
  "timeout": 30000,
  "navigation_wait": 1.0,
  "step_delay": 0.5,
  "success_condition": "login_success",
  "steps": [
    { "id": "fill_username", "type": "input", "selector": "#username", "value": "{{USERNAME}}" },
    { "id": "fill_password", "type": "input", "selector": "#password", "value": "{{PASSWORD}}" },
    { "id": "select_isp", "type": "select", "selector": "select[name='isp']", "value": "{{ISP}}", "required": false },
    { "id": "submit", "type": "click", "selector": "button[type='submit']" },
    { "id": "check_success", "type": "eval", "script": "() => document.body.innerText.includes('登录成功')", "store_as": "login_success" }
  ]
}
```

其中 `{{USERNAME}}`、`{{PASSWORD}}`、`{{ISP}}`、`{{LOGIN_URL}}` 会在运行时替换为第 2 步填写的内容，**请勿将真实密码写入任务文件**。全部步骤类型见 [浏览器任务](../3-tasks/3.3-browser.md)，变量规则见 [变量与成功判定](../3-tasks/3.4-variables.md)。

无论以哪种方式获得任务，最后回到 **方案 → 登录方式 → 浏览器任务** 确认绑定（使用内置任务时保持「通用登录（内置默认）」即可）。

### 第 5 步：手动验证一次

如果选择的是**直连请求**，回到方案编辑器点击 **发送测试请求**，确认响应匹配成功后再保存方案。

如果选择的是**浏览器任务**，回到**仪表盘**点击快捷操作中的 **手动登录**。由于第 3 步已切到调试模式（显示浏览器窗口），此时可看到浏览器完整执行一遍登录动作。配置不完整或执行失败时，仪表盘会弹出明确错误并在「登录历史」中留档：

![手动登录的失败反馈：登录历史与实时日志同步记录](/screenshots/docs/14-manual-login.avif)

- 若页面被正确填写、网络恢复正常且仪表盘日志显示成功，说明主流程已打通，可继续第 6 步。
- 若未达预期，请按下表就地排查：

| 现象 | 处理方式 |
| --- | --- |
| 按钮未点中 / 输入框未填写 | 保持窗口可见再执行一次，观察元素是否位于 iframe 内（需为步骤补充 `frame` 字段）、选择器是否因门户改版而失效 |
| 页面跳转后元素尚未加载 | 将任务的 `navigation_wait` 调整至 `1.5–2.0` 秒；需要固定等待时使用 `sleep` 步骤 |
| 验证码识别失败 | 含 `ocr` 步骤的任务需先在 设置 → 任务与环境 安装可选 OCR 依赖（`ddddocr`，约 120 MB）。OCR 单次不重试，由整体登录重试兜底 |
| 需要逐步定位 | 使用调试面板单步执行，查看每步输出与失败截图；必要时使用一键取证打包现场 |

选择器应优先使用稳定的 `id` / `name` / `data-*` 属性，避免使用构建工具自动生成的一长串 class。完整调试方法见 [调试与取证](../3-tasks/3.6-debug.md)。

### 第 6 步：开启自动化

手动验证通过后，再开启各项自动能力。

#### 断网自动重连

进入 **设置 → 检测**（网络检测）。默认已开启 **204 门户检测** 与 **登录严格模式**，通常无需调整——请保持 204 或 URL 内容探针至少一种开启（TCP 单独开启不能给出明确的在线判定）：

![网络检测设置：探针开关、重试策略与诊断辅助](/screenshots/docs/06-settings-detection.avif)

然后回到仪表盘右上角点击 **启动检测**。判定异常后，探测间隔会自动收敛至 30 秒，即掉线后约半分钟内开始重连。

> [!IMPORTANT]
> 调试模式的「启动后执行」为「无操作」，程序重启后不会自动开始检测；第 7 步切回 **默认模式** 后会自动改为「进入监测」，无需手动处理。不使用预设时，也可在 **设置 → 系统 → 启动后执行** 中手动改为「进入监测」。

三种探针的取舍见 [断网自动重连](../4-automation/4.1-monitor.md)。

#### 定时签到与保活

在 **任务 → 定时任务** 页点击 **新建定时任务**，选择任务类型（浏览器任务或脚本）与触发方式：

- **定时执行**：选择每日固定时间（如 08:00），到点自动执行；
- **启动后执行**（新增）：程序每次启动并延迟指定秒数后自动执行，可限制「每天最多成功次数」并配置失败重试，适合签到类任务。

![新建定时任务：任务类型、触发方式与超时](/screenshots/docs/13-scheduled-new.avif)

先手动验证任务稳定后再挂载定时，错过的时间点不补跑。详见 [定时任务](../4-automation/4.2-scheduled.md)。

#### 开机自启

在 **设置 → 系统** 中开启「开机自启动」，或执行 `campus-auth --autostart enable`；第 7 步切换回 **默认模式** 时也会自动开启它。

开机后的动作由「启动后执行」（`startup_action`）控制，可选直接进入监测、先登录一次或不执行动作；新配置默认为**不执行动作**，需要无人值守时改为「进入监测」。详见 [开机自启与托盘](../4-automation/4.3-autostart.md)。

### 第 7 步：收尾验证

1. 确认手动登录稳定后，回到 **设置 → 系统 → 运行模式**，点击 **默认模式**：一键恢复浏览器后台静默运行、启动后自动检测（等效「进入监测」）、开机自启动与夜间暂停时段，后续登录与开机守护无需再逐项设置。
2. 通过健康检查与接口确认服务状态：

```bash
curl http://127.0.0.1:50721/api/health

# 带鉴权查看当前配置方案（令牌位于 config/.auth_token）
curl -H "X-Auth-Token: $(cat config/.auth_token)" http://127.0.0.1:50721/api/profiles
```

3. 在控制台确认：仪表盘日志正常输出登录结果、`/ws/logs` 实时日志已连接、失败截图可正常查看。

至此配置完成，程序将按预期实现开机自动运行、掉线自动重连、到点自动签到。
