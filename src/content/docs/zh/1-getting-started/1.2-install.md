# 下载与安装

本页面指导将 Campus-Auth 部署到目标设备并成功打开控制台。桌面用户推荐使用**便携版**，服务器与 NAS 用户推荐使用 **Docker**，开发者可从源码构建。

> [!NOTE]
> 安装环节仅负责让程序运行起来。将账号与登录任务配置到「可自动登录」的完整流程，见 [新手上路](1.1-start.md)。

## 选择安装方式

| 方式 | 适用人群 | 是否需要编译 | 运行环境 |
| --- | --- | --- | --- |
| 便携版（推荐） | Windows / macOS / Linux 桌面用户 | 否，解压即用 | 首次登录时按需自动下载浏览器运行时 |
| Docker | 服务器、NAS、长期挂机、无桌面环境 | 否 | 镜像已预装完整环境，无需等待下载 |
| 从源码构建 | 需要自行修改或体验开发分支的开发者 | 是（Rust + Node.js） | 本机自备工具链 |

## 确认系统架构

安装包命名格式为 `campus-auth-<版本>-<平台架构>.<压缩格式>`，请先确认设备架构：

| 系统 | 查看命令 | 架构对应关系 |
| --- | --- | --- |
| Windows | 命令提示符执行 `echo %PROCESSOR_ARCHITECTURE%` | `AMD64` → `x86_64-pc-windows-msvc`；`ARM64` → `aarch64-pc-windows-msvc` |
| macOS | 终端执行 `uname -m` | `arm64`（Apple Silicon）→ `aarch64-apple-darwin`；`x86_64`（Intel）→ `x86_64-apple-darwin` |
| Linux | 终端执行 `uname -m` | `x86_64` → `x86_64-unknown-linux-gnu`；`aarch64` → `aarch64-unknown-linux-gnu` |

> [!TIP]
> 绝大多数 Windows 电脑、Intel 芯片的 Mac 与普通 PC 服务器均为 x86_64（amd64）；M 系列 Mac、树莓派 4/5 与部分 ARM 服务器为 aarch64（arm64）。

前往 [GitHub Releases](https://github.com/Misyra/Campus-Auth-rs/releases) 下载对应压缩包（Windows 为 `.zip`，macOS / Linux 为 `.tar.gz`）。同目录下的 `.sha256` 文件可用于校验下载完整性。

## Windows

### 1. 解压至固定目录

将压缩包**完整解压**到一个固定且可写的目录，例如 `D:\campus-auth\`。解压后应包含主程序 `campus-auth.exe`、更新助手 `campus-auth-helper.exe`，以及 `resources\`、`python_worker\` 等目录。

> [!WARNING]
> - 请勿在压缩包预览窗口中双击运行，否则程序会在临时目录启动，无法定位同级的配置与资源目录。
> - 请勿解压至 `C:\` 根目录或 `C:\Program Files\` 等需要管理员授权的路径。程序默认将配置写入可执行文件同级目录，此类位置会因权限不足导致写入失败。

### 2. 启动程序

双击 `campus-auth.exe` 即可。该程序为 GUI 子系统程序，**不会弹出控制台窗口**；稍候会自动使用默认浏览器打开控制台 `http://127.0.0.1:50721`。

如需通过命令行启动或查看输出，可在 PowerShell 中执行：

```powershell
# 进入解压目录后启动
.\campus-auth.exe

# 指定固定端口
.\campus-auth.exe --port 50721
```

### 3. 处理安全提示

- 弹出「已保护你的电脑（SmartScreen）」时，点击 **更多信息 → 仍要运行**。
- 若被第三方安全软件拦截，请将 `campus-auth.exe` 加入白名单后重试；开机自启被拦截时同理。

### 4. 首次启动

首次访问将显示初始化向导，确认使用协议与免责声明后进入仪表盘。**首次执行登录时**，程序会自动下载 `uv` 与 Python 运行依赖；本机已安装 Microsoft Edge 或 Google Chrome 时将直接复用系统浏览器，无需额外下载 Chromium。

下载失败的处理方式见 [启动与安装故障](../7-faq/7.2-startup.md)。

## macOS

### 1. 解压

在终端进入下载目录，解压与芯片对应的压缩包：

```bash
# Apple Silicon（M 系列）与 Intel 仅文件名中的架构不同
tar -xzf campus-auth-*-aarch64-apple-darwin.tar.gz   # Apple Silicon
tar -xzf campus-auth-*-x86_64-apple-darwin.tar.gz    # Intel
cd campus-auth
chmod +x campus-auth campus-auth-helper
```

### 2. 清除隔离属性

通过浏览器下载的二进制带有 quarantine 标记，Gatekeeper 会提示「无法验证开发者」或「已损坏」。对解压后的目录执行一次即可：

```bash
xattr -cr .
```

### 3. 启动程序

```bash
./campus-auth

# 浏览器会自动打开 http://127.0.0.1:50721；不希望自动打开时追加 --no-browser
./campus-auth --no-browser
```

> [!NOTE]
> 受系统框架限制，macOS 暂不支持系统托盘，轻量模式也会自动回落到完整模式。该行为属预期，不影响自动登录与控制台使用。

## Linux

### 1. 安装运行时库（桌面环境）

Linux 版的系统托盘动态链接 GTK3 等库。Debian / Ubuntu 及其衍生版请先安装运行时依赖：

```bash
sudo apt update
sudo apt install libgtk-3-0 libayatana-appindicator3-1 librsvg2-2
```

> [!TIP]
> 无桌面环境的服务器可不安装托盘库，启动时追加 `--no-tray` 即可；服务器场景更推荐直接使用 [Docker](#docker) 部署。

### 2. 解压并启动

```bash
tar -xzf campus-auth-*-x86_64-unknown-linux-gnu.tar.gz   # x64
# ARM64 设备（如 64 位树莓派系统）改用 aarch64-unknown-linux-gnu 包
cd campus-auth
chmod +x campus-auth campus-auth-helper
./campus-auth
```

### 3. 兼容性说明

- x64 包基于较旧的 glibc 构建，兼容大多数现行发行版。
- ARM64 包基于较新的系统构建，建议使用 **Debian 12+ / Ubuntu 22.04+** 或 64 位树莓派系统；过旧的发行版可能因 glibc 版本过低而无法运行。

### 4. 配置 systemd 常驻（可选）

以下为 user 级常驻服务示例，请按实际路径修改 `ExecStart` 与 `WorkingDirectory`，保存为 `~/.config/systemd/user/campus-auth.service`：

```ini
[Unit]
Description=Campus-Auth
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/campus-auth
ExecStart=/opt/campus-auth/campus-auth --no-browser --no-tray
Restart=on-failure

[Install]
DefaultTarget=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now campus-auth
```

## Docker

Docker 镜像已预装 Python 运行环境与 Chromium，**首次使用无需等待任何下载**，适用于服务器、NAS 与无桌面环境的长期挂机场景。

### 方式一：Docker Compose（推荐）

便携包与仓库根目录均附带 `docker-compose.yml`，在该文件所在目录执行：

```bash
# 构建并后台启动
docker compose up -d --build

# 查看实时日志
docker compose logs -f

# 健康检查（返回正常即启动成功）
curl http://localhost:50721/api/health
```

随后在浏览器打开 `http://localhost:50721` 即可。配置、任务与日志通过命名卷 `campus-auth-data` 持久化到 `/data`，容器重建不会丢失数据。

### 方式二：单条 docker 命令

```bash
docker build -t campus-auth .

docker run -d \
  --name campus-auth \
  --restart unless-stopped \
  -p 127.0.0.1:50721:50721 \
  -v campus-auth-data:/data \
  campus-auth
```

### 数据持久化与目录挂载

默认使用命名卷。若希望数据直接落在宿主机目录以便备份，可创建 `./data` 目录并改用仓库提供的覆盖文件：

```bash
mkdir -p ./data
docker compose -f docker-compose.yml \
  -f docker/docker-compose.override.example.yml up -d --build
```

### 关键环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CAMPUS_AUTH_HOST` | `0.0.0.0` | 容器内监听地址，必须为 `0.0.0.0` 才能从宿主机访问 |
| `CAMPUS_AUTH_PORT` | `50721` | 监听端口 |
| `CAMPUS_AUTH_BASE_PATH` | `/data` | 容器内数据根目录，与数据卷对应 |
| `RUST_LOG` | `info` | 日志级别，可选 `debug` / `info` / `warn` / `error` |

> [!WARNING]
> 容器内的鉴权令牌仅用于防止本机网页被跨站请求伪造，**并非远程访问密码**。默认端口仅绑定宿主机回环地址 `127.0.0.1`，请勿直接将端口暴露到局域网或公网。确需远程访问时，请在反向代理或 VPN 层另行配置独立账号认证与 HTTPS。
>
> 若校园网门户只能从宿主机内网访问，Linux 上可在 compose 中使用 `network_mode: host`（此时移除 `ports` 映射）。更多说明见仓库内 `docker/README.md`。

## 从源码构建

适用于需要自行修改代码或体验开发分支的用户。

### 构建依赖

- **Rust 1.85+**（Edition 2024 的最低要求；仓库 `rust-toolchain.toml` 固定了具体版本，安装 rustup 后会自动采用）。
- **Node.js**（推荐 22 LTS），用于构建内嵌前端。
- Linux 桌面构建还需开发头文件：

```bash
sudo apt install libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev libxdo-dev pkg-config
```

### 构建步骤

```bash
# 1. 先构建前端，产物由 rust-embed 嵌入二进制
cd frontend
npm ci
npm run build
cd ..

# 2. 编译并运行
cargo run --release

# 仅修改 Rust 逻辑、希望跳过前端嵌入以加快编译时
cargo check --features no-embed

# 运行测试
cargo test
```

Windows 用户也可直接使用仓库提供的打包脚本（需 PowerShell 7+）：

```powershell
./build.ps1                 # 前端 + Rust + 组装便携目录，输出到 dist/
./build.ps1 -SkipFrontend   # 已有 frontend/dist 时跳过前端构建
```

## 启动后的常见问题

### 端口与访问地址

- 默认监听 `127.0.0.1:50721`，仅本机可访问；端口被占用时自动递增，最多重试 5 次，实际端口记录在 `config/.runtime_port`。
- 可通过命令行参数或环境变量固定：

```bash
campus-auth --host 127.0.0.1 --port 50721
# 等价环境变量：CAMPUS_AUTH_HOST / CAMPUS_AUTH_PORT / CAMPUS_AUTH_BASE_PATH
```

### 单实例机制

程序同时仅运行一份实例，由 `config/.lock` 排他锁保证。程序运行时再次双击或执行启动命令，**不会开启第二个进程**，而是直接在浏览器打开已有实例的控制台。可通过以下命令管理实例：

```bash
campus-auth --status    # 查看运行实例的 PID 与端口
campus-auth --stop      # 停止运行中的实例
campus-auth --force     # 残留进程占用时，终止旧实例后重新启动
```

### 验证服务是否就绪

```bash
curl http://127.0.0.1:50721/api/health
```

该健康检查接口无需鉴权，能正常返回即代表服务已就绪。
