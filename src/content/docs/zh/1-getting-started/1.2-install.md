# 安装与运行

## 便携版（推荐）

1. 前往 [Releases](https://github.com/Misyra/Campus-Auth-rs/releases) 下载对应平台的压缩包：`Windows x64/arm64` 为 `zip` 格式，`macOS/Linux` 为 `tar.gz` 格式。
2. 解压至任意目录——该目录即为默认的 `base_path`（可通过 `--base-path` 参数或环境变量 `CAMPUS_AUTH_BASE_PATH` 覆盖）。
3. Windows 系统双击 `campus-auth.exe` 即可启动（GUI 子系统，不显示控制台窗口）；macOS / Linux 系统执行 `./campus-auth`。

首次启动时，程序将自动打开 `http://127.0.0.1:50721` 的初始化向导页面，完成使用协议与免责声明的确认后进入仪表盘。

> **环境初始化提示**：首次执行登录时，程序将自动下载 `uv` 及 Python 依赖，下载失败可参照 [常见问题](../7-faq/7.1-troubleshoot.md) 中的排障指引进行处理。已安装 Edge / Chrome 的设备可直接复用系统浏览器，无需等待 Chromium 下载；Docker 镜像已预置完整运行环境，无需额外等待。

## 端口与实例管理

- 默认监听地址为 `127.0.0.1:50721`，端口被占用时自动递增重试，最多 5 次；可通过 `campus-auth --port 50721` 或环境变量 `CAMPUS_AUTH_PORT` / `CAMPUS_AUTH_HOST` 指定固定端口与地址。实际生效端口写入 `config/.runtime_port`。
- 运行期间再次双击 `campus-auth.exe` 不会启动新的进程实例，而是直接在浏览器中打开已有实例的控制台页面。单实例由 `config/.lock` 的排他文件锁保证，进程退出后由操作系统自动释放；`config/.instance` 仅记录 PID 与端口，供 `campus-auth --status` 查询。
- 可通过 `campus-auth --status` / `--stop` / `--force` 查询实例状态、停止或强制抢占旧实例（含 PID 复用防护机制）。

## 从源码构建

前置依赖：Node.js（前端构建）、Rust 1.85 及以上版本（仓库 `rust-toolchain.toml` 固定为 1.98）。

```bash
# 1. 构建前端资源，供 rust-embed 嵌入
cd frontend && npm install && npm run build && cd ..

# 2. 编译并运行
cargo build
cargo run

# 开发期间可跳过前端嵌入（适用于仅修改 Rust 逻辑的场景，可加快构建速度）
cargo check --features no-embed

# 执行测试
cargo test
cargo test test_config_service -- --nocapture
```

## Docker 部署

```bash
docker compose up -d --build
docker compose logs -f
curl http://localhost:50721/api/health

# 仅使用 docker CLI
docker build -t campus-auth .
docker run -d --name campus-auth -p 50721:50721 -v campus-auth-data:/data campus-auth
```

- 容器内监听地址为 `0.0.0.0:50721`，宿主机通过 `http://localhost:50721` 访问。
- 数据通过命名卷 `campus-auth-data` 实现持久化存储。
- `docker-compose.yml` 默认将端口绑定在 `127.0.0.1:50721`（仅本机可访问）；上面的 `docker run` 示例写为 `-p 50721:50721`，会暴露到全部网卡。由于鉴权 token 仅用于本地浏览器会话防护、并非远程访问凭证，局域网或公网环境请改为 `-p 127.0.0.1:50721:50721`。
- 更多进阶配置请参阅仓库中的 `docker/README.md` 与 `docker/docker-compose.override.example.yml`。

## 运行模式

| 模式 | 命令 | 适用场景 |
| --- | --- | --- |
| 完整（默认） | `campus-auth` | Web 控制台 + 系统托盘 + Engine，全功能运行 |
| 轻量 | `campus-auth --mode lightweight` | 仅运行 Engine 与系统托盘，Web 控制台按需唤起（macOS 因 `tray-icon` 冲突自动回落至完整模式） |
| 单次 | `campus-auth --mode login-once` | 执行一次活跃任务后即退出，适用于脚本或计划任务调用 |

> 轻量模式下，`.instance` 文件初始记录哨兵端口 `0`，首个 Web 请求唤起服务后回写实际端口。

## 鉴权机制

- 启动时生成 `config/.auth_token`（文件权限 `0600`），前端通过 `GET /api/auth/token` 获取，并在后续请求中通过 `X-Auth-Token` / `Authorization: Bearer` / `?token=` 携带。
- 少数端点（如 `GET /api/health`）豁免鉴权，其余接口均需校验。
