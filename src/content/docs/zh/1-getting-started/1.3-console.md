# 控制台导览

Campus-Auth 的全部配置均在本地 Web 控制台完成，无需手工编辑配置文件。本页面说明各界面的位置与职责，便于后续按图索骥。

## 打开控制台

程序启动后会自动使用默认浏览器打开控制台，默认地址为 `http://127.0.0.1:50721`。若未自动弹出：

- **Windows / macOS / Linux**：再次执行启动程序，会直接打开**已在运行**实例的控制台（不会重复启动进程）。
- 端口被占用时地址会自动顺延（最多重试 5 次），以实际端口为准；也可执行 `campus-auth --status` 查看当前端口。

> [!NOTE]
> 控制台与后台 API 共用同一端口。确认服务是否存活，可访问无需鉴权的健康检查接口 `GET /api/health`。

## 初始化向导

首次访问会进入初始化向导，阅读并确认使用协议与免责声明后才会进入仪表盘。该向导仅出现一次，此后直接进入主界面。

## 主导航

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| 仪表盘 | `/` | 查看当前网络状态与实时日志、手动触发一次登录，是日常最常停留的页面 |
| 配置方案 | `/profiles` | 管理不同网络环境下的账号、登录地址与匹配规则 |
| 任务管理 | `/tasks` | 新建 / 编辑浏览器任务与脚本任务，调试并设为活跃任务 |
| AI 生成任务 | `/ai-task` | 上传门户登录页截图，由 AI 辅助生成浏览器任务 |
| 自定义脚本 | `/scripts` | 管理不经浏览器的脚本任务与 Shell 任务 |
| 定时任务 | `/scheduled` | 使用 cron 表达式让任务定时执行（如每日签到） |
| 设置 | `/settings` | 账号、网络监测、浏览器、任务、系统等全部参数（见下表） |
| 外观 | `/appearance` | 主题与界面偏好 |
| 关于 | `/about` | 查看版本与更新通道，手动检查 / 安装更新 |

> [!NOTE]
> 在 **设置** 页存在未保存修改时离开，会弹出二次确认，避免误操作丢失配置。

## 设置页的五个分区

设置页是配置的核心，按主题划分为五个分区：

| 分区 | 路径 | 负责内容 |
| --- | --- | --- |
| 账号 | `/settings/account` | 账号、密码、认证地址 `auth_url`、触发地址 `trigger_url`、运营商 `isp` |
| 网络监测 | `/settings/monitor` | 三种网络探针的开关与目标、检测间隔与超时、重试策略、暂停时段、登录前检测 |
| 浏览器 | `/settings/browser` | 浏览器选择、是否显示窗口（后台运行）、会话保持、反检测与高级参数 |
| 任务 | `/settings/tasks` | 任务总览、从文件 / 仓库导入、录制器、OCR 依赖安装与验证码测试 |
| 系统 | `/settings/system` | Python 运行环境、启动行为与开机自启、自动更新、网络 / 端口 / 代理、维护操作 |

各字段的默认值、取值范围与配置文件写法，统一收录在 [settings.json 配置参考](../6-reference/6.1-settings.md)。

## 仪表盘

- **顶部状态区**：显示当前生效的配置方案，以及网络状态——在线（`Online`）/ 被门户劫持（`CaptivePortal`）/ 离线（`Offline`）。
- **中央日志流**：通过 WebSocket 实时滚动，网络状态变化、登录步骤与失败原因都会即时打印。
- **登录按钮**：立即执行一次当前配置方案绑定的活跃任务，用于手动验证；失败时可在日志中查看错误摘要与失败截图。
- 当 Python 运行环境尚未就绪时，仪表盘会给出明确提示，并引导前往 **设置 → 系统** 修复。

## 配置方案页

- 列出全部配置方案，内置的 `default` 兜底方案不可删除，新用户直接编辑它即可完成首次配置。
- 每条方案支持 **编辑**（三段式编辑器：基本信息 / 网络匹配 / 认证设置）、**设为活跃**、**删除**。
- 页面顶部的 **自动切换** 开关开启后，程序按固定周期（默认 180 秒）探测当前网关与 Wi-Fi，自动选用最匹配的方案，多校区漫游时无需手动切换。
- 编辑器内提供 **检测当前网络** 按钮，可一键将当前网关 IP / Wi-Fi 名称填入匹配字段。

机制细节见 [配置方案概览](../2-profiles/2.1-overview.md) 与 [自动匹配网络](../2-profiles/2.2-match.md)。

## 任务管理页

- 统一展示浏览器任务、脚本任务与 Shell 任务，可按类型筛选。
- 单条任务支持 **执行**、**编辑**、**复制**、**删除**；页面顶部可新建任务、从文件导入、从仓库导入、调整排序、导入导出。
- **设为活跃** 仅对浏览器任务开放：配置方案绑定的「活跃任务」，即仪表盘点「登录」时实际执行的任务。

任务的编写方式见 [三类任务](../3-tasks/3.1-concepts.md) 与 [浏览器任务](../3-tasks/3.3-browser.md)；共享任务的下载方式见 [从仓库下载共享任务](../3-tasks/3.7-repo.md)。

## 调试面板

排查任务时最常用的工具：

- 进入单步调试后，可 **单步执行**、**连续执行**、**随时停止**，逐步查看每个步骤的输出与失败截图。
- **一键取证** 会将当前浏览器截图、页面快照（MHTML）与日志打包到 `debug/` 目录。反馈问题时附上该压缩包可显著提升定位效率。

操作流程见 [调试与取证](../3-tasks/3.6-debug.md)。

## 系统托盘

程序默认常驻系统托盘，提供启动 / 停止监测、打开控制台、退出等快捷菜单。各平台存在差异：

| 平台 | 托盘行为 |
| --- | --- |
| Windows | 完整支持；再次双击 exe 会直接打开控制台 |
| macOS | 受系统框架限制暂不支持托盘，轻量模式也会回落到完整模式 |
| Linux | 依赖 GTK3 / appindicator 运行库，无桌面环境时托盘不显示，可追加 `--no-tray` 启动 |
| 通用 | 可在 设置 → 系统 关闭「显示系统托盘」，或启动时追加 `--no-tray` |

开机自启可在 设置 → 系统 中开启，或执行 `campus-auth --autostart enable`（Windows 写入注册表启动项、macOS 创建 LaunchAgent、Linux 创建 XDG 自启项），详见 [CLI 与运行模式](../5-maintenance/5.2-cli.md)。
