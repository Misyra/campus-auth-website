# 快速开始

> 本章面向首次部署的用户，目标是在一台新设备上完成从零到“断网自动登录 + 开机自启”可用的完整配置。按顺序执行即可，无需预先通读全部文档。

## 0. 准备工作

- 准备校园网账号、密码及运营商信息（移动 / 联通 / 电信 / 校园网，部分院校无此项可留空）。
- 确认门户登录页地址：连接校园网后，浏览器自动弹出的登录页地址即为 `auth_url`；若为“访问任意 `http` 地址才跳转至登录页”的劫持型网络，需另行获取一个可触发跳转的明文 `http` 地址作为 `trigger_url`（详见 [重定向模式](../2-profiles/2.3-redirect.md)）。

## 1. 启动服务

```bash
campus-auth                          # 完整模式：Web 控制台 + 系统托盘 + Engine
# 端口被占用时自动递增，重试 5 次；如需固定端口：
campus-auth --port 50721 --host 127.0.0.1
# 查询 / 停止已有实例：
campus-auth --status
campus-auth --stop
```

Windows 系统下双击 `campus-auth.exe` 不显示控制台窗口；若已有实例正在运行，则直接在浏览器中打开 `http://127.0.0.1:50721`。首次访问进入初始化向导，后续所有配置均在 **设置** 中完成。

## 2. 配置方案：编辑默认项即可

首次启动后，程序自动生成 `default` 配置方案（系统内置兜底项，不可删除），无需新建。

打开 `http://127.0.0.1:50721`，进入侧边栏 **设置**，点击 `default` 的 **编辑** 按钮，填写认证地址与账号信息即可。如需支持多校区或多运营商，可点击 **新建配置方案** 另行创建。

| 字段 | 填写说明 | 常见错误 |
| --- | --- | --- |
| 名称 | 自定义，如“宿舍 / 教学楼” | — |
| 认证地址 `auth_url` | 浏览器中显示的登录页完整 URL | 填写为 JS 跳转后的中间态地址，或携带一次性 token 的链接 |
| 触发地址 `trigger_url` | 仅劫持型网络必填：如 `http://www.msftconnecttest.com/connecttest.txt` 等明文 `http` 地址 | 填写为 `https`（劫持场景下 TLS 握手直接失败，无法获取 `Captive` 状态） |
| 账号 / 密码 | 真实账号，落盘时自动加密为 `ENC:` 密文 | 使用测试账号 |
| 运营商 `isp` | 存在运营商下拉选项的院校必填（下拉支持“自定义”关键字输入） | 留空导致 `select` 步骤无法匹配选项 |
| 网关 IP / Wi-Fi 名称 | 点击编辑器内的 **检测当前网络** 一键填入，或手动填写；用于自动匹配配置方案 | 校区 A/B 共用同一配置方案，漫游后无法自动切换 |

> 重定向模式：`trigger_url` 非空即启用，任务中使用 `{{LOGIN_URL}}` 的既有任务将自动指向触发地址并跟随 `302` 跳转至真实门户，无需修改任务配置。

## 3. 浏览器设置：首次调试建议关闭后台运行

首次调试时，建议**关闭后台运行**，以便直观确认认证流程是否正确填入并提交。

**设置 → 浏览器** 中需关注的两项核心配置为：**后台运行**（`headless`，建议先关闭，待调试完成后再启用，便于观察执行过程）与 **浏览器选择**（默认 `msedge`，可选 `chromium` / `chrome` / `firefox` / `webkit`，支持指向本机已安装的浏览器）。其余视口、语言、会话等配置可保持默认值，完整参数说明见 [配置参考 · 浏览器](../6-reference/6.1-browser.md)。

## 4. 任务：优先使用录制器，手写为辅

### 使用录制器（无需手写 JSON）

1. 安装 Tampermonkey 浏览器扩展。
2. 进入 **设置 → 任务**，点击 **安装录制器脚本**。
3. 打开门户登录页，点击页面上的浮动按钮开始录制，按提示依次点击账号输入框、密码输入框、验证码及登录按钮。
4. 结束录制并保存 → 设为活跃任务（`POST /api/tasks/active/{id}`）→ 返回仪表盘点击 **登录** 进行验证。

### 手写 / 修改任务

浏览器任务文件位于 `tasks/browser/*.json`（`type=browser`），核心字段如下：

```json
{
  "name": "校园网登录",
  "url": "{{LOGIN_URL}}",
  "timeout": 30000,
  "navigation_wait": 1.0,
  "step_delay": 0.5,
  "variables": {},
  "success_condition": "login_success",
  "steps": [
    { "id": "fill_username", "type": "input", "selector": "#username", "value": "{{USERNAME}}" },
    { "id": "fill_password", "type": "input", "selector": "#password", "value": "{{PASSWORD}}" },
    { "id": "select_isp", "type": "select", "selector": "select[name='isp']", "value": "{{ISP}}", "required": false },
    { "id": "submit", "type": "click", "selector": "button[type='submit']" },
    { "id": "check_success", "type": "eval", "script": "() => document.body.innerText.includes('登录成功')", "store_as": "login_success" }
  ]
}
```

> - 劫持型网络中，`url` 字段建议使用 `{{LOGIN_URL}}`，避免硬编码真实门户地址；多页 SSO 场景可通过 `goto` / `navigate` 实现页面跳转。
> - 变量优先级：任务 `variables` < 系统变量 `USERNAME/PASSWORD/ISP/LOGIN_URL` < 前序步骤 `store_as` 的执行结果。
> - 全部 18 种步骤类型及字段说明，详见 [浏览器任务](../3-tasks/3.2-browser.md)。

## 5. 调试：失败时就地排查

| 场景 | 处理方式 |
| --- | --- |
| 任务未按预期执行 | **关闭后台运行后复现**：关闭后台运行后点击“执行指定任务”（`POST /api/tasks/{id}/execute`），观察是否正确触发按钮点击、是否存在 iframe 嵌套（需配置 `frame` 字段） |
| 单步定位 | 通过 `POST /api/debug/start` → `step` / `run_all` / `stop`，或在前端调试面板中逐步骤查看输出与失败截图 |
| 验证码识别失败 | 含 `ocr` 步骤的任务需先在 **设置 → 任务** 中安装 OCR 依赖（`ddddocr`，含推理依赖、体积约百 MB 级），安装完成后可通过“验证码识别”功能上传截图进行测试；`ocr` 步骤本身不重试，失败后由上层登录重试兜底 |
| 一键取证 | 通过 `POST /api/debug/capture` 打包截图、MHTML 快照与日志至 `debug/` 目录 |

**常见问题**：

- 选择器随门户改版失效——建议优先选用稳定的 `id` / `name` / `data-*` 属性，避免使用自动生成的长 class；动态页面可将 `navigation_wait` 调整至 `1.5–2.0` 秒，固定等待建议使用 `sleep`，避免使用无 `selector` 的 `wait`。
- 含 `eval` / `custom_js` 的任务在保存时将弹出安全确认对话框，确认脚本安全性后方可保存。

详见 [录制与调试](../3-tasks/3.5-debug.md)。

## 6. 配置自动执行

### 断网重连

**设置 → 网络监测**：默认仅启用 **204 门户检测**，其余探针按需启用。三种探针及登录前检测的详细说明见 [断网检测](../4-automation/4.1-monitor.md)，完整参数见 [配置参考 · 监测与重试](../6-reference/6.2-monitor.md)。

### 定时任务

通过定时任务页面（`/scheduled`）使用 cron 表达式关联既有任务（`browser` / `script` / `shell` 均可），例如 `0 8 * * *` 表示每日 8 时执行（格式为 **5 段**：`分 时 日 月 周`）。错过的轮次不会补跑；建议先通过手动执行验证任务稳定性，再配置为定时任务。

### 开机自启与长期运行

| 需求 | 配置方式 |
| --- | --- |
| 开机自启 | 执行 `campus-auth --autostart enable`（Windows 写入注册表 Run 键 / macOS 创建 LaunchAgent / Linux 创建 XDG autostart），或在控制台系统设置中启用“开机自启动” |
| 启动行为 | `app.startup_action`：`monitor`（启动后进入网络监测）/ `login_once`（启动后执行一次登录）/ `none`（不执行任何动作）；亦可通过 `campus-auth --startup-action monitor` 命令行参数覆盖 |
| 长期运行 | `app.auto_restart_hours` 默认 `24` 小时周期性自重启，以回收浏览器 / Worker 内存；`worker.keep_alive=false` 默认即用即还，`idle_timeout_seconds 300s` 空闲回收 |

## 7. 验证清单

```bash
curl http://127.0.0.1:50721/api/health
curl -H "X-Auth-Token: $(cat config/.auth_token)" http://127.0.0.1:50721/api/profiles
# 控制台核验：仪表盘日志是否正常输出登录结果、失败截图是否可访问、/ws/logs WebSocket 是否已连接
```

全部验证通过后，重新启用 **后台运行**，配置完成。后续调优可参阅 [断网检测](../4-automation/4.1-monitor.md)、[自动更新](../5-system/5.2-update.md)、[常见问题](../7-faq/7.1-troubleshoot.md) 及 [配置参考](../6-reference/6.1-browser.md)。
