# 自动匹配网络

开启自动切换后，程序周期性探测当前网关 IP 与 Wi-Fi 名称，从多条配置方案中选出与当前网络匹配的一条，实现跨校区、跨网络的无感切换。

## 开关与周期

- **位置**：配置方案 页（`/profiles`）顶部的 **自动切换** 开关（配置键 `auto_switch`）。
- **探测周期**：默认每 180 秒一次（配置键 `profile_check_interval`）。
- **关闭后的影响**：仅支持手动切换，自动登录与周期探测不再执行匹配；仪表盘手动登录与定时任务不受影响。

## 选中规则

匹配结果稳定且可预期，按以下优先级决定：

1. **匹配条件越多，优先级越高。** 同时填写网关 IP 与 Wi-Fi 名称（匹配强度 2）的配置方案，优先于仅填写一个条件（强度 1）的方案。
2. **强度相同时按配置方案 ID 字典序取最小。** 结果由「强度降序、ID 升序」的稳定排序得出，与创建顺序无关，不会出现不同时间选中不同方案的情况。
3. **均不匹配时回落到 `default`。** 兜底方案确保始终存在可用配置。
4. **删除当前配置方案后自动回落**，当前方案重置为 `default`。

> [!NOTE]
> 匹配失败不会报错，仅静默回落到 `default`。若 `default` 也未绑定活跃任务，自动登录会被跳过——这是「已开启自动却始终不登录」的常见原因。

## 匹配语义：精确相等

`gateway_ip` 与 `wifi_ssid` 均为**精确相等**匹配，不支持前缀、网段或通配符：

- 两个字段均填写：必须**同时**满足（AND）。
- 仅填写一个：满足该项即可。
- 两个字段均为空：该配置方案不参与自动匹配，只能手动切换。

> [!WARNING]
> 填写网段（如 `10.0.0.0/24`）或前缀会导致该配置方案永远无法匹配。不确定当前网络的网关 / SSID 时，请先连接目标 Wi-Fi，再点击编辑器中的 **检测当前网络** 一键填入。

## 切换时的行为

- **重置失败抑制状态**：切换配置方案后清空此前的登录失败去重计数，避免「网络已切换但仍被旧网络的失败状态抑制」而不触发登录。
- **手动与定时执行不受影响**：仪表盘手动登录、执行指定任务、定时任务均不依赖自动匹配；仅自动登录与周期探测遵循上述规则。

## 常见场景配置建议

| 场景 | 建议 |
| --- | --- |
| 双校区（本部 / 新校区） | 各建一条配置方案，分别填入与实测**完全一致**的网关 IP 或 Wi-Fi 名称，保持自动切换开启 |
| 同一网络下的双运营商 | 两条配置方案可填写相同匹配规则，用 `isp` 字段区分运营商，任务中的下拉步骤通过 `{{ISP}}` 取值 |
| 单一固定网络 | 匹配字段均留空，直接编辑 `default`，需要时手动切换 |
| 首次配置 | 先连接目标 Wi-Fi，点击 **检测当前网络**，核对填入值无误后再保存 |
