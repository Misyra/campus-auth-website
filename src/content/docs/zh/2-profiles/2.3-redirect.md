# 劫持门户（重定向模式）

部分校园网不直接提供登录页，而是**劫持客户端发起的任意明文 `http` 请求**，由网关返回 302 将客户端跳转至真正的门户登录页。此类网络称为劫持型门户（强制门户，Captive Portal），重定向模式即为这类网络设计。

**浏览器自动化渠道**下，只要满足任一条件即按重定向模式登录：`trigger_url` 非空，或 `auth_url` 留空——留空时程序自动打开内置触发地址、跟随 302 跳转至真实门户（v5.0.0 起的默认行为，这也是「认证地址」变为可选的原因）。配置入口位于 **方案 → 编辑 → 认证设置**。

## 先判断网络类型

| 网络类型 | 特征 | 配置方式 |
| --- | --- | --- |
| 直连型 | 门户登录页地址可直接打开 | 仅填写 `auth_url`，`trigger_url` 留空 |
| 劫持型 | 必须先访问任意 `http` 地址才会被 302 跳转至登录页；直接访问登录页可能无法打开 | 填写 `trigger_url`（明文 `http`），`auth_url` 可留空 |

> [!TIP]
> 拿不准时先点 **重定向检测**：程序会打开一个可见浏览器窗口，从默认触发地址出发跟随跳转，实测当前网络属于哪种类型。多数校园网经检测后**无需手工填写任何地址**。

## 配置方式

认证设置区自上而下（截图见 [新手上路](../1-getting-started/1.1-start.md) 第 2 步）：

1. **重定向检测**（按钮）：一次性实测工具。请先退出校园网登录态再点击，检测时会打开可见浏览器窗口跟随门户跳转，并给出是否需要手工填写认证地址的结论。
2. **认证地址（可选）**：检测成功时无需填写；程序默认打开内置触发地址并由浏览器跟随 302 跳转至真实门户。仅当自动跳转失败时才手工填写完整登录页 URL。
3. **重定向高级设置**（折叠）：劫持型网络需要更换触发地址时，在这里填写**自定义触发地址**（`trigger_url`）。

填写约束：

- **`trigger_url` 必须为明文 `http`。** 填写 `https` 会在劫持场景下直接导致 TLS 握手失败，程序无法取得「被劫持」判定，只会报告网络错误。
- 默认触发地址为 `http://www.msftconnecttest.com/connecttest.txt`（与 Windows 联网检测同源的明文页面），可按学校网络情况改写。
- 该模式下 `auth_url` 可留空。

## 开启后的运行时差异

| 行为 | 直连模式 | 重定向模式 |
| --- | --- | --- |
| `{{LOGIN_URL}}` 指向 | `auth_url` | `trigger_url`（即 `{{LOGIN_URL}}` 等同于 `{{TRIGGER_URL}}`） |
| 浏览器首次打开 | 直接打开 `auth_url` | 先打开 `trigger_url`，跟随 302 跳转至真实门户 |
| 已有任务 | 指向 `auth_url` | 凡是使用 `{{LOGIN_URL}}` 的任务**无需改动**，自动适配 |
| 网络检测 | 包含 `auth_url` 可达性检查 | 跳过认证地址探测 |
| 登录前预检 | 执行 `auth_url` 可达性预检 | 跳过预检 |
| 监测判定 | 常规三探针流程 | 「被劫持」判定优先于「离线」 |

## 常见问题

- **浏览器在触发页空转、步骤定位不到元素**：通常是 `trigger_url` 填写为 `https` 或地址不可达所致。改为明文 `http`，或更换触发地址后重试。
- **希望查看跳转过程**：调试时先在 设置 → 浏览器 关闭 **后台运行**，即可看到首次导航如何被 302 带至门户登录页。
