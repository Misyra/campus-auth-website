# 认证地址与重定向

部分校园网不直接提供登录页，而是**劫持客户端发起的任意明文 `http` 请求**，由网关返回 302 跳转至真正的门户登录页（强制门户，Captive Portal）。

v5.0.0 起**没有单独的「重定向模式」开关**，浏览器渠道只遵循一条规则：

> **认证地址填了直接用；留空则自动打开内置触发地址，跟随 302 重定向至真实门户。**

配置入口位于 **方案 → 编辑 → 认证设置**。

## 怎么填

| 认证地址填法 | 行为 | 适用 |
| --- | --- | --- |
| 留空（默认） | 自动访问内置触发地址，跟随 302 到真实门户 | 劫持型门户，以及拿不准的网络 |
| 填写完整登录页 URL | 直接打开该地址登录 | 直连型门户（登录页地址可直接打开） |

多数校园网**什么都不用填**。拿不准时先点 **重定向检测** 实测一次：

1. **先退出校园网登录态**；若程序预检发现当前已联网，会提示先退出再测。
2. 点击检测，程序在**独立临时会话**中打开可见浏览器，从触发地址出发跟随跳转，综合页面地址、表单结构与「校园网 / 登录 / 认证」等语义判断。
3. 识别到认证页会提示**无需填写认证地址**；未识别则提示重试或手动填写。检测全程不修改方案草稿。

## 重定向高级设置

默认折叠，**非特殊网络无需修改**：

- **自定义触发地址**（`trigger_url`）：仅在自动跳转失败时填写，**必须为明文 `http`**——填 `https` 在劫持场景下 TLS 握手直接失败，程序拿不到「被劫持」判定，只会报告网络错误。默认触发地址为 `http://www.msftconnecttest.com/connecttest.txt`（与 Windows 联网检测同源的明文页面），仅在运行时补入，不写回方案。
- **旧方案兼容**：v5.0.0 之前填过触发地址的方案继续按重定向运行（触发地址优先于认证地址）；此后手动填写认证地址时，前端会自动清除旧触发值，避免两个地址互相覆盖。

## 留空跟随重定向时的运行时行为

- `{{LOGIN_URL}}` 等同于触发地址，凡是使用它的既有任务**无需改动**，自动适配。
- 该规则仅对**浏览器自动化渠道**生效；直连请求渠道不使用触发地址，认证地址留空时 `{{AUTH_URL}}` 按空串替换。
- 网络监测时「被劫持」判定优先于「离线」，并跳过认证地址探测，见 [断网自动重连](../4-automation/4.1-monitor.md)。

## 常见问题

- **浏览器在触发页空转、步骤定位不到元素**：通常是自定义触发地址填了 `https` 或地址不可达所致，改为明文 `http` 或换一个触发地址。
- **想看跳转过程**：调试时在 设置 → 浏览器 关闭 **后台运行**，即可看到首次导航如何被 302 带至门户登录页。
