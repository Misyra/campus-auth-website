# 直连请求登录

如果校园网门户的登录动作只是一次可以复现的 HTTP 请求，可以在**方案**页的「登录方式」中选择**直连请求**，不启动 Python、Playwright 或浏览器即可完成认证。它适合没有验证码、表单字段稳定的门户；复杂页面仍应使用 [浏览器任务](../3-tasks/3.3-browser.md)，多步流程或需要自己写逻辑的门户用 [脚本登录](2.5-script-login.md)。

v5.1.0 起，直连的请求配置是一份**独立的「直连任务」**：方案只保留账号、密码、认证地址与「用哪个直连任务」这一个选择。这样同一门户的不同账号可以共用同一份请求配置，不必逐个抄一遍，也能把适配好的配置分享给别人。

## 先确认门户适合直连

1. 打开校园网登录页，按 <kbd>F12</kbd> 进入开发者工具的 **Network / 网络** 面板，并勾选 **Preserve log / 保留日志**。
2. 输入一次错误密码并提交，在请求列表中找到提交账号密码的请求。
3. 记录它的 **Request Method**、**Request URL**、POST 的 **Form Data** 以及必要的 `Referer` / `Content-Type` 请求头。

如果门户需要人工输入图形验证码、滑块或点选验证码，直连请求无法完成，请使用浏览器自动化。如果密码在请求中已经是十六进制或 Base64 等加密形式，仍可使用直连请求，见本文的「凭据变换脚本」。登录前要先从别的接口取一个令牌、或要在登录前先踢掉旧会话的门户，v5.1.0 起也能直连，见「前置请求与退出登录请求」。

## 新建与编辑直连任务

入口：**任务 → 直连任务 → 新建直连任务**（或点列表中任意一行进入编辑页）。编辑页分为「基本信息」「请求配置」「发送一次测试请求」三张卡片，其中请求配置按填写顺序分六组展开：

1. **填写门户的登录请求地址**：照抄浏览器看到的 `GET` / `POST` 与完整 URL，账号密码替换为占位符；
2. **补齐请求头与请求内容**：每行一项 `名称: 值` 的请求头，以及 POST 的 Form Data；
3. **告诉程序怎么判断登录成功**：成功关键字与失败关键字；
4. **凭据变换脚本（可选）**：密码需要加密时使用；
5. **前置请求（可选）**：登录前先取令牌；
6. **退出登录请求（可选）**：登录前先踢掉旧会话。

后三组默认折叠，配置过会显示「已配置」标记。

![直连任务编辑器：按填写顺序分组的请求配置](/screenshots/docs/16-http-login.avif)

编辑页顶部的「配置向导」（**直连登录配置向导**）按 **确认任务 → 填写请求 → 设定判定 → 发送测试** 四步引导，向导与编辑器编辑的是同一个任务，改动双向同步。**改动不需要点保存**：字段改完停手半秒自动落盘，页头状态字会显示「保存中… / 已保存 · 刚刚」，必填项没补齐时会提示「有 N 处待补全，改动暂未保存」并说明缺什么。

### 配置项速查

| 配置项 | 填写方式 |
| --- | --- |
| 方法 | 照抄浏览器看到的 `GET` 或 `POST` |
| 请求地址 | 填写完整 URL，将账号、密码替换为占位符 |
| 认证地址 | 直连任务自己的认证地址：**填了就用任务里的，留空则沿用方案里的认证地址**。本地自用不必填；要把任务分享给别人时建议填上，否则对方还得自己摸出认证页地址 |
| 请求头 | 每行一项，格式为 `名称: 值`；空行和不含冒号的行会被忽略 |
| 请求内容 | `POST` 的 Form Data，例如 `username={username}&password={password}` |
| 成功关键字 | 响应中表示认证成功的文本；留空时 HTTP 2xx 即视为成功 |
| 失败关键字 | 响应中表示账号或密码错误的文本，优先于成功关键字判断 |
| 凭据变换脚本 | 见下文「凭据变换脚本」 |
| 前置请求 / 退出登录请求 | 可选，见下文「前置请求与退出登录请求」 |
| HTTPS 证书 | 自签名 / 自建证书门户的容错策略：跟随全局设置（默认） / 忽略证书错误 / 严格校验证书 |

POST 填写请求内容但未写 `Content-Type` 时，程序会自动补 `application/x-www-form-urlencoded`；未配置 `User-Agent` 请求头时，程序会自动补一个 Chrome UA——部分门户的 WAF 会对缺失 UA 的请求直接返回 403。门户校验来源页时，可填写 `Referer: {auth_url}`。

## 占位符

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{username}` | 当前方案账号 | `20230001` |
| `{password}` | 当前方案密码，原样替换 | `secret123` |
| `{auth_url}` | 方案或直连任务中的认证地址 | `http://10.10.1.1/login` |
| `{local_ip}` | 本机主用网络接口 IPv4，取不到时为空 | `192.168.123.210` |
| `{local_mac}` | 本机主用接口 MAC，固定为小写冒号分隔 | `bc:38:98:39:ce:34` |
| `{任意脚本字段}` | 凭据变换脚本返回的字段 | 见下文 |
| `{前置请求取回的字段}` | 前置请求从响应中提取的字段，如 `{csrf_token}` | 见下文 |

值会**原样替换，不自动 URL 编码**。账号或密码含 `@`、`&`、`+`、空格等特殊字符时，请在凭据变换脚本中使用 `url_encode()`。写错的占位符会原样发出，测试结果中不应残留 `{` 字符。

`{local_mac}` 不会自动改成门户要求的格式。需要裸十六进制、大写或连字符格式时，在脚本中转换：

```javascript
function transform(ctx) {
  return {
    mac_plain: ctx.local_mac.replace(/:/g, ""),
    mac_upper: ctx.local_mac.toUpperCase(),
    mac_dash: ctx.local_mac.toUpperCase().replace(/:/g, "-"),
  };
}
```

## 前置请求与退出登录请求

这两组都是可选配置，不需要就整块留空。

### 前置请求：先取令牌再登录

有些门户的登录要带一个先从别的接口取回的令牌（典型是 CSRF token），而且这个令牌**绑定连接**——取令牌与提交登录必须落在同一条连接上，否则门户直接拒绝。填了「前置请求」后：

1. 程序先发这一次请求；
2. 按取值方式 `json:字段路径`（支持点号路径，如 `json:data.csrf_token`）从 JSON 响应中提取字段，占位符名默认取路径最后一段（也可在「名称」中自定义）；
3. 用**同一条连接**发送登录请求，登录请求的请求头 / 请求内容里以 `{csrf_token}` 这样的占位符引用它。

这一条把「先取令牌再提交」的两步式门户从"只能用浏览器方式"变成直连也能做。

### 退出登录请求：先踢掉旧会话

有些门户在你还"在线"的时候会拒绝再次登录（提示「IP 已在线 / 重复登录」）。填上门户的下线接口后，程序会在登录**之前**先请求一次把旧会话踢掉：

- 与登录请求共用同一条连接、同一套占位符（`{username}` 等）；
- 可设置「下线后等待」（0–30 秒），等旧会话失效再登录；
- 它排在所有事情最前面（先于读取登录页与凭据脚本）——旧会话还在时，这类门户的登录页会被重定向到「已在线」页，先清场再取值才对得上；
- **下线请求的成败不影响登录**：门户没开这个接口、地址写错，都只记一条日志，登录照常进行。

## 成功与失败判定

程序先检查失败关键字，再检查成功关键字：

| 响应情况 | 判定 |
| --- | --- |
| 命中失败关键字 | 凭据被拒绝，终态失败，不重试 |
| 未命中失败关键字且命中成功关键字 | 登录成功 |
| 成功关键字为空且 HTTP 状态为 2xx | 登录成功 |
| 其余情况 | 未命中成功标识，按可重试失败处理 |

许多 Dr.COM / eportal 接口无论成功还是密码错误都返回 HTTP 200，因此不要只依赖状态码；请同时填写成功和失败关键字，否则错误密码可能被误判为成功。

## 测试

直连任务可以在两个位置实测，按需选用：

- **任务编辑器里的「发送测试请求」**：任务里不含凭据（账号密码属于方案），因此手填一次「测试账号 / 测试密码」即可当场发一次真实请求。结果面板会回显实际发出的请求与响应（其中的账号、密码以及脚本产出的值都已替换为 `***`），并按结论给出针对性指引（例如「未命中成功标识」会提示核对成功关键字）；请求报文与响应片段收进折叠区，脚本报错单独高亮。
- **方案编辑器里的「发送测试请求」**：在 **方案 → 登录方式 → 直连请求** 选中直连任务后，可直接用方案已填的账号密码发一次测试——不保存、不改变自动登录状态。

两个位置的测试都只发送一次请求，同一时间只允许一个测试请求。测试结果会区分「请求判定成功」「门户拒绝凭据」「未命中成功标识」「请求未送达」和「配置或脚本错误」。

> [!TIP]
> 保存直连任务时，请求地址、请求头、请求内容与脚本会按**执行同口径**校验（含体积上限），超限直接报错，无需等到实际登录才发现。

测试通过后，回到 **方案 → 编辑 → 登录方式 → 直连请求**，在「直连任务」下拉中选中这个任务并**保存方案**。下拉首项是「未绑定（直连登录不可用）」，可随时把任务摘下来；直连**没有内置兜底任务**（门户地址因人而异，无法内置），未绑定就保存会被拒绝并当场提示。

## 复用与分享

- **多账号复用**：同一门户的多个方案（不同账号）可以绑定同一个直连任务，请求配置只维护一份，账号密码仍在各自的方案里。
- **任务导出**：在直连任务编辑页导出 JSON 文件发给同学；对方从「直连任务」Tab 导入即可，之后只需填自己的账号密码。导出内容不含凭据。从文件**导入**时，与已有任务同 ID 会直接覆盖更新。
- **任务仓库**：直连任务与浏览器任务在同一个任务仓库里**各有一份索引文件**（浏览器任务 `index.json`、直连任务 `index.http.json`，Gitee 镜像为 `index.gitee.json` / `index.http.gitee.json`），「直连任务」Tab 的仓库导入读的是直连那一份。
- **仓库导入即落盘**：从仓库导入会立即保存并当场打开该任务的编辑页（与已有任务撞 ID 时自动加后缀，不会覆盖）；导入后建议核对一遍请求地址与脚本再绑定使用。
- 分享时建议把任务里的「认证地址」填上，对方导入后不用再自己找认证页地址。

## 凭据变换脚本

门户提交的密码不是明文时，可定义一个纯计算脚本：

```javascript
function transform(ctx) {
  return { password: md5(ctx.password) };
}
```

脚本必须定义 `function transform(ctx)` 并返回对象。返回对象中的字符串、数字和布尔字段都可以作为占位符使用；与内置占位符同名时会覆盖内置值。

`ctx` 提供：`username`、`password`、`auth_url`、认证地址页面 HTML 的 `page`、`local_ip` 与 `local_mac`。可用函数包括 `md5`、`sha1`、`sha256`、`hmac_sha256`、`base64_encode`、`base64_decode`、`hex_encode`、`url_encode`、`now_ms`。脚本没有网络或文件访问能力，递归深度为 64，循环最多 100000 次，执行上限为 500 毫秒。

按本机 IP 推导密钥的门户可使用 `ctx.local_ip`：

```javascript
function keyOf(ip) {
  let k = 0;
  for (let i = 0; i < ip.length; i++) k ^= ip.charCodeAt(i);
  return k;
}

function enc(s, k) {
  let out = "";
  for (let i = 0; i < s.length; i++) {
    const h = (s.charCodeAt(i) ^ k).toString(16);
    out += h.length === 1 ? "0" + h : h;
  }
  return out;
}

function transform(ctx) {
  const k = keyOf(ctx.local_ip);
  return {
    account_enc: enc(",0," + ctx.username + "@cmcc", k),
    password_enc: enc(ctx.password, k),
    ip_enc: enc(ctx.local_ip, k),
  };
}
```

## 限制与安全提醒

- 一次登录**只提交一次登录请求**，外加最多两次可选的附加请求（前置请求取令牌、退出登录请求踢旧会话）；三次请求由同一个连接池顺序发出，因此「令牌绑连接」与「先踢旧会话再登录」的门户都能直连。直连**不携带 Cookie、不处理验证码**；需要多步交互、验证码或复杂跳转的门户，仍请使用浏览器方式。
- 单次请求超时 20 秒，最多跟随 5 次重定向，响应体最多读取 64 KiB。
- 保存直连任务时对请求地址、请求头、请求内容和脚本**全部按执行同口径校验**（体积上限分别为 8 KB / 64 KB / 256 KB / 8 KB / 128 KB），超限会在保存时直接报错，无需等到实际登录。
- 门户使用自签名证书且无法更换时，把「HTTPS 证书」切到「忽略证书错误」；该策略默认跟随全局浏览器设置。仅在可信内网使用，公网地址开启忽略校验存在中间人风险。
- GET 会把账号密码放入 URL，网关、代理和系统网络日志可能记录完整地址。能用 POST 时优先使用 POST。
- 认证结果确认成功后，程序仍会按登录后网络检测复核网络是否真正恢复。
