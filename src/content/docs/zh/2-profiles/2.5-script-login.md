# 脚本登录

如果门户的登录流程特殊到「直连请求表达不出来、又不想开浏览器」，可以把登录整个交给**你自己写的脚本**：在方案的「登录方式」里选**自定义脚本**，绑定一个脚本任务，程序负责起子进程、按退出码判定成败、再做一次登录后网络验证。它不启动浏览器与 Playwright，也不需要 Python Worker，适合愿意自己维护登录逻辑的用户。

## 什么时候用脚本渠道

先看两种更省事的方式能不能满足：

- 登录只是一次可复现的 HTTP 请求 → 用 [直连请求登录](2.4-http-login.md)；
- 门户有验证码、动态表单或复杂跳转 → 用 [浏览器任务](../3-tasks/3.3-browser.md)。

落在中间的门户才需要脚本，典型是：

- **登录前要先取一个令牌**，且令牌与连接绑定（取令牌与登录必须同一条 TCP 连接）；
- **密码按门户自己的算法加密**，而算法用直连的凭据变换脚本写不出来（需要读文件、装依赖、跑多步）；
- **要多步交互才能取到参数**（先访问 A 拿 sid、再访问 B 拿 challenge、最后提交）；
- **想直接复用你已有的登录脚本**（例如门户论坛里流传的那份 Python）。

> [!NOTE]
> 直连的凭据变换脚本跑在无网络、无文件的沙箱里，**发不出第二个请求**；这正是脚本渠道要补的那段空档。反过来，如果一次请求就能登录，脚本渠道只是把同一件事写得代码更多。

## 三步接上登录脚本

### 1. 建一个脚本任务

**任务 → 脚本 → 新建脚本**，填一个脚本 ID（落盘后不可改）、名称与内容：

| 设置 | 说明 |
| --- | --- |
| 执行程序 | 默认 **Python (项目内解释器)**，使用程序自带的 Python 环境（首次使用会自动准备并校验，**不会**安装 Playwright 浏览器）；也可指定下拉里的解释器、`.exe`，或包一层 `bat` / `shell` |
| 超时 | 单个脚本任务的超时，1~3600 秒，默认 60 秒；登录时用的就是这里的值 |
| 脚本内容 | 上限 100 KB；也可以留空，改用外部脚本文件（`script_path`） |

编辑器右侧的「立即运行」会在**不改动任何登录配置**的前提下就地跑一次，stdout 与 stderr 直接显示在结果面板——先把脚本本身调试通，再去接方案。

### 2. 在方案里选中它

**方案 → 编辑 → 登录方式 → 自定义脚本**，在「登录脚本」下拉里选中刚才那个脚本，然后**保存方案**：

![配置方案：登录方式的三张渠道卡与登录脚本下拉](/screenshots/docs/20-script-login.avif)

- **未绑定脚本任务时保存会被拒绝**（提示「请为脚本渠道选择一个脚本任务」）。脚本渠道**没有内置的兜底脚本**——登录逻辑只能由你维护，所以程序在保存时就拦下，而不是等你离开页面后看到一次「登录失败」。
- 账号与密码仍是方案字段，且对脚本渠道**同样必填**——它们是下文四个环境变量的唯一来源。
- 登录脚本属于**方案绑定的任务**：切换方案即切换脚本，多个网络可以用不同脚本。

### 3. 验证

先点任务页的「立即运行」确认脚本能跑（退出码 0），再回仪表盘点一次 **手动登录**。成败与耗时同时出现在**登录历史**里，消息里带着脚本输出的尾部。

## 脚本契约

### 凭据经环境变量下发

程序启动脚本时叠加四个环境变量：

| 变量 | 内容 |
| --- | --- |
| `CAMPUS_USERNAME` | 当前方案账号 |
| `CAMPUS_PASSWORD` | 当前方案密码（明文） |
| `CAMPUS_ISP` | 当前方案运营商，未填时为空串 |
| `CAMPUS_AUTH_URL` | 当前方案认证地址，未填时为空串 |

脚本任务**不做** `{{USERNAME}}` 这类模板替换（那是浏览器任务在 Worker 侧的特性），这四个变量是脚本唯一的凭据来源。变量一定存在，方案没填就是空串，所以不必写 `os.environ.get(...) or ""` 兜底。

除这四个变量外，脚本拿到的是**最小环境**：主进程的 Web 令牌、代理密码等都不会继承。

### 退出码决定成败

| 退出码 | 判定 | 后续 |
| --- | --- | --- |
| `0` | 本次尝试成功 | 程序再做一次**登录后网络验证**确认真的通了，通过才算登录成功 |
| 非 `0` | 本次尝试失败 | 按方案的重试策略重发，**重试预算耗尽才判终态失败** |
「脚本说成功」与「真的登上了」分开判定，是为了避免脚本漏判时把失败记成成功（与浏览器渠道同口径）。非 0 退出属于「可重试」，与直连未命中成功关键字同类——凭证写错也会按重试预算重发。

另外两类结局不走重试：**脚本超时**按可重试处理；**连进程都没起来**（脚本任务被删、扩展名不支持、解释器缺失）是配置问题，重试不会变好，直接终态失败并给出原因。

重试次数与间隔取自 **设置 → 检测** 的「最大重试次数」与「重试间隔」（默认 3 次、间隔逐次翻倍），方案本身不带独立预算。

### 输出会进登录历史

脚本的 stdout 与 stderr 会取**尾部 200 字符**、压成单行写进登录历史消息，其中**本次注入的密码会被抹成 `***`**。所以脚本打印含凭据的 URL 是安全的，但消息只留尾部——报错请写在脚本最后几行。脚本输出**不进日志页**，要看完整输出请用任务页的「立即运行」。

## 示例

```python
#!/usr/bin/env python3
import os
import sys

import requests

BASE = os.environ["CAMPUS_AUTH_URL"] or "http://10.0.0.1"
USER = os.environ["CAMPUS_USERNAME"]
PWD = os.environ["CAMPUS_PASSWORD"]
ISP = os.environ["CAMPUS_ISP"]

s = requests.Session()
# 第一步：取令牌（令牌与这条连接绑定，因此下面必须复用同一个 Session）
token = s.get(f"{BASE}/challenge", timeout=10).json()["token"]
# 第二步：带上令牌提交登录
resp = s.post(
    f"{BASE}/login",
    data={"user": USER, "pwd": PWD, "isp": ISP, "token": token},
    timeout=10,
)
body = resp.text

print(f"status={resp.status_code} body={body[:120]}")
if "登录成功" in body or '"result":1' in body:
    sys.exit(0)          # 本次成功，由程序的登录后网络验证最终确认
sys.exit(1)              # 本次失败，按重试预算重发
```

用 PowerShell 或批处理写也可以，只要**把退出码传出去**：

```powershell
# 执行程序选 powershell.exe，脚本内容如下
$body = @{ user = $env:CAMPUS_USERNAME; pwd = $env:CAMPUS_PASSWORD }
$r = Invoke-RestMethod -Uri "$env:CAMPUS_AUTH_URL/login" -Method Post -Body $body
if ($r.result -eq 1) { exit 0 } else { exit 1 }
```

## 与另两种渠道的分工

三条渠道**同一时间只有一条生效**（由方案的「登录方式」决定），都受同一套重试、抢占、取消与登录后网络验证约束：

| 渠道 | 适合谁 | 代价 |
| --- | --- | --- |
| **浏览器自动化** | 想开箱即用的小白用户与简单门户：不用写代码，验证码、动态表单、跳转都能过 | 资源占用最高，需要 Python 环境与浏览器（对内存占用敏感的用户不适合） |
| **直连请求** | 需要轻量运行：一次请求就能登录、表单字段稳定的门户 | 免 Python 与浏览器，最快最省资源；表达不出多步流程与验证码 |
| **自定义脚本** | 自己维护登录逻辑的用户：门户逻辑特殊，要用自己的解释器与库 | 登录逻辑要自己写、自己修；不启动浏览器与 Python Worker（脚本若用「项目内解释器」仍需 Python 环境，只是不装浏览器） |

> [!TIP]
> 拿不准就先试直连：在方案里选「直连请求」并点「发送测试请求」，成功即说明这个门户不需要脚本。测试失败也别急着写脚本，先看失败原因是「门户拒绝凭据」还是「请求形状不对」。

## 注意

- **退出码 0 之后仍有一次登录后网络验证**：脚本自称成功但网络没恢复时，本次登录最终仍记为失败——那说明脚本的判定过宽，请让它在失败时返回非 0。
- **脚本以本机用户权限运行**，能读写你的文件系统。请只使用你自己写的、或来源可信的脚本。
- **登录脚本不参与「定时任务」的自动登录**：定时任务调脚本是「跑一次辅助动作」，与登录渠道无关。要做登录请用方案的登录方式。
- 脚本渠道**不需要**在「设置 → 浏览器」里配置浏览器，也不会占用浏览器会话；长驻的登录脚本请自己控制超时，别依赖程序强杀。
- **改脚本即改登录方式**：脚本内容保存后立刻对下一次登录生效，与账号一样由你自己维护。
