# 调试与取证

任务无法按预期执行时，请按以下顺序使用本页的三项能力：**调试面板**逐步定位、**常见问题**快速命中、**一键取证**打包反馈。

## 调试面板

调试面板全局可用，是排查步骤问题的主阵地：

- 通过 `POST /api/debug/start` 进入单步模式（启动前会先检查运行环境，缺失时引导修复）。
- 支持 **单步执行（step）/ 连续执行（run_all）/ 停止（stop）**。
- 可查看每一步的输出与失败截图；截图经鉴权通道内联返回，不会暴露本机绝对路径。
- 建议先查看仪表盘日志与失败截图（保留天数受 `retention_days` 控制），再进入面板逐步骤定位。

调试接口一览：

| 接口 | 作用 |
| --- | --- |
| `POST /api/debug/start` | 启动调试会话 |
| `POST /api/debug/step` | 单步执行 |
| `POST /api/debug/run_all` | 连续执行剩余步骤 |
| `POST /api/debug/stop` | 停止调试 |
| `POST /api/debug/capture` | 一键打包截图、页面快照与日志到 `debug/` |

## 验证码 OCR

| 项目 | 说明 |
| --- | --- |
| 何时需要 | 仅含 `ocr` 步骤的任务需要 |
| 依赖 | `ddddocr`（含推理库，体积约百 MB 级），在 设置 → 任务 一键安装（底层通过 `uv add ddddocr`） |
| 管理位置 | 设置 → 任务 的 **OCR 依赖** 区，可安装 / 卸载，状态实时检测（含大小与重试） |
| 未安装的影响 | 不影响其他不含 OCR 的任务，仅 `ocr` 步骤会失败 |
| 验证方式 | 同页 **验证码识别** 可上传本地图片测试识别效果 |

## 常见问题

| 现象 | 排查建议 |
| --- | --- |
| 任务未按预期执行 | 先 **关闭后台运行** 再复现：观察是否真的点中按钮、是否存在 iframe 嵌套（需为步骤配置 `frame`） |
| 选择器失效 | 改用稳定的 `id` / `name` / `data-*`，必要时使用 `text="登录"`；避免使用自动生成的长 class |
| 动态页面元素尚未出现 | 将 `navigation_wait` 调整至 `1.5–2.0` 秒；固定等待使用 `sleep` |
| 验证码识别失败 | 确认 OCR 依赖已安装、`ocr` 的 `selector` 指向验证码**图片**（`target_selector` 才是输入框）；OCR 单次不重试，由整体登录重试重跑 |

更多「无法自动登录」的场景（网络探针、冷却、暂停时段等）见 [无法自动登录](../7-faq/7.1-login.md)。

## 一键取证

需要向作者反馈问题时，`POST /api/debug/capture` 会将浏览器截图、MHTML 页面快照与日志一并打包到 `debug/` 目录。附上该压缩包可显著提升定位效率。

- 实时日志走 `/ws/logs`，保留天数由 `retention_days` 控制（默认 7 天）。
- 反馈时请说明操作系统、安装方式（便携版 / Docker / 源码）、门户类型（直连 / 劫持）与复现步骤。
