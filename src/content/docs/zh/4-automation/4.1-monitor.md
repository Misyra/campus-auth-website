# 断网检测

由 `MonitorService` 通过三探针及登录前检测共同决定是否触发自动登录。**三探针中至少启用其一，自动触发方可生效**；否则仅支持通过仪表盘“登录”按钮或接口手动触发。

> 完整参数的默认值、取值范围及 `settings.json` 字段说明，详见 [配置参考 · 监测与重试](../6-reference/6.2-monitor.md)。

## 控制台位置

**设置 → 网络监测**（`/settings/monitor`）：

| 区域 | 说明 |
| --- | --- |
| 左侧 · 网络状态检测 | `TCP 检测` / `204 门户检测` / `URL 标题检测` 三探针的开关与目标配置 |
| 右侧 · 登录前检测 | `网卡连接检查` / `认证地址可达检查` / `监测不走代理` |
| 顶部 · 检测与重试 | 检测间隔、检测超时、最大重试次数、重试间隔、登录后延迟、暂停时段 |

## 三探针语义

| 探针 | 开关 | 默认 | 目标字段 | 判定 |
| --- | --- | --- | --- | --- |
| TCP | `tcp_enabled` | 关闭 | `tcp_targets`（逗号分隔，缺省端口默认为 `53`） | 任一目标连通即判定为在线 |
| HTTP 204 | `http_enabled` | **启用** | `http_targets`（`generate_204` 端点） | `204`=在线、`200`=被门户劫持（`Captive`），必须为明文 `http` |
| URL 标题 | `url_enabled` | 关闭 | `url_targets`（每行 `地址\|关键字`） + `url_expected_responses` 映射 | 标题包含关键字即判定为在线，否则判定为劫持 |

> **默认仅启用 204 探针**：`generate_204` 语义单一（204 / 200 二值）、主流厂商（小米 / 华为 / vivo）均提供该端点，且具备轻量、误判率低的特点。TCP 与 URL 探针可按需启用。

### 网络状态术语

Engine 对外仅暴露三种网络状态（源码枚举 `NetworkStatus`），日志与 WebSocket 推送均使用其英文值：

| 状态 | 枚举值 | 判定含义 |
| --- | --- | --- |
| 在线 | `Online` | 任一启用的探针判定网络可达 |
| 强制门户（劫持） | `CaptivePortal` | 204 探针返回 `200`，或 URL 探针未命中预期关键字；该判定**优先于**离线 |
| 离线 | `Offline` | 全部探针失败，且认证地址 `auth_url` 亦不可达 |

### 默认目标

| 探针 | 默认目标 |
| --- | --- |
| TCP | `8.8.8.8:53`、`114.114.114.114:53`、`www.baidu.com:443` |
| 204 | `http://connect.rom.miui.com/generate_204`、`http://connectivitycheck.platform.hicloud.com/generate_204`、`http://wifi.vivo.com.cn/generate_204` |
| URL | `http://captive.apple.com/hotspot-detect.html\|Success`、`http://detectportal.firefox.com/success.txt\|success`、`http://www.msftconnecttest.com/connecttest.txt\|Microsoft Connect Test` |

### 探针选择建议

| 场景 | 建议 |
| --- | --- |
| 大多数校园网环境 | 保持默认配置，仅启用 204 探针即可 |
| 需提升连通性判断灵敏度 | 额外启用 TCP 检测（开销最小） |
| 门户标题稳定、可作为特征 | 启用 URL 标题检测，按 `地址\|关键字` 配置 |
| 误判频繁 | 检查目标是否配置为普通网页（对 204 探针而言，普通网页恒返回 200，将被误判为“被劫持”而反复触发登录） |

## 登录前检测

`local_check_enabled`（网卡连接检查，默认启用）、`auth_url` 可达性预检（劫持型网络自动跳过）及 `disable_proxy`（监测不走代理，默认直连）三项，详见 [配置参考 · 监测与重试](../6-reference/6.2-monitor.md)。

## 超时、重试与暂停

`check_interval` / `post_login_delay` / `retry_settings` / `pause` / `profile_check_interval` / `disable_proxy` 等参数的默认值与取值范围，统一见 [配置参考 · 监测与重试](../6-reference/6.2-monitor.md)。

需注意两点：

- **实际检测间隔是自适应的**：`check_interval`（默认 `300` 秒）只是上限。网络在线时从 `30` 秒起指数放大并封顶于该值；一旦判定为 `CaptivePortal` / `Offline`，间隔立即收敛为固定 `30` 秒，因此断网后约半分钟内即可感知并重连。
- **连续失败会进入冷却**：同一会话内连续登录失败 `3` 次后暂停自动登录 `300` 秒，避免账号被门户临时封禁。若发现“识别到断网却不再重试”，通常是冷却生效，等待冷却结束或手动登录一次即可恢复。

## 与重定向模式的配合

- 劫持型网络（`trigger_url` 非空）跳过认证地址预检。
- `{{LOGIN_URL}}` 同步为触发地址（`{{LOGIN_URL}} == {{TRIGGER_URL}}`），Worker 首导航跟随 `302` 重定向至真实门户。
- URL 探针的 `Captive`（被劫持）判定优先于离线状态。

## 故障排查

- **检测未触发**：确认至少启用一种探针（默认仅 204 启用，误关闭后将无法自动触发）；检查暂停时段是否覆盖当前时间。
- **频繁误判为劫持**：检查 204 目标是否配置为普通网页（普通网页恒返回 200）；核对 URL 探针的关键字是否与实际标题一致。
