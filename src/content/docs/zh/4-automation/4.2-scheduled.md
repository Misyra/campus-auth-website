# 定时任务

定时任务让某个已有任务**按时间表自动执行**，适用于每日签到、定时保活等场景。它与掉线触发的自动登录是两套独立机制：前者依据时间，后者依据网络状态，互不干扰。

控制台入口为 **定时任务** 页（`/scheduled`），调度配置持久化在 `tasks/scheduled/{id}.json`。

## 创建步骤

1. 先在 **任务管理** 中创建并**手动调通**一个任务（浏览器任务 / 脚本任务 / Shell 任务均可）。
2. 进入 **定时任务** 页，选中该任务并填写 cron 表达式。
3. 建议先使用「执行指定任务」多次运行确认稳定，再挂载定时调度。

> [!NOTE]
> 定时任务本身不保存任务类型，类型由关联任务的 `target_id` 自动推导。因此修改目标任务后，定时配置无需同步改动。

## cron 表达式

使用标准 **5 段** 格式：`分 时 日 月 周`（不含秒、不含年）。程序内部会自动补全后交给 cron 解析器，按**运行机器的本地时区**计算。

| 表达式 | 含义 |
| --- | --- |
| `0 8 * * *` | 每天 08:00 |
| `30 7 * * 1-5` | 工作日 07:30 |
| `0 */2 * * *` | 每 2 小时一次 |
| `0 9,18 * * *` | 每天 09:00 与 18:00 各一次 |

> [!WARNING]
> 必须恰好 5 段。写成 6 段（带秒）会被拒绝并提示「期望 5 个字段」。

## 字段说明

配置文件为 `tasks/scheduled/{id}.json`：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `id` | 由文件名推导 | 不写入 JSON |
| `name` | `未命名定时任务` | 显示名称 |
| `description` | 空 | 描述 |
| `cron` | — | 5 段 cron 表达式 |
| `target_id` | — | 关联的任务 ID（三类任务均可） |
| `profile_id` | `null` | **预留字段，当前不生效**：定时执行统一走通用路径，不注入账号密码 |
| `timeout` | `null`（沿用全局 300 秒） | 单次执行超时秒数 |
| `enabled` | `true` | 是否启用该调度 |
| `last_run` / `last_result` | `null` | 上次执行时间与结果，重启不丢失 |

## 执行时机

- 到点执行关联任务，历史写入 `tasks/scheduled/history/{id}.json`。
- **错过不补跑**：关机或程序未运行时错过的时间点，重启后不会补执行，调度器从当前时间推算下一次触发。
- **暂停时段不影响定时任务**：网络监测的暂停时段仅静默监测与自动登录，定时任务照常触发。
- 仪表盘「登录」与手动执行仅用于验证，不受定时调度影响。
- 调度状态持久化在 `tasks/scheduled/`，重启不丢失。
