# 定时任务

定时任务让某个已有任务**自动执行**，适用于每日签到、定时保活等场景。它与掉线触发的自动登录是两套独立机制：前者依据时间或启动事件，后者依据网络状态，互不干扰。

控制台入口为 **任务 → 定时任务** 标签页（`/tasks/scheduled`），调度配置持久化在 `tasks/scheduled/{id}.json`，执行历史保存在 `tasks/scheduled/history/{id}.json`。

## 创建步骤

![新建定时任务：任务类型、触发方式与超时](/screenshots/docs/13-scheduled-new.avif)

1. 先在 **任务** 页创建并**手动调通**一个任务（浏览器任务或脚本任务均可）。
2. 进入 **任务 → 定时任务** 标签页，点击 **新建定时任务**。
3. 填写任务名称与描述（可选），选择**任务类型**（浏览器任务 / 脚本）并选定目标。
4. 选择**触发方式**并完成执行设置，点击 **保存**。

> [!NOTE]
> 定时任务本身不保存任务类型，类型由关联任务的 `target_id` 自动推导；修改目标任务后，定时配置无需同步改动。

## 两种触发方式

### 定时执行（每日固定时间）

选择每日的执行时间（如 `08:00`），程序到点自动执行，按**运行机器的本地时区**计算。

| 表达 | 含义 |
| --- | --- |
| `08:00` | 每天 08:00 执行 |
| `07:30` | 每天 07:30 执行 |

> [!IMPORTANT]
> 界面仅提供「每日 HH:MM」粒度。若手工编辑过配置文件、写入了任意 5 段 cron 表达式（如工作日 `30 7 * * 1-5`），程序仍能识别执行；但之后**一旦在界面中保存该任务**，非「每日固定时间」的表达式会被界面所选时间覆盖为每日执行。需要复杂调度时请直接维护配置文件，不要在界面中再保存。

### 启动后执行（v5.0.0 新增）

程序**每次启动**后自动执行一次目标任务，适合「开机顺手签到」类场景。可配置三项：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 每天最多成功 | 1 | 成功执行才计入次数，当日达到上限后自动跳过；跨天自动归零，重启不丢 |
| 失败重试 | 2 | 单轮失败后的重试次数，每次间隔 1 分钟 |
| 延迟执行（秒） | 30 | 启动后先等待再执行，便于网络就绪（0–86400 秒） |

典型用法：签到任务设为启动后执行、延迟 60 秒、每天最多成功 1 次——程序无论重启多少次，当天只会成功签一次。

## 字段说明

配置文件为 `tasks/scheduled/{id}.json`：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `id` | 由文件名推导 | 不写入 JSON |
| `name` | `未命名定时任务` | 显示名称 |
| `description` | 空 | 描述 |
| `trigger` | `cron` | 触发方式：`cron` 定时执行 / `startup` 启动后执行 |
| `cron` | — | 5 段 cron 表达式（`分 时 日 月 周`）；仅 `trigger=cron` 时生效，界面编辑会归一为每日时间 |
| `target_id` | — | 关联的任务 ID（浏览器任务或脚本任务） |
| `profile_id` | `null` | **预留字段，当前不生效**：定时执行统一走通用路径，不注入账号密码 |
| `timeout` | `null`（沿用全局 300 秒） | 单次执行超时秒数 |
| `enabled` | `true` | 是否启用该调度 |
| `max_runs_per_day` | `null`（沿用默认 1） | 启动触发：每日成功次数上限 |
| `max_retries` | `null`（沿用默认 2） | 启动触发：失败重试次数 |
| `startup_delay_secs` | `null`（沿用默认 30） | 启动触发：延迟执行秒数 |
| `last_run` / `last_result` | `null` | 上次执行时间与结果，重启不丢失 |

## 执行时机与历史

- 定时执行：到点触发；启动后执行：程序启动并延迟指定秒数后触发，当日成功次数用完后跳过。
- 每次执行的成败、时间、耗时与消息都会记录在任务的 **执行历史**（列表中点击查看），便于确认签到是否成功。
- **定时执行错过不补跑**：关机或程序未运行时错过的时间点，重启后不会补执行；启动后执行则天然「下次启动补上」。
- **暂停时段不影响定时任务**：网络检测的暂停时段仅静默监测与自动登录，定时任务照常触发。
- 仪表盘「手动登录」仅用于验证当前方案的登录，与定时调度无关。
