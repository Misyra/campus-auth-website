# 定时任务

定时任务让某个已有任务**自动执行**，适用于每日签到、定时保活等场景。它与掉线触发的自动登录是两套独立机制：前者依据时间或启动事件，后者依据网络状态，互不干扰。

控制台入口为 **任务 → 定时任务** 标签页（`/tasks/scheduled`），调度配置持久化在 `tasks/scheduled/{id}.json`，执行历史保存在 `tasks/scheduled/history/{id}.json`。

## 创建步骤

![定时任务编辑页：任务类型、触发方式与执行设置](/screenshots/docs/13-scheduled-new.avif)

1. 先在 **任务** 页创建并**手动调通**一个任务（浏览器任务或脚本任务均可）。
2. 进入 **任务 → 定时任务** 标签页，点 **新建定时任务** 后进入编辑页——与其他任务子页同一套交互，不再弹窗。
3. 填写任务名称与描述（可选），在「任务配置」中选择**任务类型**（浏览器任务 / 自定义脚本）并选定目标任务。
4. 在「执行设置」中选择**触发方式**（定时执行 / 启动后执行）并完成执行设置。
5. 名称与目标任务补齐后，改动停手半秒自动落盘（页头状态字提示保存进度），**没有保存按钮**；点面包屑「返回定时任务」回列表。

> [!NOTE]
> 名称与目标任务补齐前什么都不写，新建不会在磁盘上留下半成品。定时任务本身不保存任务类型，类型由关联任务的 `target_id` 自动推导；修改目标任务后，定时配置无需同步改动。定时任务只调度浏览器任务与脚本；直连任务的验证入口在其任务编辑器里。

## 两种触发方式

### 定时执行（每日固定时间）

选择每日的执行时间（如 `08:00`），程序到点自动执行，按**运行机器的本地时区**计算。

| 表达 | 含义 |
| --- | --- |
| `08:00` | 每天 08:00 执行 |
| `07:30` | 每天 07:30 执行 |

> [!IMPORTANT]
> 界面提供「每日 HH:MM」粒度。若手工编辑过配置文件、写入了任意 5 段 cron 表达式（如工作日 `30 7 * * 1-5`），程序仍能识别执行，编辑页也会明示「保存后将改为每日执行」。**只要不动「执行时间」控件**，改名称、目标等其他字段都不会改写调度；动了时间控件才按表单值改写为每日执行。需要复杂调度时请直接维护配置文件，不要在界面中改动执行时间。

### 启动后执行（v5.0.0 新增）

程序**每次启动**后自动执行一次目标任务，适合「开机顺手签到」类场景。可配置三项：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 每天最多成功 | 1 | 成功执行才计入次数，当日达到上限后自动跳过；跨天自动归零，重启不丢 |
| 失败重试 | 2 | 单轮失败后的重试次数，每次间隔 1 分钟 |
| 延迟执行（秒） | 30 | 启动后先等待再执行，便于网络就绪（0–86400 秒） |

典型用法：签到任务设为启动后执行、延迟 60 秒、每天最多成功 1 次——程序无论重启多少次，当天只会成功签一次。

## 字段说明

配置文件为 `tasks/scheduled/{id}.json`：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `id` | 由文件名推导 | 不写入 JSON |
| `name` | `未命名定时任务` | 显示名称 |
| `description` | 空 | 描述 |
| `trigger` | `cron` | 触发方式：`cron` 定时执行 / `startup` 启动后执行 |
| `cron` | — | 5 段 cron 表达式（`分 时 日 月 周`）；仅 `trigger=cron` 时生效。界面只写每日时间；手工写入的任意表达式只要不动界面的「执行时间」就不会被改写 |
| `target_id` | — | 关联的任务 ID（浏览器任务或脚本任务） |
| `profile_id` | `null` | **预留字段，当前不生效**：定时执行统一走通用路径，不注入账号密码 |
| `timeout` | `null`（沿用全局 300 秒） | 单次执行超时秒数 |
| `enabled` | `true` | 是否启用该调度 |
| `max_runs_per_day` | `null`（沿用默认 1） | 启动触发：每日成功次数上限 |
| `max_retries` | `null`（沿用默认 2） | 启动触发：失败重试次数 |
| `startup_delay_secs` | `null`（沿用默认 30） | 启动触发：延迟执行秒数 |
| `last_run` / `last_result` | `null` | 上次执行时间与结果，重启不丢失 |

## 执行时机与历史

- 定时执行：到点触发；启动后执行：程序启动并延迟指定秒数后触发，当日成功次数用完后跳过。
- 列表为一张表格（名称 / 类型 / 触发 / 目标 / 超时 / 最近结果 / 启用 / 操作），**目标直接显示任务名**——目标任务已被删除时当场标红「目标已不存在」；停用的任务整行淡显但「启用」开关保持可点，低频操作收进行尾 `⋯` 菜单。
- 编辑页侧栏会说明下一次执行：定时执行显示「下次执行」是今天还是明天，启动后执行显示今日已成功次数。
- 每次执行的成败、时间、耗时与消息都会记录在任务的 **执行历史**（编辑页侧栏或列表 `⋯` 菜单中查看），样式与仪表盘登录历史一致：状态图标 + 时间 / 耗时 / 结果的纵向信息列，成功绿色、失败红色。
- 列表或编辑页中手动点「运行」只表示**已触发执行**（提示「已触发执行，结果见执行历史」），成败以后续的执行历史为准。
- **定时执行错过不补跑**：关机或程序未运行时错过的时间点，重启后不会补执行；启动后执行则天然「下次启动补上」。
- **暂停时段不影响定时任务**：网络检测的暂停时段仅静默监测与自动登录，定时任务照常触发。
- 仪表盘「手动登录」仅用于验证当前方案的登录，与定时调度无关。
