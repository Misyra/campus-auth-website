# 定时任务

定时任务是对既有任务的 cron 调度视图（控制台 **定时任务** 页面 `/scheduled`，源码 `src/scheduler`），调度状态持久化于 `tasks/scheduled/{id}.json`。它与断网触发的自动登录彼此独立：前者按时间触发，后者按网络状态触发。

## 创建与管理

1. 在 **任务管理** 中创建并调通一个任务（`browser` / `script` / `shell` 均可）。
2. 进入 **定时任务** 页面，选择该任务并填写 cron 表达式。
3. 建议先用“执行指定任务”（`POST /api/tasks/{id}/execute`）手动验证稳定性，再挂载定时调度。

> 定时任务本身不存储任务类型：类型由关联任务 `target_id` 经 `TaskKind` 推导，因此修改目标任务无需同步改动定时配置。

## cron 表达式

格式为 **5 段**：`分 时 日 月 周`（不含秒与年）。程序内部自动补全为 `0 {5段} *` 后交给 cron 解析器。

| 示例 | 说明 |
| --- | --- |
| `0 8 * * *` | 每日 8:00 执行 |
| `30 7 * * 1-5` | 工作日 7:30 执行 |
| `0 */2 * * *` | 每 2 小时执行一次 |
| `0 9,18 * * *` | 每日 9:00 与 18:00 各执行一次 |

> 段数必须为 5，填写 6 段（含秒）会被直接拒绝并提示“期望 5 个字段”。执行时间按**运行机器的本地时区**计算。

## 字段说明（`tasks/scheduled/{id}.json`）

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `id` | 文件名推导 | 由文件名派生，**不写入 JSON** |
| `name` | `未命名定时任务` | 显示名称 |
| `description` | 空 | 任务描述 |
| `cron` | — | 5 段 cron 表达式 |
| `target_id` | — | 关联的任务 ID（`browser` / `script` / `shell` 均可） |
| `profile_id` | `null` | **预留字段，当前不生效**：定时任务统一走通用执行（打卡），不注入账号密码 |
| `timeout` | `null`（沿用全局默认 `300` 秒） | 单次执行超时秒数 |
| `enabled` | `true` | 是否启用该调度 |
| `last_run` / `last_result` | `null` | 上次执行时间与结果，重启后不丢失 |

## 执行时机

- 到达 cron 触发点时执行关联任务；执行历史写入 `tasks/scheduled/history/{id}.json`。
- **错过的轮次不补跑**：关机或程序未运行时到点的任务不会在重启后重放，调度器从当前时间推算下一个触发点。
- **暂停时段不影响定时任务**：`global.pause` 仅静默网络监测与自动登录，定时任务照常触发。
- 仪表盘“登录”与 `POST /api/tasks/{id}/execute` 为手动触发，仅用于验证，不受定时调度影响。
- 调度状态持久化于 `tasks/scheduled/`，重启后不丢失。
