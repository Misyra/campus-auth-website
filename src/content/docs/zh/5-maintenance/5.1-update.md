# 自动更新

认证喵（Campus-Auth）内置版本检查与自更新能力。本页面说明更新通道、检查频率、代理设置与常见问题。

## 操作入口

更新相关操作集中在 **设置 → 网络与更新**（`/settings/network`）的「自动更新」区块：总开关、检查频率、更新通道、上次检查时间、**立即检查**、手动选择安装包。发现新版本时，界面与系统通知会给出更新提示，按引导确认后由后台完成下载与替换。

![网络与更新设置：自动检查、更新通道与手动选择安装包](/screenshots/docs/10-settings-update.avif)

## 三种更新通道

| 通道 | 配置值 | 跟随的版本 |
| --- | --- | --- |
| 正式版 | `stable` | 仅跟随稳定发布 |
| 测试版 | `prerelease` | 仅跟随 alpha / beta 等预发布版本 |
| 全通道最新 | `all` | 正式版与预发布版一并纳入，按版本号取最高 |

希望第一时间体验新功能，可选择测试版或全通道最新；追求稳定请选择正式版。切换通道后手动点击一次「立即检查」即可生效。

## 检查频率与开关

| 配置项 | 字段 | 说明 |
| --- | --- | --- |
| 总开关 | `updater.auto_check_enabled` | 关闭后后台检查与启动检查均静默，仅保留手动「立即检查」；运行时改回无需重启 |
| 启动检查 | `updater.check_on_startup` | 每次启动时是否**立即检查一次**，无论检查间隔取何值都生效；无界面开关，仅 settings.json（默认开） |
| 检查间隔 | `updater.check_interval_hours` | 界面显示为「每次启动 / 每天 / 每周」，对应 `0 / 24 / 168`；非标准存量值在展示时自动归一 |
| 检查结果落盘 | `update/last_check.json` | 每次检查无论成败均刷新（时间、是否有更新、最新版本、错误信息） |

## 下载代理设置

国内网络访问 GitHub 受限时，常需为更新下载单独配置代理：

| 配置项 | 字段 | 说明 |
| --- | --- | --- |
| 代理开关 | `updater.use_proxy` | 是否使用显式代理下载 |
| 代理地址 | `updater.proxy_url` | 如 `http://127.0.0.1:7890`，支持非本机代理 |
| 兼容字段 | `updater.proxy_port` | 旧版「本地代理端口」，仅用于兼容读取，新配置统一写入 `proxy_url` |

代理地址解析顺序：`proxy_url` 非空时优先；否则回退到由 `proxy_port` 拼出的 `http://127.0.0.1:{port}`；两者均为空时跟随系统代理。

> [!NOTE]
> 更新代理同时作用于**程序更新与任务仓库下载**；网络检测流量是否走代理由 设置 → 检测 的「检测不走代理」单独控制，两者互不影响。详见 [从仓库下载共享任务](../3-tasks/3.7-repo.md)。

更新产物先下载到 `update/staging/`，下载完成后比对 `.sha256` 校验，最终的文件自替换由 `campus-auth-helper` 完成。

## 手动更新（下载慢的替代方案）

自动下载受网络限制时，v5.0.0 起提供两条手动路径，均在 设置 → 网络与更新：

1. **放入 `update/` 目录**：从 [GitHub Releases](https://github.com/Misyra/Campus-Auth-rs/releases) 自行下载与本机平台匹配的安装包，放入程序目录下的 `update/` 文件夹。更新时检测到本地已有对应包会**自动跳过下载**，直接进入校验与替换。
2. **手动选择安装包**：点击 **选择安装包**，从本地挑选一个已下载好的发布包直接安装，完全不联网下载。支持 `.zip` / `.tar.gz` / `.tgz`，上限 512 MB；**所选包的版本必须高于当前版本**，否则会被拒绝。适合下载慢、或使用自编译 / 镜像包的场景。

两条路径最终都复用同一套 `.sha256` 校验与 `campus-auth-helper` 替换流程，安全性一致。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 代理环境下下载失败 | 在 设置 → 网络与更新 的网络 / 代理处填写可用代理（如 `http://127.0.0.1:7890`）；留空则跟随系统代理 |
| 需要查看上次检查结果 | 「关于」页与系统设置中的「上次检查时间 / 错误提示」均来自 `update/last_check.json` |
| 切换通道后没有变化 | 切换通道后手动点击一次「立即检查」 |
