# CLI 与运行模式

本页面汇总命令行参数、运行模式与程序在磁盘上生成的目录结构。主程序为 `campus-auth`（Windows 下为 `campus-auth.exe`）；同目录的 `campus-auth-helper` 用于自动更新时的文件自替换，无需手动调用。

## 三种运行模式

| 模式 | 命令 | 说明 |
| --- | --- | --- |
| 完整（默认） | `campus-auth` | Web 控制台 + 系统托盘 + 监测引擎，全功能运行 |
| 轻量 | `campus-auth --mode lightweight` | 仅运行引擎与托盘，Web 控制台按需唤起（macOS 因不支持托盘会自动回落到完整模式） |
| 单次执行 | `campus-auth --mode login-once` | 执行一次活跃登录任务后退出，适合写入脚本或系统计划任务 |

> [!NOTE]
> 程序同时仅运行一份实例。再次执行启动命令不会开启第二个进程，而是直接在浏览器打开已有实例的控制台。单实例由 `config/.lock` 排他锁保证，进程退出时由系统自动释放，无需手动清理。

## 常用命令行参数

```bash
# 指定端口 / 监听地址 / 数据目录
# 等价环境变量：CAMPUS_AUTH_PORT / CAMPUS_AUTH_HOST / CAMPUS_AUTH_BASE_PATH
campus-auth --port 50721 --host 127.0.0.1 --base-path /data/campus-auth

# 实例管理
campus-auth --status          # 查看运行实例的 PID / 端口 / 存活状态
campus-auth --stop            # 停止运行中的实例
campus-auth --force           # 残留进程占用时，终止旧实例后重新启动（带 PID 复用防护）

# 开机自启（也可在 设置 → 系统 中开关）
campus-auth --autostart enable
campus-auth --autostart disable

# 启动时不自动打开浏览器 / 不显示托盘
campus-auth --no-browser
campus-auth --no-tray

# 覆盖「启动后执行」动作
campus-auth --startup-action monitor      # 启动后进入网络监测（默认）
campus-auth --startup-action login_once   # 启动后先登录一次
campus-auth --startup-action none         # 启动后不自动执行任何动作
```

完整参数可执行 `campus-auth --help` 查看（定义见 `src/launcher.rs`）。Windows 下从终端启动时，日志会输出到当前控制台。

## 运行时目录结构

默认数据根目录（`base_path`）即可执行文件所在目录，可通过 `--base-path` 或环境变量 `CAMPUS_AUTH_BASE_PATH` 改至其他位置：

```text
<base_path>/
├── config/                  # settings.json、profiles/*.json、.auth_token（权限 0600）
│                            # 以及 .lock（实例锁）、.instance（PID+端口）、.runtime_port
├── tasks/                   # 浏览器 / 脚本 / 定时任务（scheduled/ 与 history/）
├── logs/                    # 按天归档的日志（保留天数受 retention_days 控制）
├── environment/             # uv / .venv / Playwright 浏览器（按需下载）
├── update/                  # last_check.json 与 staging/（更新产物）
└── debug/                   # 一键取证的打包产物
```

- `settings.json` 当前为 v6 结构，由 `config_version` 驱动自动迁移；写入采用「临时文件中转 + 原子替换」，文件损坏时先备份为 `settings.corrupt.*` 而非直接覆盖。
- 账号密码以 `ENC:` 前缀的 AES-256-GCM 密文保存，内存中及时清零。
- 每条配置方案独立存为 `config/profiles/{id}.json`，删除时移入 `.trash` 安全回收站。

完整目录与字段说明见 [目录与文件](5.3-files.md)。

## 鉴权与端口

| 项目 | 说明 |
| --- | --- |
| 访问令牌 | 启动时生成 `config/.auth_token`（权限 `0600`），前端获取后通过 `X-Auth-Token` / `Authorization: Bearer` / `?token=` 携带 |
| 免鉴权端点 | `GET /api/health`、`GET /api/system/info`、`GET /api/monitor/status`、`/api/background/*`、`/api/debug/screenshot/*`、`/api/ai/capture/screenshot`、`GET /api/tools/task-recorder.user.js`、`/api/docs/*` |
| 默认端口 | `127.0.0.1:50721`，被占用时自动递增、最多重试 5 次；Docker 下默认 `0.0.0.0:50721` |
| 轻量模式 | `.instance` 初始记录哨兵端口 `0`，控制台首次被唤起后回写真实端口 |

## 日志与可清理项

| 项目 | 说明 |
| --- | --- |
| 日志保留 | `logging.retention_days` 默认 7 天；是否写文件与日志级别可在 设置 → 系统 热更新，无需重启 |
| 日志级别 | `TRACE / DEBUG / INFO / WARN / ERROR`，不支持 `OFF`（写入会回退为 `INFO`）；需要完全静默请关闭「写入文件」 |
| 实时推送 | `/ws/logs`（日志）、`/ws/status`（网络状态） |
| 可安全删除（会自动重建） | `python_worker/.venv`（约 100 MB+，按需重建）、`logs/` 旧归档、`update/staging/`、`debug/` 打包产物 |

> [!WARNING]
> `settings.json`、`profiles/*.json`、`.auth_token` 包含关键配置与凭据，**请勿随意删除**。
