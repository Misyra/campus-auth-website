# CLI 与运行模式

本页面汇总命令行参数、运行模式与程序在磁盘上生成的目录结构。主程序为 `campus-auth`（Windows 下为 `campus-auth.exe`）；同目录的 `campus-auth-helper` 仅用于自动更新时的文件替换，无需手动调用。

## 三种运行模式

| 模式 | 命令 | 说明 |
| --- | --- | --- |
| 完整（默认） | `campus-auth` | Web 控制台 + 系统托盘 + 监测引擎 |
| 轻量 | `campus-auth --mode lightweight` | 仅运行引擎与托盘，Web 控制台按需唤起；macOS 不支持托盘时自动回落完整模式 |
| 单次登录 | `campus-auth --mode login-once` | 按当前方案的登录方式（浏览器任务、直连请求或脚本登录）执行一次登录后退出 |

程序同时只运行一个实例。完整模式下再次执行启动命令不会开启第二个进程，而是打开已运行实例的控制台（需未关闭「自动打开浏览器」；轻量模式无 Web 入口，重复启动会提示已有实例在运行）。

## 常用命令

```bash
campus-auth --status          # 查看运行实例的 PID / 端口
campus-auth --stop            # 停止运行中的实例
campus-auth --force           # 终止旧实例后启动

campus-auth --autostart enable
campus-auth --autostart disable

campus-auth --port 50721 --host 127.0.0.1 --base-path /data/campus-auth
campus-auth --no-browser       # 启动后不自动打开控制台
campus-auth --no-tray          # 不显示系统托盘

campus-auth --startup-action monitor      # 启动后开始网络检测
campus-auth --startup-action login_once   # 启动后登录一次
campus-auth --startup-action none         # 启动后不执行动作
```

`--port`、`--host`、`--base-path` 分别对应环境变量 `CAMPUS_AUTH_PORT`、`CAMPUS_AUTH_HOST`、`CAMPUS_AUTH_BASE_PATH`。完整参数以 `campus-auth --help` 为准。

## 运行模式预设

控制台 **设置 → 系统 → 运行模式** 提供「默认」和「调试」预设。默认模式适合长期运行：后台运行、INFO 日志、开机自启和暂停时段均开启；调试模式关闭后台运行、提高日志级别、保持浏览器进程并关闭暂停时段，便于手动复现。修改任一项后会显示为「自定义」。

暂停时段的起止时间不会被预设覆盖。新配置的默认暂停时段为 `23:00–06:00`，已有配置保留原值。

## 启动默认值

新配置的 `startup_action` 默认为 `none`，程序启动后待命、不自动开始检测；`auto_switch` 默认为 `false`，方案不会自动切换。需要无人值守的「启动即守护」时，把启动动作改为 `monitor`（控制台 设置 → 系统，或启动参数 `--startup-action monitor`）。升级已有配置时，已保存的值不会被新默认值覆盖。

## 运行时目录结构

默认数据根目录（`base_path`）为可执行文件所在目录，可通过 `--base-path` 或 `CAMPUS_AUTH_BASE_PATH` 覆盖：

```text
<base_path>/
├── config/
│   ├── settings.json          # 全局配置，当前 v9 schema
│   ├── profiles/*.json        # 方案、凭据与登录方式
│   ├── .auth_token            # Web 访问令牌
│   └── llm.json               # AI 服务商配置（密钥加密保存）
├── tasks/
│   ├── browser/               # 浏览器任务
│   ├── scripts/               # 脚本任务
│   └── scheduled/             # 定时配置与历史
├── logs/login_history/        # 日志与登录历史
├── environment/               # uv 与 Python 运行时状态
├── python_worker/
│   ├── .venv/                 # Python 虚拟环境
│   ├── captures/               # AI 页面捕获结果
│   └── debug/                  # 调试快照
└── update/                    # 检查记录与更新暂存
```

浏览器任务使用的 Playwright 浏览器位于各平台默认缓存目录；Docker 镜像会将其放在镜像内的 `/ms-playwright`。`settings.json` 当前为 v9，低版本配置会由 `config_version` 驱动迁移；密码以 `ENC:` 前缀的 AES-256-GCM 密文保存。

## 鉴权与端口

| 项目 | 说明 |
| --- | --- |
| 访问令牌 | 启动时生成 `config/.auth_token`，前端通过 `X-Auth-Token` / `Authorization: Bearer` / `?token=` 携带 |
| 默认端口 | `127.0.0.1:50721`，仅回环地址在端口占用或 Windows 保留端口时改由系统随机分配；非回环地址无法自动改绑 |
| 实际端口 | 以 `campus-auth --status`、启动日志或 `config/.runtime_port` 为准 |
| Docker | 默认监听容器内 `0.0.0.0:50721`，请勿直接暴露到公网 |

## 日志与可清理项

| 项目 | 说明 |
| --- | --- |
| 日志保留 | `logging.retention_days` 默认 7 天，设置页可热更新 |
| 实时推送 | `/ws/logs`（日志与网络状态事件，仅此一个 WebSocket 端点） |
| 可安全删除 | `python_worker/.venv`、`logs/` 旧归档、`update/staging/`、`python_worker/debug/` |

删除 `.venv` 后，浏览器任务下次运行会按需重新准备 Python 环境；直连请求登录不依赖该环境。
