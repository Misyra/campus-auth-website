# 监测与重试

> 对应 `src/config/schema.rs::MonitorSettings` / `PauseSettings` / `RetrySettings`，控制台路径 **设置 → 网络监测**（`/settings/monitor`）。所有字段持久化于 `settings.json → global.monitor` / `global.pause` / `global.retry_settings`。

## 网络状态检测（三探针）

三种探针独立开关，至少启用其一方可触发自动登录。默认仅启用 204 探针。

| 探针 | 开关字段 | 默认 | 目标字段 | 默认目标 | 判定 |
| --- | --- | --- | --- | --- | --- |
| TCP 检测 | `tcp_enabled` | 关闭 | `tcp_targets`（逗号分隔，缺省端口默认为 `53`） | `8.8.8.8:53`、`114.114.114.114:53`、`www.baidu.com:443` | 任一目标连通即判定为在线 |
| 204 门户检测 | `http_enabled` | **启用** | `http_targets`（`generate_204` 端点） | `http://connect.rom.miui.com/generate_204`、`http://connectivitycheck.platform.hicloud.com/generate_204`、`http://wifi.vivo.com.cn/generate_204` | `204`=在线、`200`=被门户劫持（`Captive`），必须为明文 `http` |
| URL 标题检测 | `url_enabled` | 关闭 | `url_targets` + `url_expected_responses`（`URL → 关键字` 映射） | `http://captive.apple.com/hotspot-detect.html\|Success`、`http://detectportal.firefox.com/success.txt\|success`、`http://www.msftconnecttest.com/connecttest.txt\|Microsoft Connect Test` | 标题包含关键字即判定为在线 |

### 204 探针为何必须使用明文 http

`generate_204` 端点的语义为二值判定：`204`=在线、`200`=被门户劫持。`https` 在劫持场景下 TLS 握手直接失败，Engine 仅返回网络错误而非 `Captive` 判定；唯有明文 `http` 方可收到 `200` 响应作为劫持证据。

### 配置错误示例

- 204 目标配置为普通网页 → 普通网页恒返回 `200`，将被误判为“被劫持”，导致反复触发登录。
- URL 探针的关键字与实际标题不一致 → 恒判为劫持或恒判为在线。

## 登录前检测

| 开关 | 字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| 网卡连接检查 | `local_check_enabled` | 启用 | 物理网卡全部断开时直接判定为离线，跳过外网探测与登录流程 |
| 认证地址可达检查 | `auth_url` 可达性预检 | — | 登录前确认 `auth_url` 可达，不可达则跳过本次登录；劫持型网络（`trigger_url` 非空）自动跳过 |
| 监测不走代理 | `disable_proxy` | `true`（直连） | 启用时检测流量直连，不经过系统代理；关闭后跟随系统代理（重启后生效）。仅影响检测流程，不影响更新与任务仓库的代理 |

## 超时与间隔

| 参数 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 检测间隔 | `check_interval` | `300` 秒 | 网络平稳时两次检测之间的**上限**；实际间隔为自适应值，见下方“自适应探测节奏” |
| TCP 超时 | `tcp_timeout` | `2` 秒 | 单次 TCP 探测的等待上限 |
| HTTP 超时 | `http_timeout` | `10` 秒 | 单次 204 探测的等待上限 |
| URL 超时 | `url_timeout` | `10` 秒 | 单次标题探测的等待上限 |
| 认证地址超时 | `auth_url_timeout` | `5` 秒 | 登录前 `auth_url` 可达性检查的超时时间 |
| 登录后延迟 | `post_login_delay` | `5` 秒（`0…60`） | 登录完成后等待门户生效再复查网络 |
| 配置方案切换间隔 | `profile_check_interval` | `180` 秒 | 自动切换配置方案的检测周期（`auto_switch` 启用时） |

## 重试策略

> 对应 `global.retry_settings`，位于 **设置 → 网络监测** 的“检测与重试”区域。

| 参数 | 字段 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 最大重试次数 | `retry_settings.max_retries` | `3` 次 | 单次会话内登录失败后的最大重试次数 |
| 重试间隔 | `retry_settings.retry_interval` | `5` 秒 | 首次重试间隔，之后按指数退避 `5 → 10 → 20` 秒；间隔过短可能触发登录页限流 |
| 登录冷却 | 常量（`COOLING_DOWN_THRESHOLD` / `COOLING_DOWN_DURATION_SECS`） | 连续失败 `3` 次后冷却 `300` 秒 | 冷却期内不再尝试自动登录，避免账号被门户临时封禁；冷却结束后自动恢复，无需重启 |

### 自适应探测节奏

`check_interval` 是间隔**上限**而非固定值，Engine 按网络状态动态调整实际检测间隔：

| 网络状态 | 实际间隔 |
| --- | --- |
| 在线（`Online`） | 从 `30` 秒起指数放大（`30 → 60 → 120 → …`），最大不超过 `check_interval` |
| 异常（`CaptivePortal` / `Offline`） | 固定 `30` 秒，与 `check_interval` 无关 |

即：断网后最快约 30 秒内感知并重连，无需等待一个完整的 `check_interval`；网络持续在线时逐步拉长间隔以降低开销。

> 需要立刻验证网络状态时，可在控制台点击“立即检测”（`POST /api/monitor/test`，后台执行，30 秒超时），无需等待下一轮探测。

## 暂停时段

> 对应 `global.pause`，支持跨天配置（如 `22:00 → 06:00` 表示每晚 22 时至次日 6 时暂停检测与登录）。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否启用暂停时段 |
| `start_hour` / `start_minute` | `0 / 0` | 开始时间 |
| `end_hour` / `end_minute` | `0 / 0` | 结束时间 |

> 暂停时段内，监测与自动登录完全静默，仅支持手动登录与定时任务。

## 完整配置示例

```json
{
  "global": {
    "monitor": {
      "check_interval": 300,
      "tcp_enabled": false,
      "tcp_targets": ["8.8.8.8:53", "114.114.114.114:53"],
      "http_enabled": true,
      "http_targets": ["http://connect.rom.miui.com/generate_204"],
      "url_enabled": false,
      "url_targets": ["http://captive.apple.com/hotspot-detect.html"],
      "url_expected_responses": {
        "http://captive.apple.com/hotspot-detect.html": "Success"
      },
      "local_check_enabled": true,
      "disable_proxy": true,
      "profile_check_interval": 180,
      "tcp_timeout": 2,
      "http_timeout": 10,
      "url_timeout": 10,
      "auth_url_timeout": 5,
      "post_login_delay": 5
    },
    "pause": {
      "enabled": false,
      "start_hour": 22,
      "start_minute": 0,
      "end_hour": 6,
      "end_minute": 0
    },
    "retry_settings": {
      "max_retries": 3,
      "retry_interval": 5
    }
  }
}
```
