# 无法自动登录

本页面按「最常见 → 较少见」的顺序组织。多数「无法自动登录」的问题都能通过第一份清单解决；任务步骤层面的问题见 [调试与取证](../3-tasks/3.6-debug.md)。

## 六步自查

请按顺序逐项排查：

| # | 排查项 | 处理方式 |
| --- | --- | --- |
| 1 | 网络探针未开启 | 进入 **设置 → 网络监测**，确认至少开启一种探针（默认仅开启 **HTTP 204 门户检测**，被误关后不会自动触发） |
| 2 | 认证地址配置错误 | 直连型填写 `auth_url`；劫持型必须开启重定向模式并填写**明文 `http`** 的 `trigger_url`，见 [新手上路](../1-getting-started/1.1-start.md) 第 2 步 |
| 3 | 任务未设为活跃 | 在 任务管理 页点击 **设为活跃**，仪表盘「登录」才会执行该任务；「执行指定任务」仅用于单次验证 |
| 4 | 后台运行导致看不到失败原因 | 到 设置 → 浏览器 **关闭后台运行** 后再次执行，观察是否存在 iframe 嵌套或选择器失效 |
| 5 | 已触发但不再重试（处于冷却期） | 同一会话连续失败 3 次后会冷却 300 秒，等待冷却结束或手动登录一次即可恢复，无需重启 |
| 6 | 正处于暂停时段 | 暂停时段仅静默监测与自动登录（定时任务不受影响）；确认是否设置了跨天时段（如 `22:00 → 06:00`） |

## 其他相关场景

- **验证码识别失败**：确认 OCR 依赖已安装、`ocr` 的 `selector` 指向验证码图片，详见 [调试与取证](../3-tasks/3.6-debug.md) 的「验证码 OCR」一节。
- **首次登录就走不到浏览器**：多半是运行环境初始化问题，见 [启动与安装故障](7.2-startup.md)。
- **服务已启动但控制台打不开**：同样见 [启动与安装故障](7.2-startup.md) 的实例管理一节。

## 反馈前请准备

先完整执行上述自查；仍未解决时，使用调试面板的 **一键取证** 将截图、页面快照与日志打包到 `debug/`。反馈问题时附上该压缩包可显著提升定位效率，操作方法见 [调试与取证](../3-tasks/3.6-debug.md)。
