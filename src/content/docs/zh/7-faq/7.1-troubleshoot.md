# 故障排查

## 无法自动登录

按以下顺序逐项排查，可解决 90% 以上的“无法自动登录”问题：

| 序号 | 排查项 | 处理方式 |
| --- | --- | --- |
| 1 | 检测未启用 | 进入 **设置 → 网络监测**，确认至少启用一种探针（默认仅 **204 门户检测** 为启用状态，误关闭后将无法触发自动登录） |
| 2 | 认证地址配置错误 | 直连型网络填写认证地址，劫持型网络须启用“重定向触发地址”并填写 `http` 地址（详见 [快速开始](../1-getting-started/1.4-quickstart.md) 第 2 节） |
| 3 | 任务未设为活跃 | 在任务管理页面点击 **设为活跃**，仪表盘的“登录”按钮方可执行该任务；`POST /api/tasks/{id}/execute` 仅用于单次验证 |
| 4 | 后台运行导致无法观察失败原因 | 进入 **设置 → 浏览器 → 后台运行**，关闭后重新执行，以确认是否存在 iframe 嵌套或选择器失效 |
| 5 | 已触发检测但不再重试（冷却生效） | 同一会话内连续登录失败 `3` 次后自动暂停 `300` 秒；等待冷却结束或手动登录一次即可恢复，无需重启 |
| 6 | 暂停时段覆盖当前时间 | **设置 → 网络监测** 的暂停时段仅静默监测与自动登录，定时任务不受影响；确认时段设置是否跨天（如 `22:00 → 06:00`） |

## 启动与解压

**为何双击后无任何反应或提示文件缺失？**

请勿在压缩包内直接双击运行 `campus-auth.exe`。部分解压软件（如 Windows 资源管理器预览、Bandizip 快速预览）会在临时目录中启动程序，导致相对路径下的 `config/`、`tasks/` 等资源无法定位。

- 请先将压缩包完整解压至固定目录（如 `D:\campus-auth\`），再双击 `campus-auth.exe` 启动。
- 如已在压缩包内启动过，请关闭程序后重新解压至新目录，再启动一次。

**解压后应看到哪些文件？**

以 Windows 为例，解压后目录应至少包含 `campus-auth.exe` 与 `campus-auth-helper.exe`（如适用）。首次启动后将自动生成 `config/`、`tasks/`、`logs/` 等目录。仅看到单个 `campus-auth.exe` 且无其他文件，通常为未完整解压所致。

**Windows 提示“已保护你的电脑”或被杀毒软件拦截？**

- 点击“更多信息”→“仍要运行”，或将 `campus-auth.exe` 添加至杀毒软件白名单。
- 企业或校园网环境中，`WebView2` 运行时缺失亦可能导致启动失败，请按提示安装后重试。

**macOS 提示“无法验证开发者”或“已损坏”？**

执行 `xattr -cr /path/to/campus-auth` 清除隔离属性后重试；Apple Silicon 设备请下载 `aarch64` 版本。

## 环境初始化失败

> 相关代码：`src/environment/uv.rs` / `bootstrap.rs` / `python.rs` / `browser.rs`；错误分类逻辑见 `classify_uv_download_failure` 与 `classify_playwright_failure`。

### 前置自检（30 秒）

1. **确认已通过校园网认证**：浏览器可正常访问外网后再尝试。未通过校园网认证时，下载源无法连接，通常表现为 DNS 解析或连接失败。
2. **查阅错误提示中的“原因 / 建议 / 详情”**：程序已对超时、404/403、磁盘空间、证书等错误进行分类，按提示处理较反复重试更为有效。
3. **代理环境需预先配置**：更新与 `uv add/sync` 将使用代理，检测流量如需跟随代理，则关闭“监测不走代理”选项。

### uv 下载失败（`uv` 二进制无法安装）

现象：设置 → 系统 → Python 环境报告 `uv 下载失败`，或日志中出现 `uv 下载失败 (重试 N 次): 原因：…；建议：…；详情：…`

| 原因 | 典型详情 | 处理方式 |
| --- | --- | --- |
| 下载超时或停滞 | `下载停滞（60s 内无数据…）` / `下载超时 (超过 300s)` | 校园网高峰期或镜像限速所致，稍后重试；代理环境需确保代理可用 |
| 无法连接下载源 | `dns error` / `connection refused` / `certificate` / `tls` | 检查是否已通过校园网认证、代理是否可用、防火墙是否放行 GitHub 与镜像站 |
| 下载源返回错误 | `HTTP status 404/403/429/5xx` / `所有镜像均失败: HTTP 403` | 资源或镜像限流，稍后重试；注意夜间校园网可能存在限速 |
| 磁盘空间不足 | `No space left on device` / `ENOSPC` | 清理磁盘空间后重试 |
| 下载内容异常 | `大小上限` | 网关劫持或镜像返回异常页面，更换时段后重试 |

**技术说明**：`download_uv` 对全部镜像并发执行 `HEAD` 测速排序后按序尝试，失败时自动按 `5s / 10s / 20s` 指数退避，单次下载总超时 300 秒、停滞超时 60 秒，压缩包经 SHA256 校验，跨卷安装通过 `copy → 临时名 → rename` 实现原子落盘。

**处理方式**：

- 在控制台 **设置 → 系统 → Python 环境** 中点击“初始化 Python 环境”（或“重试安装”），通过 `POST /api/system/retry-install` 重试。
- 代理环境：在 设置 → 系统 → 网络、端口与代理 中填写 `http://127.0.0.1:7890`（支持非本机代理），留空则跟随系统代理。
- 本机已安装 `uv` 的设备可直接使用 PATH 中的 `uv`（版本 ≥ `0.5.0`），无需重复下载。
- `uv` 文件损坏可通过 `uv --version` 实际执行探测拦截，不会误判为就绪状态。

### uv sync 失败（Python 虚拟环境无法创建）

现象：`uv sync 失败 (exit code=…): …；可能原因：依赖源不可达/被限速或依赖冲突，详见 stderr 末尾`，或 `uv sync 超时 (>600s)` / `uv {add/remove} 失败`

**处理方式**：

- 查阅 stderr 末尾 400 字符的实际报错信息（日志中保留 4000 字符全量），判断为源不可达、限速或依赖冲突。
- 旧 `python_worker/.venv` 损坏可通过 `python --version` 实际执行探测发现，自动触发 `uv sync` 修复；更新后新增依赖通过 `.venv-resync` 强制重同步。
- OCR 依赖 `ddddocr` 通过 `uv add` 写入 `pyproject.toml` 主依赖，执行 `uv sync` 时按声明自动对齐，无需额外配置 extra 开关。

### Playwright / Chromium 下载失败

现象：`Playwright 安装失败 (重试 N 次): 原因：… 建议：… 详情：…`，浏览器长时间无法安装

| 原因 | 处理方式 |
| --- | --- |
| 下载超时 | 检查系统代理与防火墙配置，连通 `npmmirror.com` 后点击“初始化 Python 环境”重试 |
| 无法连接下载源 | 确认代理可用，能正常访问 `npmmirror.com/mirrors/playwright` |
| 下载源返回错误（404/403/429） | 镜像缺失该版本构建或被限流，稍后重试 |
| 磁盘空间不足 | 清理磁盘空间后重试 |
| 证书校验失败 | 多为企业网关 MITM 拦截，检查代理配置或设置 `NODE_EXTRA_CA_CERTS` |

**补充说明**：本机已安装 Edge / Chrome 时自动复用，无需下载 Chromium；Firefox / WebKit 可在 设置 → 浏览器 中一键安装；并发安装通过 `BootstrapGate` 串行化处理，不会产生对同一 `.venv` 的并发写入。Docker 镜像已预置完整环境，无需等待下载。

**处理方式**：

- 本机已安装 Edge / Chrome 时，切换至对应浏览器渠道即可直接使用。
- 在 设置 → 浏览器 中一键安装 `chromium`（亦可通过 `POST /api/system/retry-install` 重试）。
- 代理环境按上述方式配置代理；磁盘空间与企业网关证书亦为常见原因。
- 进度长时间无变化属正常现象（`uv run playwright install` 可持续数分钟），控制台每 5 秒刷新进度与最新输出行。

### 一键取证与日志

- 通过调试面板的 `POST /api/debug/capture` 打包截图、MHTML 及日志至 `debug/` 目录，反馈时附带最为有效。
- 仪表盘与设置中的日志通过 `/ws/logs` 实时推送；日志保留天数由 `retention_days` 控制（默认 7 天），`file_enabled` 与 `level` 支持热更新。

## 服务无法访问

**服务提示已启动但无法访问如何处理？**

```bash
campus-auth --status
campus-auth --stop
campus-auth --force   # 抢占运行（含 PID 复用防护）
```

Windows 系统下双击已运行实例将自动打开 `http://127.0.0.1:50721`，轻量模式记录哨兵端口 `0`，首个 Web 请求按需启动后回写实际端口。

更多说明见 [控制台导览](../1-getting-started/1.3-console.md)、[自动更新](../5-system/5.2-update.md) 及 [断网检测](../4-automation/4.1-monitor.md)。
