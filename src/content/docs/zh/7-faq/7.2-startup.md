# 启动与安装故障

程序装不上、起不来、控制台打不开，均归在本页。登录执行层面的问题见 [无法自动登录](7.1-login.md)。

## 启动与解压问题

### Windows 双击无反应或提示缺少文件

**请勿在压缩包预览窗口中直接运行。** 部分解压软件的「快速预览」会将程序放到临时目录启动，导致无法定位同级的 `config/`、`tasks/` 等资源。

- 先将压缩包**完整解压**到固定目录（如 `D:\campus-auth\`），再双击 `campus-auth.exe`。
- 曾在压缩包内启动过的，请关闭程序后重新解压到新目录再启动。
- 正常解压后至少应看到 `campus-auth.exe` 与 `campus-auth-helper.exe`；`config/`、`tasks/`、`logs/` 等目录在首次运行后才会生成。

### Windows 提示「已保护你的电脑」或被安全软件拦截

- **SmartScreen**：点击 **更多信息 → 仍要运行**。
- **第三方安全软件**：将 `campus-auth.exe` 加入白名单；开机自启被拦截时同理。

### macOS 提示「无法验证开发者」或「已损坏」

通过浏览器下载的二进制带有隔离属性，执行以下命令清除后重试（注意按芯片选择安装包，Apple Silicon 选择 `aarch64`）：

```bash
xattr -cr /path/to/campus-auth
```

### Linux 启动报找不到 GTK / appindicator 库

系统托盘动态链接了 GTK3 等系统库。Debian / Ubuntu 安装运行时依赖即可；无桌面环境的服务器可直接追加 `--no-tray`，或改用 Docker 部署：

```bash
sudo apt install libgtk-3-0 libayatana-appindicator3-1 librsvg2-2
```

## 运行环境初始化失败

首次登录需要 `uv` 与 Python 运行环境，相关逻辑位于 `src/environment/`。请先完成三项前置自检：

1. **先通过校园网认证**：确认可以正常访问外网再重试。未认证时下载源不可达，常表现为 DNS 或连接失败。
2. **阅读错误提示中的「原因 / 建议 / 详情」**：程序已对超时、404/403、磁盘不足、证书错误等情况分类，按提示处理比反复重试更有效。
3. **代理环境请先配置代理**：更新与依赖安装会走代理；若希望网络检测也走代理，请关闭「监测不走代理」。

### uv 下载失败

现象：设置 → 系统 → Python 环境显示「uv 下载失败」，或日志出现 `uv 下载失败 (重试 N 次)`。

| 原因 | 典型信息 | 处理方式 |
| --- | --- | --- |
| 超时 / 停滞 | `下载停滞（60s 内无数据）`、`下载超时（300s）` | 校园网高峰或镜像限速，稍后重试；代理环境请确认代理可用 |
| 无法连接下载源 | `dns error`、`connection refused`、`certificate`、`tls` | 检查是否已完成校园网认证、代理是否可用、防火墙是否放行 |
| 下载源返回错误 | `HTTP 404/403/429/5xx` | 资源被限流，稍后重试 |
| 磁盘空间不足 | `No space left on device` / `ENOSPC` | 清理磁盘后重试 |
| 内容异常 | `大小上限` | 网关劫持或镜像返回了异常页面，更换时段重试 |

处理方式：在 设置 → 系统 → Python 环境 点击「初始化 / 重试安装」；代理环境在系统设置中填写代理地址。本机已安装 `uv`（≥ 0.5.0）时会直接复用 PATH 中的版本，无需重复下载。

### uv sync 失败（虚拟环境无法建立）

- 查看日志末尾的真实报错（界面保留末尾 400 字符，日志文件保留全量），区分是下载源不可达、限速还是依赖冲突。
- 旧的 `.venv` 损坏时会被实际执行探测发现并自动重新同步；版本更新引入的新依赖会强制重同步。
- OCR 依赖 `ddddocr` 已写入主依赖声明，`uv sync` 时自动对齐，无需额外开关。

### Playwright / Chromium 下载失败

| 原因 | 处理方式 |
| --- | --- |
| 下载超时 | 检查代理与防火墙，确认可连通 `npmmirror.com` 后点击「初始化 Python 环境」重试 |
| 无法连接下载源 | 确认代理可用，可访问 `npmmirror.com/mirrors/playwright` |
| 404 / 403 / 429 | 镜像缺少该版本或被限流，稍后重试 |
| 磁盘空间不足 | 清理磁盘后重试 |
| 证书校验失败 | 多为企业网关中间人拦截，检查代理或设置 `NODE_EXTRA_CA_CERTS` |

> [!NOTE]
> 本机已安装 Edge / Chrome 时会直接复用，无需下载 Chromium；安装过程可能持续数分钟，属正常现象。**Docker 镜像已预装完整环境，不会触发这些下载。**

## 服务已启动但控制台打不开

```bash
campus-auth --status    # 查看实例 PID / 端口
campus-auth --stop      # 停止实例
campus-auth --force     # 终止残留进程后重新启动（带 PID 复用防护）
```

- Windows 下双击已在运行的实例，会自动打开 `http://127.0.0.1:50721`。
- 轻量模式初始记录哨兵端口 `0`，控制台首次被唤起后才回写真实端口。
- 端口可能因被占用而顺延，以 `--status` 输出或 `config/.runtime_port` 为准。
