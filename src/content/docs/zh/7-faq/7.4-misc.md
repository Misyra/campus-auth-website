# 定时、自启与更新

本页面汇总定时任务、开机自启、长期运行与版本更新的常见问题。

## 定时任务

### 如何配置定时签到或保活？

在 **定时任务** 页（`/scheduled`）使用 5 段 cron 表达式（`分 时 日 月 周`）关联一个已调通的任务，例如 `0 8 * * *` 表示每天 08:00 执行。建议先手动执行确认稳定，再挂载定时。详见 [定时任务](../4-automation/4.2-scheduled.md)。

### 关机期间错过的触发点会补跑吗？

不会。程序未运行时错过的触发点不会在重启后补执行，调度器从当前时间推算下一次；暂停时段也不影响定时任务。

## 开机自启

### 如何开机自动运行？

两种方式任选其一：在 设置 → 系统 → 启动与运行 开启「开机自启动」，或执行 `campus-auth --autostart enable`。程序按平台落地：Windows 写入注册表启动项、macOS 创建 LaunchAgent、Linux 创建 XDG 自启项。

### 开机自启被安全软件拦截怎么办？

Windows 上部分安全软件会拦截注册表启动项写入，将 `campus-auth.exe` 加入白名单后重新开启即可。

### 开机后希望程序执行什么动作？

由「启动后执行」（`startup_action`）控制：`monitor` 直接进入网络监测（默认）、`login_once` 先登录一次、`none` 不执行任何动作。

## 长期运行与内存

### 长时间运行后内存逐渐上涨怎么办？

浏览器与 Worker 常驻会缓慢占用内存。程序默认每 24 小时优雅自重启一次（`auto_restart_hours`，设为 `0` 关闭），运行时调整无需重启。

默认 `keep_alive=false` 为即用即还模式，空闲 300 秒回收浏览器；若已开启进程常驻，建议保留定时自重启。详见 [settings.json 配置参考](../6-reference/6.1-settings.md)。

## 版本更新

### 如何检查与安装更新？

在 **关于** 页点击「检查更新」，或在 设置 → 系统 中配置自动更新。更新通道分为正式版 / 测试版 / 全通道最新；检查结果回写 `update/last_check.json`，可查看「上次检查时间」与错误提示。国内网络可在系统设置中为更新单独配置代理。详见 [自动更新](../5-maintenance/5.1-update.md)。

## 任务配置

### 为什么保存含 eval 的任务会弹出安全警告？

`eval` / `custom_js` 可执行任意 JavaScript，因此保存前会要求确认脚本安全，确认后才会写入。该提示属正常设计，并非报错。

### 运营商下拉如何配置？

- **原生 `<select>`**：使用 `select` 步骤，值填写 `{{ISP}}`。
- **自定义样式下拉**：使用 `click_select`（`selector` 点开列表 + `option_selector` 圈定选项 + `value={{ISP}}`）。
- **无运营商选项的门户**：为该步骤设置 `"required": false`，匹配不到时自动跳过。

### 多校区 / 多运营商如何配置？

为每个网络环境各建一条配置方案，分别填写网关 IP / Wi-Fi 名称、绑定各自的活跃任务，并开启「自动切换」，程序会自动选用匹配度最高的一条，无需为每种网络复制一份任务文件。编辑器中的「检测当前网络」可一键填入。详见 [自动匹配网络](../2-profiles/2.2-match.md)。

### 共享仓库中的任务可以直接用吗？

可以，但需先完成安全核对（不含明文凭据、导航地址可信、脚本行为可解释）。完整流程见 [从仓库下载共享任务](../3-tasks/3.7-repo.md)。
